# AxKit.Core notes: Safety (docs/axKit/security-audit-2026-10-24.md)

- `SystemPrograms` (S-1): Windows' own programs by full path, and `OnPath`, the PATH searched in its full folders only; every process an app starts is named through it or by a full path it found itself. `KeepCurrentFolderOffSearches` sets Windows' `NoDefaultCurrentDirectoryInExePath` for the process, which the shells and programs it starts inherit (`Program.Main` calls it first; in axTerminal's cmd a program in the current folder is `.\name` since 2026-11-09). The command line of a program that may be a batch file (repairs R-24, 2026-11-14): `LineFor(program, arguments)` gives a `ProgramLine` (`FileName`, `Arguments`, `CommandLine`, or a `Refusal`): a program as it is with `QuoteArgument` (the C runtime's quoting, from axClaude's `ClaudeLauncher` on its second use); a `.cmd` or `.bat` (`IsBatch`) through cmd.exe as `/d /s /c ""path" "arg"..."`, every argument quoted, where `& | < > ^ ( ) , ; =` are text, and `BatchRefusal`, the sentence naming the character and the argument, for `CmdNeverSafe` (`%`, `!`, a double quote, a line break) in an argument and those or `CmdOperators` in the batch file's own path. Every start of Claude Code goes through it (`ClaudeCodeProgram.LineFor`); never build a `cmd /c` line anywhere else. `CmdSpecials` with `HasCmdSpecials` is the strict list for batch files whose inside nobody knows, started with an argument list (axFile's own programs, axMCP's servers). `SystemProgramsTests` runs a real batch file through cmd.exe.
- `ProgramInstall` (AX-2.9, 2026-10-24): the programs an app needs and Windows lacks (Git, KeePassXC, Claude Code, PowerShell 7), each with its winget id or its maker's own installer and its download page; `StartInfo` (the install without a window, every question answered; Windows PowerShell by its full path), `Winget` (only Windows' own, never one on the PATH, S-10) with `WingetArguments` (`--source winget`), `RefreshPath` (the PATH read again from Windows after an install); `InstallerArguments` (KeePassXC's `AUTOSTARTPROGRAM=0 LAUNCHAPPONEXIT=0`, passed with `--custom`), and the safety net of 2026-11-14: `SignInEntries` (the user's Run key, read only), `AddedSignInEntry` (pure: the new value that names `ProgramFile`) and `SignInNotice` (the words, with `SignInOff`); the PATH is searched through `SystemPrograms.OnPath`. Tested in `ProgramInstallTests`.
- `AutomationEnvironment` (S-11): a test run's secret and folder, read once in `Main` and taken out of the environment; only a new axKit window of the run gets them (`PassTo`).
- `ProcessRun` and `ProcessResult` (2026-10-25; from axGIT's `GitRunner`, Claude Code's version check and axPass's `KeePassCli` on their third use, inventory item 3): a program run without a window to its end under a time limit, input lines then closed, both outputs read under the limit, the whole tree ended on a timeout, `Finished` telling whether the program itself had ended (git's case of a child holding the pipes). Tested in `ProcessRunTests`; the callers' own tests cover their cases.
- `DisplayText` (S-42, 2026-10-25): text from outside shown as a list line, its bidi and zero-width characters made
  visible; `AxKit.Forms/AxKitList.Fill` applies it to every list it fills.
- `Signatures` (S-19): whether a program file carries a valid Authenticode signature (`WinVerifyTrust`, the file alone,
  no network), asked before a secret is handed to a program found outside an administrator's folders; axPass's tool.
- `Redaction` (S-20; from AxClaude.Core on its second use, Copy diagnostics): e-mail addresses, the account's paths, pipe names, ids and the account name replaced by placeholders, for text to be shown or shared.
