# AxKit.Core notes: Safety (the security audit of 2026-10-24)

- `SystemPrograms` (S-1): Windows' own programs by full path, and `OnPath`, the PATH searched in its full folders only; every process an app starts is named through it or by a full path it found itself. `KeepCurrentFolderOffSearches` sets Windows' `NoDefaultCurrentDirectoryInExePath` for the process, which the shells and programs it starts inherit (`Program.Main` calls it first; in axTerminal's cmd a program in the current folder is `.\name` since 2026-11-09). The command line of a program that may be a batch file (repairs R-24, 2026-11-14): `LineFor(program, arguments)` gives a `ProgramLine` (`FileName`, `Arguments`, `CommandLine`, or a `Refusal`): a program as it is with `QuoteArgument` (the C runtime's quoting, from axClaude's `ClaudeLauncher` on its second use); a `.cmd` or `.bat` (`IsBatch`) through cmd.exe as `/d /s /c ""path" "arg"..."`, every argument quoted, where `& | < > ^ ( ) , ; =` are text, and `BatchRefusal`, the sentence naming the character and the argument, for `CmdNeverSafe` (`%`, `!`, a double quote, a line break) in an argument and those or `CmdOperators` in the batch file's own path. Every start of Claude Code goes through it (`ClaudeCodeProgram.LineFor`); never build a `cmd /c` line anywhere else. `CmdSpecials` with `HasCmdSpecials` is the strict list for batch files whose inside nobody knows, started with an argument list (axFile's own programs, axMCP's servers). `SystemProgramsTests` runs a real batch file through cmd.exe. `Installed(fileName, installFolders)` (repairs R-70, 2026-11-16) is for a program run under an agreement that names it and not its path (git, PowerShell 7): its install folders first (`ProgramFilesFolders`, under Program Files and Program Files (x86) as Windows names them, which only an administrator can write), then the PATH's folders that are on a drive of this computer (`LocalPaths.IsLocal`). A new program of that kind is found through it, not through `OnPath`.
- `ProgramInstall` (AX-2.9, 2026-10-24): the programs an app needs and Windows lacks (Git, KeePassXC, Claude Code, PowerShell 7), each with its winget id or its maker's own installer and its download page; `StartInfo` (the install without a window, every question answered; Windows PowerShell by its full path), `Winget` (only Windows' own, never one on the PATH, S-10) with `WingetArguments` (`--source winget`), `RefreshPath` (the PATH read again from Windows after an install); `InstallerArguments` (KeePassXC's `AUTOSTARTPROGRAM=0 LAUNCHAPPONEXIT=0`, passed with `--custom`), and the safety net of 2026-11-14: `SignInEntries` (the user's Run key, read only), `AddedSignInEntry` (pure: the new value that names `ProgramFile`) and `SignInNotice` (the words, with `SignInOff`); the PATH is searched through `SystemPrograms.OnPath`. Tested in `ProgramInstallTests`.
- `AutomationEnvironment` (S-11): a test run's secret and folder, read once in `Main` and taken out of the environment; only a new axKit window of the run gets them (`PassTo`).
- `ProcessRun` and `ProcessResult` (2026-10-25; from axGIT's `GitRunner`, Claude Code's version check and axPass's `KeePassCli` on their third use, inventory item 3): a program run without a window to its end under a time limit, input lines then closed, both outputs read under the limit, the whole tree ended on a timeout, `Finished` telling whether the program itself had ended (git's case of a child holding the pipes). Since 2026-11-27 each output is read piece by piece into a text that is kept, so that a run past its limit still says what it printed (a read to the end, cancelled, gave nothing, and git read an empty output with exit code 0 as an empty status), with half a second after the limit for what is already in the pipes; `ProcessResult.Stopped` is the run ended before it had finished, whose output is a part and no result, and the compiler holds every caller to asking it (the review's second pass of 2026-11-27; a test that read the sources for the word held nothing): `Output` is null of a stopped run, so it is read only after `Stopped` was asked, and what was printed whatever became of the run is `Printed`, taken only in the files `ProcessRunTests` lists with their reasons (git's runner, whose own result carries the stop on, and axTask's action output, shown as what it is). Tested in `ProcessRunTests`; the callers' own tests cover their cases.
- `DisplayText` (S-42, 2026-10-25): text from outside shown as a list line, its bidi and zero-width characters made
  visible; `AxKit.Forms/AxKitList.Fill` applies it to every list it fills. The one place that says which
  characters are neither seen nor heard (`Hidden`; `Hides` asks it): by Unicode's own classes since the third review of
  2026-11-27, in place of a list that each review found short: the general categories Format, Control, Surrogate,
  PrivateUse and OtherNotAssigned, the line and paragraph separators, and the default ignorable code points of
  another category (`DefaultIgnorable`, from the Unicode Character Database). One exception keeps an emoji whole: FE0F
  right after a symbol, and 200D between two symbols. `VisibleCommand` also writes out a space that is not the plain
  one, for a command offered to run and a permission question's label. Each rule has its rows in `DisplayTextTests`. `VisibleLine` keeps a tab, for a question's name and answers: `AxKit.Forms/ControlArea` applies
  it to every question it shows, `McpOffer.Shown` to an offered command. A new place that puts a program's or an AI's
  text in front of the user to decide on goes through here.
- `Signatures` (S-19): whether a program file carries a valid Authenticode signature (`WinVerifyTrust`, the file alone,
  no network), asked before a secret is handed to a program found outside an administrator's folders; axPass's tool.
- `Redaction` (S-20; from AxClaude.Core on its second use, Copy diagnostics): e-mail addresses, the account's paths, pipe names, ids and the account name replaced by placeholders, for text to be shown or shared. Since 2026-11-27 the profile folder is replaced first and whole (`WithoutProfile`: the folder's own path with single or doubled backslashes or forward slashes, the drive as Git Bash and WSL spell it too), the names (`DefaultNames`, the profile folder's name among them, the longest first) before the pattern for paths under Users, which ends a name at a space and left the second word of a profile folder of two words in the text; `Redact` and `ReportPrivacy.Mask` take the profile as a parameter, which the tests give. An account path is never written whole in a test or a comment: `PrivacyTests` finds it. `MaskRecording` masks a recording's session ids, the subscription tier and, since 2026-11-26, the reset of a usage limit on Claude Code's row "You've used 76% of your weekly limit · resets 11pm (<time zone>)" (the hour and the account's time zone) byte for byte (zeros, x), so that PtyCapture's fixtures hold none of them and every cursor position stays right. `WithoutIds` (2026-11-27) masks the ids alone, for a log line that names a program's command line (`claude --resume <id>`).
- `SettingsSeal` (AX-5.6, repairs R-53, 2026-11-16): the one seal on the settings that decide what is run or what Claude may read. A settings class lists its sealed fields in a private `SealedText()` (`Text`: each field with its length in front, null as `-`), keeps a `Seal` property, and does three things: in `Save`, `Seal = SettingsSeal.Of(path, SealedText())`, then `SettingsSeal.Remember(path)` when `SettingsFile.Save` wrote the file; in `Load`, before its own sanitising (the seal is over the values as written), `SettingsSeal.Checks(path, Seal, SealedText(), new T().SealedText())`, and when that is false the sealed fields to their defaults and `error = SettingsSeal.Refused(error, <its sentence>)`. A sentence holds the words `ChangedOutside` ("changed outside axKit and"), by which the window tells it from an unreadable file (`IsRefusal`). The users: `TerminalSettings`, `GitSettings`, `MCPSettings`, `FileSettings`, axClaude's `AppSettings`, `AiSettings`, `Consent`. The key and the names of the sealed files are one file under `UserSecret.Protect`, `AppPaths.SettingsSealFile` (`KeyFileOf`: beside the settings file for a file outside axKit's settings folder, which is every test's): no seal and not on the list is a file from before the seal, accepted; on the list without a seal, a wrong seal, or a key file that cannot be read is refused; a new key after an unreadable one makes every file count as listed. The first key file is put in place only if none came meanwhile, so that two windows end with one key. `McpAccess` keeps its own file, key and seal value and takes `Hmac`, `Same` and `ReadKey` from here. A new setting that names a program or a folder Claude reads joins its class's `SealedText` and the list in AX-5.6. Tested in `SettingsSealTests` and each app's `*SealTests`.
- `SettingsSeal.WasSealed` (2026-11-16, for R-57): whether this install has sealed a file before, for a list whose missing state is not the safe one (`Reports/ReportWritten`: "not kept yet" sends everything, so a deleted list must count as kept and empty). The accepted files of Claude's working folder (`Ai/AiFolderCheck`) and the report form's file names are sealed lists of axKit's own, not settings classes; both use `Text`, `Of`, `Remember` and `Checks` as a settings class does.
- `ThisProgram` (S-13; in `AxKit.Forms` until 2026-11-21, moved unchanged when the relays of axClaude, which load nothing of the windows, came to ask it too): whether a process runs this very program file, by its image path (`Runs`, `ImageOf`), the process that started one (`ParentId`, `ParentOf`), its command line (`CommandLineOf`), and `Serves`, whether a pipe this process connected to is served by this same program file: asked before a secret is written to a pipe known by its name alone.
- `ShellQuote` (docs/axTask/forms-framework.md AF-4.5, 2026-11-21): `CommandLine`, one command line for a shell from a program and its arguments, each element quoted by the shell's own rule so that it stays one element, for a line a person reads before sending it (never for a program axKit starts, which takes its arguments as a list). PowerShell and PowerShell 7: single quotes with every character PowerShell reads as a single quote doubled, the typographic ones too, the call operator before a quoted program, and a refusal for what Windows PowerShell 5.1 does not hand to a program whole whatever the quotes (found by a real run, 2026-11-27: an element with a double quote, an empty one, one with a space and a backslash at its end; PowerShell 7.3 hands them on whole, so no one line is right for both); and, since the review's third pass (L2, by a real run: "sc query" ran Set-Content, and "& 'sc'" too, the call operator looks for an alias first; "exit" ended the shell), a refusal for a program written bare that is one of PowerShell's own aliases or words (the table of Windows PowerShell 5.1's, a superset of 7's; "write the program's file name, as sc.exe") and for an element `--%`, after which PowerShell hands the rest on unquoted; cmd.exe: double quotes, and a refusal for a character it would act on; a refusal for any other shell and for a control character. Tested in `ShellQuoteTests`, which also runs the line through powershell.exe itself and reads what the program was handed (and through pwsh.exe where it is installed; skipped, and said so, where it is not).
- `ChildJob` (2026-11-21, the audit of the stream source): a Windows job that ends the processes put into it, and all they start, when it is ended and when this process ends however it ends. `TryCreate` (null where Windows gives none), `Add`, `Terminate`, `Dispose`; one handle under one lock. `StreamHost` runs Claude Code in one.
