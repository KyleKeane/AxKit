# AxFile.Core, the pure code

Everything of axFile that needs no window: a folder's entries, the file operations with their undo, the window's history of operations, the settings with the favorites. Unit tested in `tests/AxFile.Tests` over temporary folders. The spec is `docs/axFile/SPEC.md` ("SPEC.md" below); the window is `src/AxFile`, with its own `CLAUDE.md`. The bundle rules are in the root `CLAUDE.md`. The player seam and the queue went to `AxMedia.Core` and the text rule to `AxPreview.Core` on 2026-10-22 (the split's inventory of 2026-10-22, in the git history); `MediaFiles` and `NaturalOrder` are `AxKit.Core`'s since the same day.

## Where things are

- `FolderListing` and `Entry`, `SortBy` (SPEC.md AF-2.2, AF-3, AF-3.8): `Read` (a `Listing`: a folder's entries, hidden and system ones and ones starting with a period left out unless asked and counted, folders first in natural order), `NotShownText` ("Not shown: 3 hidden, 2 starting with a period"), `Sort` (by name, date newest first or size largest first, folders first, ties by name; the filter of the names is the item window's since 2026-11-22, the same in every navigator), `SortName` (the type-ahead of AF-3.6 is `AxKit.Core/TypeAhead` since 2026-10-24), `ListName` ("24 items"; the item window adds the filter and how many it shows), `Information` ("report.pdf, 1.2 MB, modified …"; a drive's free space; the sizes through `AxKit.Core/FileSize` since 2026-10-24), `Parent` (null at a drive's root), `ThisPC`, `IsThisPC` and `Drives` (the ready drives as folder entries marked `IsDrive`, "Local Disk (C:), drive", AF-3.10), `Resolve` (a typed path with environment variables, a file's path giving its folder and the file).
- `PathCompletion` and `Completion` (AF-3.3, AF-D12): `Split` (a typed text into the folder to list and the start of a name: environment variables expanded, a name or a relative folder in the folder shown, the drives for an empty text, a drive letter or This PC), `Candidates` (the entries starting with it in the list's order, a folder's text ending in a backslash; the drives' roots; empty when the folder cannot be read), `Spoken` ("Windows, folder, 2 of 5").
- `FileOperations` (AF-4):
  - `CheckName`;
  - `Lookalike` (the existing name that reads the same as a typed one without being it: the accents composed through the bundle's `Accents` table, since the program runs without the globalization data, case-folded, spaces folded, invisible characters dropped);
  - `CreateFolder`, `CreateFile` (an empty "New file.txt", or "New file - 2.txt"), `Rename` (a change of case included);
  - `DeleteToRecycleBinAsync` (a list of paths, one operation) and `FreeName` ("name - 2.ext", the first name nothing has);
  - `Destinations` (where each source lands: its name, or a free one, around the `reserved` paths a running operation is still writing, AF-4.5);
  - `CopyOrMoveAsync` (`SHFileOperationW` with undo allowed, silent, no confirmation, one destination per source with `FOF_MULTIDESTFILES`, each on a single-threaded-apartment thread of its own through `OnShellThreadAsync`, which the window also uses for the Recycle Bin's Restore);
  - `CheckUndo` (why an operation cannot be undone now: an entry made or moved is gone, "has changed"; a new folder or file filled, "has files now" / "has content now"; the place to go back to taken, "is already here");
  - and `UndoAsync` (the inverses: a rename back, an empty folder or file deleted, a move back through the shell with the made folder removed when empty, copies, a zip or an extracted folder to the Recycle Bin; a delete is the window's, through the shell's Restore);
  - `Message` (one line from an exception):
    - Windows' sharing violation, HRESULT 0x80070020, becomes `InUse`, "In use by another program: a terminal or an app runs in it, or the file is open", and an `IOException` access denied `AccessDenied`, since both come from outside axFile and the Windows text does not say what to do;
    - the shell's codes 0x20 and 0x21 are the same text.
- `Operation` and `OperationKind` (AF-4.14, AF-9.3): an operation is its kind with the paths before and after it (a move into a new folder names the folder), and knows the folder its undo lands in (`Folder`), the entry to select then (`Select`), where it left its result (`ResultFolder`, `Result`, for Recent operations), "notes.md" or "3 items" (`What`) and its "Undone: …" text, which says what Undo took back (the menu item is one "Undo" since 2026-11-25, so the operation has no menu label any more).
- `ActionLog`, `ActionEntry` and `ActionState` (AF-9.2, AF-9.3, AF-4.14): the window's history of file operations, in time order, the last fifty kept and the last twenty undoable: `Begin(text, folder)` a running entry, `Progress`, `End(entry, text, operation)`, `Fail(entry, reason)`, `Add(text, operation)` an entry done at once, `Newest()` the operation Ctrl+Z takes (the newest that can be, one per press), `Undone`, `NotUndone(entry, reason)`, `Recent()` (newest first, for Actions → Recent operations), `Latest` (the newest entry, which the status bar shows), `Items` ("1 item", "5 items"); an entry's `Line` (with ", undone" or ", not undone: <reason>"), `HistoryLine` (the line with its time, "Copied 3 items, 21:04", or ", running"), `CanUndo` and `Location` (where Recent operations goes: the result, or the undo's landing once undone). The log takes a clock for the tests. It was shown as a list pane under the folder list until 2026-11-23 (SPEC.md AF-D3); a change of the selection was an entry too from 2026-10-22 to 2026-11-22 (AF-D11): the log holds only what changed files.
- The marks on the shown entries (AF-3.7) are the bundle's since 2026-11-22, on their second use (the item windows; bundle AX-8.16): `AxKit.Core/Marks` with `MarkChange` and `MarkRow`, tested in `tests/AxKit.Tests/MarksTests`. The window holds them through the item window's `AxKit.Forms/ListSelection`.
- `RecycleBin` and `RecycleRecord` (AF-4.14): the `$I` record beside a bin item's `$R` file parsed into the original path and the deletion time (version 2 with the path's length, the older fixed field before it); `ReadRecord` from the `$R` path, `Parse` from bytes, tested on synthetic records.
- `Archives` (AF-4.12): `Compress` (entries into a new zip in their folder, named after the one entry or the folder, a folder's tree under its name, an empty folder as an entry; the zip's name is taken at once with an empty file, so that a second compress running meanwhile picks the next, then the zip is written to a `.tmp` and moved over it, the empty file deleted on a failure), `Extract` (a zip into a new folder named after it, entry by entry; an entry whose full path would land outside the folder is refused with an `IOException`), `IsZip`; both take an optional progress callback called after each file with the count done and the total, for the operation's line in the status bar (AF-9.2); the names from `FileOperations.FreeName`; .NET's `System.IO.Compression`, no package.
- `UserPrograms` and `UserProgram` (AF-4.11): the user's own programs and scripts of Open with ▸: `DefaultName` (the file name without its extension), `StartInfo` (a `.ps1` through `powershell.exe -NoProfile -ExecutionPolicy Bypass -File`, anything else through the shell, every entry's path an argument, the first one's folder the working directory).
- `FileSettings` (AF-8.1): the settings file, on the bundle's `WindowSettings`, with the last folder, the recent folders, `ShowHidden`, `ShowDotFiles`, `SortBy`, `Programs` (the user's own, a record each; one without a name or a path is dropped), `Favorites` with `IsFavorite`, `ToggleFavorite` and `RemoveFavorite`, and `FavoriteLine` ("Music (C:\Music)", a root by its path alone), for the Favorites list and its submenu (AF-3.9, AF-9.1; not sealed); an older file's player keys are ignored. `Programs` is under the bundle's seal (AF-8.1a, `ProgramsNotUsed`; `src/AxKit.Core/notes/safety.md`); `FileSealTests`.

## Gotchas already learned

- `SHFileOperationW` wants its path list ended by a second null; the marshaller adds one, the code adds the other.
- `Directory.Move` and `File.Move` rename a name whose case alone changes; `Rename` skips the existence check for that case.
- An `ActionEntry` that fell off the front of the log is still the object the window holds for a running operation; the log's `Progress`, `End` and `Fail` change it without looking it up, so nothing breaks when fifty quick operations outrun a slow one.
