# AxClaude.Core: the stream

Notes of `src/AxClaude.Core/Streaming`, moved out of `src/AxClaude.Core/CLAUDE.md` word for word on 2026-11-17, when that file neared its limit; the rest of the pure code's notes are there. The specification is `docs/axClaude/stream-mode.md`; what the recordings of the real stream showed is `tests/fixtures/streams/README.md`.

- `Streaming/ClaudeCodeStream.cs` (2026-11-17; root rule 12, a place of Claude Code's beside `ClaudeCodeHooks` and `ClaudeCodeTranscript`): Claude Code's non-interactive stream, the options that start it, the lines a host writes (`UserLine`, `InterruptLine`, `ModeLine` for the permission mode, the permission tool's `AllowAnswer`, `AlwaysAnswer` (a rule of the session's alone, written to no file), `QuestionAnswer`, `DenyAnswer`) and a line of its output read down to a neutral `StreamLine` of `StreamPart`s (`Read`, tolerant: what is not understood is `StreamKind.Unknown`, never an exception; the start line also gives `Session`, an id that is never shown or logged, and `Commands`, the slash commands the run takes; a status note gives `Status`), with `ShapeOf`, a line's keys without a value. The window's stream source starts Claude Code with `StartArguments` (the stream's options, each message sent back, the relay's file and tool, the window's model, the user's own arguments last; no permission mode is ever named and the session is never kept out of the store), and it is what `tools/ClaudeProbe stream` measures with. `NextMode` is the round of the window's mode key: the three modes every run has, then each other mode the run was itself in, so that the key never reaches the mode that asks nothing unless the user started Claude Code with it. `Interrupted` tells the end line of a turn the user interrupted from a failure. The report is `docs/axClaude/stream.md`; `ClaudeCodeStreamTests`; `ClaudeCodePlacesTests` counts the file as a place. What a model needs of a line (2026-11-17, stage 2 of docs/axClaude/stream-mode.md): a message come back is a `StreamKind.Message` with its text, a slash command's print come back a `CommandOutput`; a call has its `Call` and what it is `About`; a failed result its first line, unless the words are meant for the model alone (`RefusedWords`, which a host's permission tool answers a refusal with); the note that lists the work in the background gives `Tasks` (`StreamTask`); an end line its `Turns`; `ModeWords` says a mode as the screen's mode line does; the notes a model acts on have names (`StatusNote`, `CompactedNote`, `ClearedNote`, `CompactingStatus`). `InitializeLine` is the request a host sends first, measured and not documented for the command line: its answer, a `StreamKind.Control` line, gives the permission mode in force and the version before any message (the fixture `start`), and `Models` (`StreamModelChoice`: the name Claude Code takes, the one it shows, its words, the efforts; a name or a level that is not one word is passed over, since it is sent back after its command; the fixture `choices`); the account and the other lists it also holds are never read, but for the commands' names (`Commands`, since 2026-11-26, SM-5.8; the same 69 as the start line's with 2.1.332, the user's own among them, never logged as a list). `AsksToSignIn` tells an error's words that name the sign-in command (SM-6.2); `RefusedWithWords` is the refusal with the user's words why (SM-7.4), which `Result` hides under the call as it hides a bare refusal. A start line gives `Model`, the model in use by its full name. A command that runs the model (a skill, a custom command) comes back as a replay of Claude Code's tags, read down to a `StreamKind.Command` with the command as typed (2026-11-25, the fixture `custom-command`). `StartArguments` takes the file of axKit's AI tools as a second file of the one `--mcp-config` (SPEC.md FR-9.7). Since 2026-11-26 (SM-4.11, SM-7.7): a result's `StreamPart.Output` is all it gave back, also for a call that went well (the fixture `tool-output`), empty for the words a refusal, an interrupt or a plan sent back give the model alone; `PlanTool` and `PlanMember` are the plan tool and its plan; `AllowWithMode` is the yes that also sets the session's mode (`setMode`, measured: Claude Code's next status names it); `KeepPlanning` the plan sent back with the user's words.
- `Streaming/StreamModel.cs` (2026-11-17): the stream's model, the second on `ClaudeModel`: `Take` a line read down, `Send` a message the window writes, `Ask` and `Answered` for a question the relay passes on. It gives the conversation the screen's labels and markers (`ExchangeBlock` of the base, shared with `SessionModel`), and every line is final as it is added. Its rules are what the recordings in `tests/fixtures/streams` showed (their `README.md` says each), never the documentation alone: Claude works from a message written while idle, or a start line, until an end line that leaves no message of the window's still to come back (the end line's own count of waiting messages is wrong for a message written while a reply was being written); a message's block goes in at once when Claude was idle and else when its line comes back, also inside a running turn; a text is a slash command's print, and no reply, while a command the window sent has no end line yet and no message has come back; a start line with no message waiting and no command running is a turn Claude Code began by itself (`TurnSelfStarted`); a failed or refused call's line becomes `tool error:`; a question of Claude's is a call that gets no line; a subagent's own lines are left out; the end of a turn of the model's rings the bell (`LineStore.RaiseBell`), also when the turn failed, whose error line starts the response as the screen's error row does; an interrupted turn says Interrupted and rings none, and the end of a command Claude Code ran by itself, which counts no turn, rings none; a turn that began with a command awaited and no message is that command's (`_commandTurn`), whatever turns its end counts, so that a skill or a custom command, which runs the model, is no longer awaited after its turn; such a command's own line (`StreamKind.Command`) makes the turn's texts replies, as a message come back does, and is shown as the screen's echo of a command (`you: /name`), which the window's own command has since it was sent (`TakeCommand`; the fixture `custom-command`). `Models` and `ModelInUse` are what the window's lists of the model and the effort are made from (`StreamChoice`). `Up` (on `ClaudeModel`, `Mode is not null` for the screen) is also true once `FirstRequestUnanswered` was called, which the window does when the first request has waited five seconds while the process runs (SM-4.10); a new run forgets it. `AddAnswerRecord` writes the record of an answer to Claude's own questions as `LineKind.AnswerRecord` rows, which `Arrivals` skips as with the screen. Since 2026-11-26 (SM-5.8, SM-5.9, SM-6.2): `Commands`, the slash commands the run takes, from the first request's answer and each start line, forgotten with the run; `TypedTextOf` tells a typed text by them (`TypedText`: a message, a shell line, a command the run takes, a command of Claude Code's screen alone by `SlashCommands`, a name it does not know; a path is a message; with no list every command is taken), and `Send` gives a name the run does not take a message's block, since Claude Code hands it to the model (measured); `CommandWord` is the command as typed for the window's words; `SignInAsked` is raised once for a turn by an error text, or a failed end, whose words name the sign-in command. Since 2026-11-26 (SM-4.11): a call that went well gets what it printed under its line (`TakeResult` with `ToolOutput.Shown`, plain lines, inserted under the call so that calls made together keep their own), and every call's whole output is kept by its line and its shown lines (`OutputOf`); the cap lets go of an output with its lines (`TrimLines`), and `Clear` and `/clear` empty them. `StreamModelTests` replays every fixture through `StreamReplay` against its `expected.txt` (`AXCLAUDE_UPDATE_EXPECTED=1` writes them, to be read through) and says each rule in a test of its own. A new behaviour of the stream is recorded first (`tools/ClaudeProbe stream --record`), then the model is changed. The window's stream source feeds it (`src/AxClaude/MainForm.Stream.cs`): `WorksIn` is told the folder with every start, since a window keeps its model while its folder changes; `ModeName` and `ModesSeen` are Claude Code's own names, for the mode key; a turn the user interrupted adds the line `System: Interrupted` and says the word, since no Done follows.
- `Streaming/ClaudeCodeMarkdown.cs` (2026-11-25, stage 7; SM-4.5; root rule 12, Claude Code's own rendering): `Plain` makes a reply's Markdown read as Claude Code's screen shows it, its rules read off the timeline fixture `long-reply` (bold, italics and code spans lose their marks, never inside a code span; a fence line goes and its code stays as written; a table row is "Column: cell." for each cell; a link whose text is its address is the address, another "text (address)"; a quote loses its mark; lists stay); a heading keeps its marks, which the model makes a heading by and the view hides by its option. `StreamModel.TakeText` gives it a reply's lines, not an error's or a command's print. A rule the screen shows differently is changed here, from a recording, and `ClaudeCodeMarkdownTests` holds the fixture's pair.
- `Streaming/StreamHost.cs` (2026-11-17): a program as one process over three pipes, for the stream (`StreamHostOptions`: the `ProgramLine`, the folder, the environment whole). It knows no word of Claude Code's. Three background threads: the output line by line, the error output drained, and the input written from a queue, since a pipe's write waits while the program does not read; `lineReceived` and `exited` are called on those threads and only post. The end is reported once, after the error output was read to its end, with the exit code; `Write`, `CloseInput` (Claude Code ends when its input ends), `Kill` (the program with what it started). What the program writes as errors is kept in part (`ErrorTail`) for the user to be shown and is never logged. `End` closes the input, which is how a Claude Code that is idle is told to end, and ends the program after a grace when it has not ended, on a thread of the pool: the caller never waits. `StreamHostTests` runs it against Windows' own programs. The window's stream source runs Claude Code in it.
- `Streaming/AskRelay.cs` (2026-11-17, stage 3): the verb `AxKit.exe ask`, the permission tool of a Claude Code run over its stream, decided first in `Program.Main` as `HookRelay`'s verb is. `Serve` is the server's loop over two text streams (MCP's JSON-RPC, one object a line: `initialize`, `tools/list`, `tools/call`; the tool's input schema is `ClaudeCodeStream.PermissionToolInputSchema`, Claude Code's words); `Ask` passes one question to the window's pipe and reads the answer, both as frames of `HookFrame`, which serves a second kind of pipe through its overloads with a prefix (`PipePrefix`, `Variable`: the name and the secret come from the environment the window gives Claude Code, never from a file; a name of another pipe is refused); `ConfigText` is the configuration for `--mcp-config`, with the program and the verb and nothing of the pipe; `ToolName` is what `--permission-prompt-tool` is given. It holds no logic and fails closed: null from the window, an exception, a wrong secret, or a text that is no answer (`IsAnswer`: an object whose `behavior` is allow or deny) all become a no with `NoWindowWords`. It waits for the user without a limit. `AskRelayTests` (both sides stood in, and one real pipe); live, `tools/ClaudeProbe stream` plays three cases with the probe as the window's end (`relay`, `relay-refused`, `relay-gone`). `WriteConfig` writes the configuration's file when it is missing or names another program, whole or not at all. The window's stream source names the relay at every start of Claude Code and serves the pipe (`AskChannel` in `src/AxClaude/MainForm.Stream.cs`): the question's frame in, the answer's frame out when the user has answered.
- `Streaming/StreamAsking.cs` (2026-11-17, stage 5; docs/axClaude/stream-mode.md SM-7.4 to SM-7.6): one question of Claude Code's permission tool as the window asks it, pure. `ClaudeCodeStream.ReadAsk` reads the question down first (`StreamAsk`: the tool, the call, what it is about, the input as it came, and for Claude's own question tool the `AskQuestion`s with their `AskChoice`s). A tool call is one `Question` with no first, where a list starts (`RefuseKey`, then `OnceKey`, `AlwaysKey`, a rule of the session's alone, and `ExplainKey`, which answers nothing: `Explains`, `ExplainText`, everything Claude asks to do with the caution first); its title names who asks and for what, and its text is `AiCaution.Asked`, heard with the question every time (bundle rule 11; the words are `AxKit.Core/AiCaution`'s, `ToolCall` for the explanation). Claude's own questions are asked one after another (`Current`), each with its choices by number and Other last; Other sets `WordsPrompt`, the row Claude Code's screen shows for the user's own words (`ClaudeCodeTexts.TextPromptFor`), which the model hands the window as its `TextPrompt` (`StreamModel.AskWords`), so that the window's own field asks for them; `Answer` gives the relay's answer when the whole is answered, `Escape` goes back from the words to the list and else refuses the whole; `AnswerRecord` then gives the rows Claude Code's screen prints in the answered question's place (`ClaudeCodeTexts.AnsweredLabelText`, then `· question → answer`), empty for a tool call, before the last answer and after a refusal (SM-7.5, 2026-11-25). Never add an answer that runs something in front of no, and never drop the caution from the question's text. `StreamAskingTests`, from the questions the recordings hold. Since 2026-11-26 a tool call's question has its `Core`, the tool and its subject in a few words (`Transcript/PermissionCore`, the same reading as the screen's; the tool alone for Claude's own description of the call), which every answer's label carries in the control area; the keys, and so the answers, are unchanged. Since the same day "No, and tell Claude why" is the second answer (`RefuseWhyKey`, `RefuseWhyLabel`; Yes once, Yes always and Explain are 3, 4 and 5): `AsksForWords` says it answers nothing yet, `Answer` sets `WordsPrompt` (the screen's row for the words, as after Other) and then takes the words, giving the refusal with them; `ToldWhyLine` is the line the window keeps in the conversation, and Escape from the words goes back to the list. Since the same day a call of the plan tool is a plan's question (`IsPlan`, SM-7.7): the title, `AiCaution.PlanAsked` and then the plan made plain (`PlanLines`, headings without their marks) as its text, and four answers, `KeepPlanningKey` (asks for words, then `KeepPlanning`), `PlanManualKey` and `PlanAutoKey` (`AllowWithMode` with `default` or `auto`) and `PlanReadKey` (`Explains`, the text with `AiCaution.Plan` first); `AnswerRecord` gives the plan under the approval, `ToldWhyLine` the plan sent back, and `StandingWords` nothing for a plan.
- `Streaming/StreamChoice.cs` (2026-11-25, SM-5.5): Choose the model and Choose the effort over the stream, pure. `Model` lists the models by the names Claude Code shows, each with its words after the dash, the one in use marked when named by the same name; `Effort` lists every effort the models take, each once, in the list's order, none marked; both null when nothing is known. `CommandFor` gives the line the window sends for a key (`/model haiku`), null for what is no answer; the command comes from `ClaudeCodeSettings`, never written here. The window shows `Question` through its own code for a question and keeps the choice apart from a question of Claude Code's, which closes it (`MainForm.Stream.cs`). `StreamChoiceTests`, from the fixture `choices`.
- `Streaming/SessionHandover.cs` (2026-11-25, stage 6; docs/axClaude/stream-mode.md SM-8, its measurements in section 13): which conversation a start takes up. A session is one file whichever source wrote it, and either source takes the other's up by its id; the stream writes nothing of the conversation it takes up; the interactive program's `--continue` passes over every session the stream began, for good, while the stream's takes the folder's newest. So `ForStream` turns each `--continue` of a stream window's arguments into `--resume` with `Newest` (the session file written last, directly in the folder's `ProjectFolders`), and `ForScreen` turns a screen window's `--continue` into `--resume` with the session a stream window kept for the folder (`AppSettings.StreamSessions`, `KeptSession`; kept over the list as the file has it now, since the settings file's members are merged whole) while that is still the newest. `IsSessionId` is the gate of every id put on a command line, into the settings or into a file's name: a UUID in its usual form, never what a file or a line merely holds. `Read` reads a session file whole through `RecordTail` and `ClaudeCodeTranscript.Parse`, off the window's thread, null when it cannot. `StreamModel.ShowOlder` makes the entries the lines the screen's model makes of a replayed conversation (`# Input n from previous session`, the `you:` line, the output marker before the first reply line, the replies made plain, `tool:` with the tool's name alone, `tool error:` for a failed result, a line of the app's for an interrupt and a compaction; nothing Claude Code wrote in the user's place, no subagent's entry, no question of Claude's own), numbered apart from the live exchanges; `HoldsConversation` keeps a restart from showing it twice. The window reads the file before the start and adds the lines right after it, before Ready (`MainForm.Stream.cs`). `SessionHandoverTests`, from the hand-written files of `tests/fixtures/records` (`stream-session.jsonl` has the shape a stream's session was measured in); the stand-in of the stream writes such a file where Claude Code keeps it with `--session` (script 51), and script 52 hands a conversation between the sources live. Since 2026-11-26 (SM-8.5): `AsksToChoose` (a bare `--resume`), `WithChosen` (the chosen id in its place, or none) and `All` (every session file of the project folders, newest first) serve the choice of an earlier conversation.
- `Streaming/ToolOutput.cs` (2026-11-26, SM-4.11; stream-equivalence.md L21): what a tool printed as a conversation shows it under the call, pure and of no program: `Shown`, the first `ShownLines` (three, the screen's preview, measured with 2.1.332) and `MoreLines` ("… +9 lines", the screen's form less its Ctrl+O hint); `Text` and `Lines`, the whole, for a key that reads all of it (none yet). `ToolOutputTests`; the model's use of it in `StreamModelTests`, from the fixture `tool-output`.
- `Streaming/ConversationChoice.cs` (2026-11-26, SM-8.5; stream-equivalence.md L4): the choice of an earlier conversation over the stream, as `StreamChoice` is for the model. `Find` reads the folder's session files off the window's thread (`SessionHandover.All`, each through `RecordTail.ReadAll` to `ReadBytes` only), `FirstWordsOf` names one by the first words of its first message (a turn Claude Code began, an agent's prompt, a note are none; `Words`, `Characters`, hidden characters written out), `Name` adds the date and time (`FieldTypes.ShortDate`), `Of` makes the `Question` and `SessionFor` gives the id of a key. A session file is private: nothing of it is logged, and no more than the first words shown. The window: `ChooseConversation` and `ResumeChosen` in `src/AxClaude/MainForm.Stream.cs`. `ConversationChoiceTests`, from `tests/fixtures/records`; the stand-in writes several session files with `--session a,b` (script 58).
- Rules the audit of 2026-11-21 set (docs/axClaude/stream-mode.md section 13): a relay writes its secret only to a pipe this same program file serves (`ThisProgram.Serves`), never to a pipe known by its name alone; text of the stream is never put into a control as it came: what Claude asks goes through `StreamAsking.Shown` (hidden characters written out), a line of the conversation through `StreamModel.Printable` (control characters dropped), since a character of code 0 ends a text box's text; a title says Claude's own description as Claude's (`StreamAsk.AboutDescribes`) and says when the input holds more than it names (`AboutCut`, `HoldsMore`); the program runs in a `ChildJob`, so that it never outlives the window.
