# axTerminal, the window

The WinForms side of axTerminal: axClaude's window around a shell, a transcript with NVDA-style single-key navigation and a command field at the bottom. The pure code (the launcher, the model, the arrivals, the history, the settings) is `src/AxTerminal.Core`, with its own `CLAUDE.md`; the console pieces (ConPTY, the parser, the screen, the line store, the mirror) are `src/AxKit.Core`'s and the view is `src/AxKit.Forms/TranscriptView`. The spec is `docs/axTerminal/SPEC.md` ("SPEC.md" below); the guide `docs/axTerminal/user-guide.md` is embedded by `AxTerminal.csproj` for Help → User guide; the manual test plan is `docs/axTerminal/nvda-test-plan.md`. The bundle rules are in the root `CLAUDE.md`.

## Commands

```
& '.\scripts to run-individual-apps\run-axTerminal.ps1' C:\src\myproject    # build AxKit and start axTerminal there (run.ps1 -App terminal; -NoBuild)
dotnet build src/AxTerminal/AxTerminal.csproj -o <scratch dir>   # while AxKit runs: never into src/AxKit/bin
dotnet test tests/AxTerminal.Tests/AxTerminal.Tests.csproj
```

## Where things are

- `TerminalForm` (on `AxKit.Forms/ConsoleForm`, the bundle's console window shared with axClaude since 2026-10-23, which owns the view, the field, the control area, the status bar pair, the pty bridge, the paced writes with their one pump, the recording, the export, find, the signals, the music, the focus keys, the bookmark toggle and the notice hooks; on `AxKitForm` under it, bundle AX-6.5), one class in partial files, one per section:
  - `TerminalForm.cs` (fields, the two constructors, `OnShown`, `TakeHandedCommand` (AT-1.5a: a command handed over at start goes into the field as one line for the shell; its caution is the field's own name, `HandedCommand.FieldName`, while the line stands there as it came, since NVDA reads a name before the text and cut the announcement it was until 2026-11-22; kept as a system line too; never sent, and never add a way to send it), the closing question (Keep running keeps a pending update restart through the base's `KeepWorkingAfterUpdate`, AX-3.5), the hooks: `Working`, `SaveCommand` with the export, the diagnostics lines, `PathInHand`);
  - `TerminalForm.Ui.cs` (the menus with their keys as one command list, `Add` and `AddKey` of `AxKitForm`, docs/axKit/app-kit.md AK-2: no key switch is left, the console window's read to the end aside; Speak output, the title, the status bar);
  - `TerminalForm.Input.cs` (the field's keys, sending with PowerShell's extra Enter through the base's queue, interrupt and Escape, Enter on a line, the recent commands in the control area; every key sequence sent and every fact about a shell is named by `AxTerminal.Core`'s `ShellTexts`, never written here, root `CLAUDE.md` rule 12);
  - `TerminalForm.Process.cs` (starting, stopping and restarting the shell around the base's `StartProcess` and `StopProcess`, the exit; the consent of a custom shell or a shell of the user's is `ConsentTarget.CommandLineShell`, for the name with the command line, and the start's system line names the line, AT-1.6b);
  - `TerminalForm.Model.cs` (what the model reports: the tick and the speech, Ready, Done or Failed with the base's signals, the "a program asks" heuristic, F7 (what is running), Clear; the output's speech is held for 300 ms from its first line (`HoldOutput`), so that the word of a command's end stands before its whole result, "Done. hello", as one announcement (`SayWithFinished`, AT-5.1, the maintainer's decision of 2026-11-22); never raise the word and the output as two announcements, NVDA speaks only one of them);
  - `TerminalForm.NewShell.cs` (the New session notice with the shared `SessionControls`, Switch shell, the user's own shells (AT-1.6a: `FillUserShells` makes their items in Switch shell and Remove a shell again as the submenu opens, through its `RefreshedOnOpening`, so that the palette lists them; `AddUserShell` is two `AskText` notices, the name then the command line; `RemoveUserShell` switches to the default shell when the one removed is in use; a user's shell is `_shell` Custom with `_userShell` set, `ShellName` and `CustomLine` read it), the folder picker, the recent folders' action, Show in).
  - `TerminalForm.Screen.cs` (the screen view of a full-screen program, SPEC.md AT-9.9: `FollowScreen` at every pass over the transcript opens, follows and closes it from `TerminalModel.Page`; the rows that changed replaced with the drawing held, the caret on the program's cursor in keys to the program and kept in reading the screen; `ToggleScreenMode` on Ctrl+Space; the marked run said through `ScreenMarks`, ProgramSaid, not interrupting; the base's notice, focus and announcement hooks turned to the view while it shows; AT-9.10: `PlacesRefused` gives Alt+1, Alt+2 and Alt+3 the words of `ScreenView.PlacesWords` while it shows, `FindDialog` and `FindNext` search its text with the base's find of a text box in reading the screen and say `FindWaitsWords` in keys to the program, and the model's `Answer`, a colour question's answer, goes to the shell through `Write`), with its text `ScreenBox` (on `AxKitTextBox`, read-only, no wrapping; in keys to the program its own `ProcessCmdKey` takes every key before the window's commands, but Ctrl+Space, F1 and Alt+F4, and sends what `ScreenKeys` names, and its `WndProc` sends the characters and drops the edit control's own key and menu messages).
  - A change goes in the file of its section; what both console windows need goes to `ConsoleForm`.
- `AxTerminalKeys`: the window's keys (SPEC.md AT-6.2; bundle AX-8), the one place a key is changed, with `Transcript` (the view's keys as data); a notice's heading letters are the bundle's (`TextJump.HeadingLetters`). `HelpText`: the F1 text and the embedded guide. `AxTerminalApp`: the entry point through `AxKit.Forms/AppHost`.

## Rules

1. Every control gets an `AccessibleName`; every action in the SPEC.md key table works without a mouse; the caret in the terminal moves only on the user's own command; results of navigation are one UI Automation notification.
2. Never block the UI thread on the pseudo console: reads come on a background thread and are posted in bursts (the console window's `StartProcess`).
3. No second window (AX-7.2): questions and errors are notices (`ShowNotice`), the recent commands take the field's place (`ControlArea`); the folder and file pickers are the only separate windows.
4. Run the `accessibility-review` skill on a change here before committing, and check it with NVDA following the test plan.

## Gotchas already learned (do not rediscover)

- The gotchas of the EDIT control, NVDA's reading after a key press, the notice state and the sounds are axClaude's and live in `src/AxClaude/CLAUDE.md`; the shell's own are in `src/AxTerminal.Core/CLAUDE.md` (PSReadLine off with a screen reader, the empty line that ends a block, the exit code rule, cls).
- The state in the status bar is empty until the shell's first mark arrives: a custom shell without marks shows no state at all, by design (SPEC.md AT-1.4).
- The screen view's name never says the way the keys go: NVDA speaks a focused control's new name by itself, so a name changed with Ctrl+Space would be said twice with the two words (AT-9.2). Windows' `edit` took no keys for about four seconds after it starts while its colour questions went unanswered (AT-9.7); since they are answered (AT-9.10) it takes keys at once, and a script waits half a second before its first key. An answer is written only while the alternate screen is in force: on the main screen PowerShell's own line reading would take it as typed text.
- The review of 2026-11-27: a command that needs the command field asks `FieldBehindScreen` first (Recent commands, the sends), which says the places' words while the screen view shows and does nothing; a new command that puts something into the field or focuses it needs the same. `ShowPage` keeps the user's selection in reading the screen over a change of the rows (`EditKeys.SelectionEnds`, `ScreenView.Kept`, `EditKeys.Select`). `Relaunch` calls `RequoteHandedCommand`: a handed line still in the field as it came is made again for the shell that starts (`HandedCommand.ForNewShell`), or taken out, and that is said.
