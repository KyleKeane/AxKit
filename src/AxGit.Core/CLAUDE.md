# AxGit.Core, the pure code

Everything of axGIT that needs no window: git as a process and the parsers of its output. Unit tested in `tests/AxGit.Tests` from recorded git output, with no git process but a fake git.cmd the runner tests write. The spec is `docs/axGIT/SPEC.md` ("SPEC.md" below); the window is `src/AxGit`, with its own `CLAUDE.md`. The bundle rules are in the root `CLAUDE.md`.

## Commands

```
dotnet test tests/AxGit.Tests/AxGit.Tests.csproj
git -C <repo> status --porcelain=v2 --branch --untracked-files=all   # what GitStatus.Parse reads
git -C <repo> log -n200 --date=short --format=%h%x09%ad%x09%an%x09%s   # what GitLog.Parse reads
git -C <repo> branch --list --format=%(refname:short)%09%(HEAD)%09%(upstream:short)%09%(upstream:track)
```

## Where things are

This folder is the one place for everything git is told and everything read from it (root `CLAUDE.md` rule 12; `docs/axKit/access-layers.md`): the window writes no option of git's and matches no text of git's, and `GitTextsTests` fails when it does or when a characteristic word leaves its file here.

- `GitTexts` (2026-11-14): git's words that belong to no record of a view: the argument lists of the commands on the whole repository (`StageAllArguments`, `UnstageAllArguments`, `CommitArguments`, `FetchArguments`, `PullArguments`, `PushArguments`, each of the three with the remote the consent was read for on its command line, after `--`, AG-5.4a; a push ties a branch without an upstream to `DefaultRemote`), those of the commands on several files (2026-11-22, the selection: `StageArguments`, `UnstageArguments` and `DiscardArguments` of a set of paths, every path after `--`, the window calling once for each `PathsPerCall` paths), and the two texts of git's output an announcement is chosen by (`SaysUpToDate` after a pull, `CommittedHash` from the summary line of a commit). A new command of the window's gets its arguments here or on the record it acts on, never in the window.
- `GitRunner`: `RunAsync` (one process per command, run through `AxKit.Core/ProcessRun` since 2026-10-25, `-C <repo> --git-dir=<the git folder read> --work-tree=<repo> -c core.quotepath=false -c color.ui=never` in front of the arguments (the fifth pass, P1: `Command(repository, gitDir, arguments)`, git looks for no repository of its own; `findRepository` for the one question of `GitSession` that lets git find it, its ownership check), the environment by `SetEnvironment` (pure: the caller's variables, `FixedEnvironment`, and in a repository none of `RepositoryVariables`, GIT_DIR and the rest, and `GIT_CEILING_DIRECTORIES` the folder above it), `GIT_TERMINAL_PROMPT=0`, both streams read in UTF-8 on tasks, a timeout that kills the process; `GitNotFoundException` when git is not found; `Program`, the executable, git unless the tests point it at a fake: looked for in `InstallFolders`, Git for Windows' `Git\cmd` under Program Files, before the PATH's folders on this computer, through `AxKit.Core.SystemPrograms.Installed`, since the agreement is for Git by its name, bundle repairs R-70), `Command` (the argument list, pure, tested). `GitResult` carries the exit code and both texts, `FirstLine` for an announcement and `AllText` for a notice; `Result` (2026-11-27, pure) turns a run into it: a run stopped at the timeout is `TimedOut`, exit code -1 and never `Ok` whatever it printed, with the reason after git's own complaint; a run git finished while a program it started held its output open is `OutputHeldOpen`, git's own exit code and output (that other program may have written after git's, so the window reads no list from it). Since the review's second pass of 2026-11-27: `Command` also turns git's automatic maintenance off for every run (it runs `gc.recentObjectsHook`); what is set aside for a repository that is not trusted is a list of `GitSetting` given through the environment (`SetOverrides`: `GIT_CONFIG_COUNT`, `GIT_CONFIG_KEY_n`, `GIT_CONFIG_VALUE_n`), never a `-c name=` argument, which a name with an equals sign in it defeats; and a `GitResult`'s complaint, `FirstLine` and `AllText` never hold the sign-in of an address (`GitRemote.WithoutSignIn`), by the record itself.
- `UntrackedFile` (AG-3.3, 2026-11-27): an untracked file's first 200 KB read and no more (`ReadAsync`), and the details' text with its first line (`Details`).
- `GitStatus` and `ChangedFile`, `RepositoryStatus` (SPEC.md AG-3.1): porcelain v2 to records; the item's `Label` ("Modified src/Foo.cs, unstaged"), the list's name, the status bar text, and the argument lists on one file: `DiffArguments` for Enter and `DiscardArguments` for Delete, so that the window knows no git syntax (Stage and Unstage of the selected files go through `GitTexts`; a file's own stage toggle, Space until 2026-11-22, went with it). `Unquote` undoes git's C-style quoting of odd paths.
- `GitLog` and `Commit` (AG-4): the tab-separated log to records, `Label`, `ShowArguments`.
- `GitBranches` and `Branch` (AG-5): the branch list to records with the upstream state (a detached HEAD, which git lists in parentheses, left out), `Label`, `SwitchArguments`, `CreateArguments`.
- `GitTrust` (AG-1.6; security audit S-2; the line since the review's fourth pass of 2026-11-28, T1): the rules of what in a repository is a risk, how a risk is named and said, and what is set aside. Pure, tested on indexes git wrote and on indexes written byte by byte (`GitIndexTests`).

## Gotchas already learned

- `git status --porcelain=v2` without `-z` quotes a path only when it holds control characters, quotes or a backslash once `core.quotepath` is off; `Unquote` handles the C escapes and octal bytes. Renames come as one line with the new path, a tab, the old path.
- The log and branch formats use `%x09` and `%09` for tabs, so a subject with spaces or colons parses cleanly; a subject never holds a tab.
- `LC_ALL=C.UTF-8` keeps git's messages in English (the announcements quote them) and its output in UTF-8; `GIT_PAGER=cat` is belt and braces, git does not page without a terminal anyway.
