# The question flow and the message path, review by review

The rules the reviews of 2026-11-27 and 2026-11-28 set for the control area's answers and for a message on its way to Claude Code (`MainForm.Area.cs`, `MainForm.Input.cs`; SPEC.md D33). Moved here word for word from `src/AxClaude/CLAUDE.md`'s bullet of `MainForm.Area.cs` on 2026-11-28, when that file reached its limit. Read it before changing the flow or the message path, and keep it current in the same commit.

## Until the sixth review (moved word for word)

Since 2026-11-27, two rules against an answer that reaches a question the user did not hear (bundle rule 11; read them before changing the flow). With the screen, `MarkWaitAnswered` (the answer, Escape, a key of Claude Code's own) makes the wait `Answered`, and `OnTranscriptChanged` makes it `Stale` once a frame shows anything else in its place or the same title and answers around other lines (Core's `AnsweredWait.Over`, `Question.Content`): the settle then shows and says what waits afresh though it reads the same (two files to create in one reply), and never acts while the user's keys still go out (`AnsweredWait.SettleWaits`; script 61). Over the stream, every list and field that answers asks `StillAsked` first, with the model's number of what it was shown for (`ClaudeModel.Asked`, `StillAsks`; the wait keeps it for a typed answer): the next request is the model's at once while the old list still shows (script 62). The second review of that day, the same class (what the user did not hear is never acted on by a key): every list and field reaches the area through `AreaList` or `AreaField` alone, which hold it (`hold: true`, bundle AX-6.4; never work the hold out from `UserActed`, which decides the chime only) and wrap Enter, Escape and a key of its own in the caller's check (`StillAsked`, `ScreenStillShown`, `OfferStillShown`); `WaitsUnheard` (Core's `AnsweredWait.Unheard`) is true from the frame that brings or replaces what waits until the settle has shown or announced it, and then nothing goes to Claude Code as an answer, also not from the message field (`FieldWaitsForQuestion`) or by the mode key; `LapseAnswer` takes `Answered` back when the question still stands three seconds after a key that answered nothing; an unanswered question replaced under the same title by one of another core is `Stale` (`AnsweredWait.Replaced`); `Interrupt` stamps the user's act as ending now; a notice's buttons ask `ScreenStillInforms`. Scripts 61 and 65 play them; `WindowLastResortTests` reads the source for the rest, and says what that is worth. The third review of that day: `StillAsked` takes the signature the control was shown for (`AnsweredWait.StillWaits`); every queued write asks again right before it goes (`MessageChecks`, `AnswerStill`, `QueuedWrite`; scripts 65 and 68); the mode key is refused while Claude asks and a key of Claude Code's own while the area shows the question (`KeyMayGoToClaude`), with a table of every console write in `WindowLastResortTests`; an information screen's notice is always `ByItself` and shows its rows through `DisplayText`; scripts 66 and 67 play a question that gets the focus late or under a notice. The fourth review of that day: a message's Enter goes only on a positive check (`MessageChecks` gives each write of a message its check, `QueuedWrite.MessageEnter`: the frame shows the message on the prompt row, `SessionModel.PromptHolds`, and nothing is asked); when the row does not show it yet, the Enter is asked again every tenth of a second for three seconds (until the fifth review a timer of its own did it, outside the queue); the Enter sent again asks the same positive check (`QueuedWrite.EnterAgain`); "Sent", "Queued" and `FlowSent` come when the Enter goes, never before (`QueueWrites`' `sent`), and a dropped message is taken back from the conversation (`ClaudeModel.TakeBack`); a message sent into a question is bound to it by `WaitIdentity`; `ConsoleForm.Write` and `Enqueue` take their check as a required argument (`still: null` written out where none is asked), and `WindowLastResortTests`' table says why for each method. The stand-in draws typed text on its prompt row (`tools/AxAutomate/StandIn.cs`, `EchoTyped`), so the scripts' messages pass the check as Claude Code's would. The fifth review of that day: one message in flight (`MainForm.Input.cs`): the Enter's check answers an `AxKit.Core/Pty/WriteCheck` (`QueuedWrite.MessageEnter`), "not yet" keeping it first in the queue with everything behind it waiting, never read as over, and three seconds later over; "Sent", `FlowSent` and the count come only from inside that check; every message whose Enter had not gone is given back in one place, `WritesDropped` (the console window's hook, called whenever its queue is dropped with writes in it, and by `StopProcess` through `GiveBackUnsentOnStop`), the reason in `_givenBack`: taken back from the conversation, into the field, the row emptied before the next send (`_rowHoldsUnsent`, `ClearRestoredMessage`), said as `EventKind.NotSent`; the empty field's Enter is checked too (`EmptyFieldEnter`, `ClaudeModel.PromptDraft`); the Enter sent again is skipped alone when it no longer holds. Scripts 70 and 71 play it with the stand-in's `echoAfter`, `echo` and `keys`. The sixth review: a message is in flight until Claude Code has taken it (`MessageChecks`; the rules are Core's `QueuedWrite` and `AxKit.Core/Pty/WriteQueue`): typed only onto a bare row, its Enter once the row holds it, the Enter once more after 1.5 s, then an empty write that waits until the row is bare again; 3 s at each step, then it and all behind it are given back (`GivenBack`); the row is emptied only of exactly the text given back; every text not back in the field is written out, a stop included (`_givenBackOnStop`, kept by `Relaunch`). Scripts 73 to 76 (`dropEnters`).

## The seventh review (2026-11-28)

A message is given back only on positive evidence that Claude Code did not take it; a time limit alone is none. The checks of a message's writes are Core's `MessageFlight` (its `Writes`, which `QueueWrites` queues and the tests queue the same, and its `First`, `Rest`, `Enter`, `Again` and `Taken`); `MessageChecks` only wraps one of them with what the window adds (the reason into `_givenBack` from `MessageFlight.Why`, "Sent" and `FlowSent` when `Entered` turns, the log when `EnteredAgain` turns, the flight ended in `_unsent` when `Done`). The rules, each with its test:

- K1: at the three seconds' limit after the Enter only a row that still shows the message gives it back (`QueuedWrite.Taken`, `GivenBack.StillShown`, "Claude's prompt row still showed your message three seconds after its Enter"); a row not drawn or holding other text counts as taken, and the next message waits for a bare row before it is typed. `MessageFlightTests` runs the flights over the recordings with the recorded clock, /clear's row not drawn from 13448 ms to 16144 ms among them; script 77 with the stand-in's `hideAfterTake`.
- K2: when Claude Code asks before the row was seen without the message, the row of the last frame that asked nothing decides (`ClaudeModel.PromptHeldBeforeAsk`): it still showed the message, so the message is given back, typed, and the next send empties the row (`GivenBack.AskedOverIt`, said without cutting into the question); else it is taken. Script 78, a question drawn under the held draft.
- K3: every reading of the row reads one frame: `SessionModel` keeps the rows' text and the cursor's row as of the frame's end (`KeepFrame`), and as of the last frame that asked nothing (`KeepAskFree`); `PromptRowReadingTests` replays the recordings cut at random. After /clear the prompt row keeps its cells (`Screen.DetachRows(keepCells)`, read through `Screen.UnlinedText`): until then the first message after /clear was never on the row for the window.
- K4: a text with a hidden character is held only by a row that shows it with that character, and gets no second Enter (`QueuedWrite.EnterAgain`'s `hides`); an offered command with any character `DisplayText.VisibleCommand` writes out is refused (`McpOffer.Refusal`).
- K5: an offered line, or the /feedback line about one, not put back into the field is written out as `McpOffer.Shown` makes it, under `AiCaution.OfferedNotSent` or `ConcernNotSent` (`QueueWrites`' `shown`; script 75).
- L1: closing asks first while a message is in flight or the field still holds what was given back (`MessageAtStake`, `ClosingQuestion`; script 77).
- L2: a check that throws never stops the pump: `WriteQueue.Next` answers `WriteStepKind.Failed`, and `WritesDropped(failed: true)` gives the messages back with `GivenBack.Failed`.
- L3: a blank between two words on one row counts, only a row join may lose one (`SessionModel.DraftIs`); paste marks of one draft are numbered in order, and the row is emptied of a message given back only while it is exactly as it was seen holding it (`MessageFlight.SeenDraft`).
- L6: the empty field's Enter, queued behind a message, says "Nothing to send" and is skipped alone when the row is bare by its turn; a question in between drops it and what is behind it with `GivenBack.Asked`.
- L7: the event core is told nothing of a give-back: a sent message only moves its generation on and starts the record's folder rule for the message's key (`MainForm.Flow.cs`, `FlowSent`; `notes/beside-the-screen.md`), and neither is made wrong by a message that never reached Claude Code: no entry with its key comes, and the next message moves the generation on again.
