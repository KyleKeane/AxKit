# axClaude's window: the machinery beside the screen

Notes of `MainForm.Flow.cs`, `MainForm.Record.cs` and `MainForm.Hooks.cs`: how the window learns what happens in a session beside reading the screen. The index and the rest of the window's notes are `src/AxClaude/CLAUDE.md`.

This machinery is the screen source's own (docs/axClaude/stream-mode.md SM-3.6, 2026-11-17). Its three files are the only ones that ask `_screenModel`, the screen's `SessionModel`, and only for what is not on `ClaudeModel`: `Marked`, `Work` and `Epoch` (inside `FlowFeed.FromFrame`) and `TurnOpen`. `WireFlow` subscribes the core to the turn marks and is called before `WireHooks`, which notes the first end mark of a run for itself, so the core hears a mark first, as it always did. Everything else these files ask about Claude they ask `_model`, as the rest of the window does.

## The core beside the window (2026-11-15)

`MainForm.Flow.cs`. The specification is `docs/axClaude/events-and-grounding.md` (EG-4.8, EG-4.10, EG-4.11, EG-9) and is not restated here.

- One queue, one loop. Everything that happens is an input handed to `EnqueueFlow`: the model's marks, bells and passes (`FlowFrame`), the user's actions (`FlowActed`, `FlowSent` in `QueueWrites`, `FlowQuestionShown`), Claude's start and end (the end in `StopProcess` alone). The loop gives each to `SessionFlow.Handle` and carries its decisions out before the next; an input raised meanwhile is only queued, so the core never runs nested. A new source posts to the UI thread and calls `EnqueueFlow`; nothing else calls the core.
- In charge of the state (2026-11-17, EG-6.1 to EG-6.4): `Built` names `FlowCharge.State`. Whether Claude works is `ClaudeWorks`, the core's word while `FlowDecides(FlowCharge.State)` and the screen's otherwise (the setting `eventCore` set to `shadow`, a core that failed), and the status bar, the music, `ClaudeBusy`, `ClaudeIdle`, the Enter sent again and the ready rule all ask it. One other place still reads the model's own `Working`, the argument of `Arrivals.Update` in `OnTranscriptChanged`: the core is handed a frame only after that call (`FlowFrame` needs its result), so in a run without marks the core's word there is the frame before's, and a reply's row drawn with the first working frame was spoken while Claude worked (script 27 failed on it); it moves with reply speech (WP-A18), never by itself. `ClaudeInTurn` adds the core's ending for "Queued". `Carry` carries `StateChanged` out with `UpdateStatus` and `UpdateMusic`, since a mark, an event or a tick changes the state with no frame behind it, and `FlowTurnToModel` sets `SessionModel.TurnOpen` there and after every input (`FlowAfter`): the ending changes without a decision, and a value left true would hold a sent message's block for good. Null again when the core does not decide. The model reads `TurnOpen` only as a frame ends, so when the value falls `FlowTurnToModel` asks for one more frame end of the screen as it stands (`After`, never inside the pass that runs): without it a held block whose echo never came stayed out of the conversation after the turn (SPEC.md FR-4.7). What waits for Claude to be idle (`ShowOfferWhenIdle`, `OpenDraftsWhenIdle`) is still asked with a frame or a closed notice alone.
- In charge of Done (2026-11-17, EG-5.6, EG-6.5, section 4.2): `Built` names `FlowCharge.Done` too. While `FlowDecides(FlowCharge.Done)` the bell's handler only queues the bell for the core. A bell that ends a turn is answered with `SayDone`, at the core's own moment, and `FlowDone` carries it out: put away, the Done is owed (`_doneOwed`, `SettledWhilePutAway`); else `SpeakHeld`, then "Done" by its switch and `Signal(question: false)`. A bell that ends no turn comes back as `AttentionBell`, and `FlowBell` does what the handler did before (`_bellPending`, the settle restarted), with `_bellNoMarks` for a run that has shown no mark. The settle says Done by itself only where `DoneBySettle` says so (`MainForm.Model.cs`): a Done that was owed, a bell of a run without marks, and every bell while the core does not decide (the setting `eventCore`, a core that failed), which is the old rule whole and why the handler's old lines stay. Never ask `_bellPending` alone whether to say Done. The `SpeakHeld` in `FlowDone` is not in the package's text: reply speech is still the window's own, behind its 250 ms hold, and with a record the core's Done comes some 40 ms after the reply's frame, so the reply was heard after its Done (measured with script 35); it goes when the core releases the lines itself (WP-A18). The core's Done has no settle behind it: something that must happen at a turn's end belongs in `FlowDone`, not in `OnFrameSettled`. A survey shown right at a turn's end no longer has its Done said first by the settle (the "Done first" branch is the old rule's): the core's Done comes at its own moment, before or after the survey is shown. A core that fails on a bell hands that bell to the settle (the catch of `EnqueueFlow`); a Done it owed at that moment is not said.
- A turn Claude Code began by itself (SPEC.md FR-7.3b): for the core's `TurnSelfStarted`, `Carry` says `SelfStartedWords` while the core decides the state and `AnnounceSelfStarted` is on. No sound, nothing to the shadow; script 36.
- In shadow: reply speech and the background. There the window's own code decides and tells `FlowShadow` what it did (`FlowSpoke` with the lines it spoke, of which the shadow keeps the kinds alone, `FlowSaidDone` where the settle said Done by itself, and in `FlowFrame` that a question is open); the log gets one `Events: shadow` line for each turn, which for a turn that differed names the kinds, the states and an open question (EG-4.11), never a text. The shadow still needs the state of both sides, since a turn of its line lasts until both are idle: while the core decides the state, `Carry` tells it the one state for both at the one time (`FlowWindowState`), so the line never names the state as a difference; with `eventCore` set to `shadow` the window's side is the screen's again and the line compares the two as before. Done likewise: `FlowDone` tells both sides the one Done at the one time, after the lines it spoke first and also when the Done is only owed, so the line names no difference in Done; the Done of a run without marks is the settle's own, the core says none, and the line names that difference, truly. No timer of the window was replaced. Moving a family to the core adds it to `Built` and asks `FlowDecides` where the old code acts; the old path stays, for the screen alone and for the setting `eventCore`.
- `_flowTimer` is the core's one timer. An exception from the core is logged as an ERROR and switches the core off until Claude starts again; it must never take the window down.
- The record's reader is told through the partial methods declared there (`RecordTurn` and six more); the hooks' pipe and the reader get files of their own.

## Claude Code's hooks in the window (2026-11-15)

`MainForm.Hooks.cs`. The specification is `docs/axClaude/events-and-grounding.md` (EG-2, EG-9.1, EG-10) and is not restated here.

- A start that passes no hooks is the old start: no file, no pipe, no variable, no wait. `HookArguments` decides for each start and gives `_health` the one word why not; `HookNotPassed` and `HookStopChannel` undo what a start that fails afterwards had begun.
- The version gate needs `claude --version` before the line is built. `WireHooks` asks it as the window is made, never before the consent to Claude Code; `HookVersionOf` keeps the answer for each program file; `StartClaude` waits only for what is left of its two seconds (`HookStartWhenAnswered`, then `StartClaudeNow`). `_hookStart` drops a wait that another start or a stop overtook; `_hookVersionWait` makes the status bar say starting and keeps a message in its field.
- `HookChannel`: one pipe instance served in turn on a thread of its own, every wait and read under a token; `Stop` cancels and never joins. Do not copy the blocking wait of `McpChannel`: such a pipe cannot close with its Claude Code. Faults are counted and get one `Log.Info` line for each start; an ERROR line fails every window script.
- `StopProcess` stops the pipe after the base has ended Claude Code, so that the hook of the session's end finds it at once. `HookArrived` checks the session and the file's path, counts, and calls `EnqueueFlow`; nothing an event carries is logged.
