# AxKit.Forms: the shared controls, keys and sounds

Part of the notes of `src/AxKit.Forms` (the index is `src/AxKit.Forms/CLAUDE.md`). One bullet per piece.

- `Sounds`: the chimes and ticks through one winmm wave-out device kept open for the life of the process, every sound prepared once and queued with a single write, and axClaude's working music as one buffer that loops with the loop flags on a second device, so that a chime's reset never cuts it (see the gotchas in `src/AxClaude/CLAUDE.md`). `Notice()` is the one every window uses; `Edge()` (a short low note, 2026-10-22; two falling an octave and louder since 2026-10-23, the one note lost under speech) is the earcon for a key that moves nothing or a typed name nothing starts with (axFile AF-3.6), where a sentence would be noise. `Offer()` (five short swoops falling from 2400 to 900 Hz, an alarm, `WaveTone.Swoops`, chosen by ear; 2026-11-13) is the chime of a command offered for the user to run (axClaude FR-2.12), in place of `Notice()`, so that an offer is told from a question before a word is spoken. `Heading()` (G4 leaping to G5, 85 ms, AX-7.9, 2026-11-11) is played by the window's `SoundOnHeading` (`AxKitForm.Theme.cs`, unless Options, Text, Sound on headings is off, `display.headingSound`, TH-6.6) when the user's key lands on a heading: the item apps' `ItemForm` from `AxKitList.UserMovedSelection` on a section row, the editors with Markdown headings and every notice's text through `FollowHeadings` from `AxKitTextBox.UserMovedLine`.
- `EditKeys.Page`: Page Up and Page Down in an edit control, one screen at a time and to the ends (`EM_LINESCROLL` against `EM_GETFIRSTVISIBLELINE`, since `EM_SCROLLCARET` is ignored without the focus).
- `EditKeys.Paragraph`: Ctrl+Up and Ctrl+Down in an edit control move to the start of the previous or next paragraph (the first line, or a line with text after a blank line), and with Shift grow the selection to there (AX-8.2). The EDIT control's own keys scroll a row and leave the caret, which a screen reader reads as the same text again. The arithmetic is `AxKit.Core.Paragraphs`, tested. The control hides the selection's anchor: the caret is drawn at the active end, so `GetCaretPos` against the position of the selection's start (`GetPositionFromCharIndex`) tells which end moves, and `EM_SETSEL` takes the anchor first and the caret second.
- `EditKeys`: the KeyDown handler that gives any edit control the two above; since 2026-11-09 nothing subscribes it: `AxKitTextBox` calls it itself, after the window's own handlers, for a multi-line control (`TextBoxTests` fails on a subscription, which would move the caret twice).
- `AxKitTextBox` (AX-8.9, 2026-11-09): the edit control of every app, a `TextBox` with no length cap and the edit keys above built in, after the window's own KeyDown handlers, so that a window's key on the same stroke comes first (axTerminal's Ctrl+Up is its history); `TranscriptView` derives from it. Word wrap is the control's (on); the editors alone take it from the theme file (`AxKitForm.Theme.cs`, TH-6). A line break a key puts into an editable field of several lines is said, "new line" (AX-7.8, 2026-11-11): the text and selection are kept as Enter goes down, compared after a handler that suppressed the key press or after the control's `WM_CHAR` for Enter or Ctrl+Enter (`AxKit.Core.TypedLineBreak`), and the window's `SayTypedLineBreak` announces it unless Options, Text, Say new line is off (`display.sayNewLine` in the theme file, TH-6.5; the item is placed by `CreateTextMenu` in every window and checked from the theme read at the last activation as the Text menu opens). Since AX-7.9 (2026-11-11) `UserMovedLine`: the caret's line before and after a key's handling (`PreProcessMessage` for the window's commands, `WndProc` for the control's own move), raised when the line changed with the text unchanged and nothing selected; `AxKitForm.FollowHeadings` plays the heading sound from it on a Markdown heading's line (`MarkdownOutline.HeadingLineAt`), once per heading. `TextBoxTests` fails on a plain `TextBox` made in `src`.
- `WindowsOpenWith` (2026-10-24; from axFile's `Shell.OpenWith` on its second use, axPreview's Open with): Windows' "How do you want to open this file?" dialog through `SHOpenWithDialog`, the program chosen running the file and the dialog's own Always setting the default; the reason when Windows refuses.
- `User32` (2026-10-24): the Win32 calls and messages more than one file makes (`SendMessage`, `PostMessage`, the foreground and window-process calls, the key and edit messages), declared once and used through `using static AxKit.Forms.User32;`; a call only one file makes stays declared next to its use.
- `Announcer`: the one UI Automation notification (AX-7.1): "most recent" for the result of the user's own key, "all" for status; false without a handle, so the caller can fall back to a selection. Every window and the notice announce through it.
- `AxKitList` (AX-8.6, 2026-10-24): the list of every app, a `ListBox` with type-to-find and the edge earcon built in.
  - Type-to-find: letters within a second one prefix through `AxKit.Core/TypeAhead`, Shift with a letter backwards from `ModifierKeys`, the edge earcon when nothing starts with it, `e.Handled` so that the list box's own one-letter jump never runs; any other move of the selection starts a new search, `OnSelectedIndexChanged` with `_jumping` set around the search's own move, since axAutomate typed "s", moved, then "b" within the second and searched "sb"; a space never starts a search.
  - The edge earcon for Up or Home on the first item and Down or End on the last (`OnKeyDown`, after the window's `ProcessCmdKey` has had its keys).
  - `UserMovedSelection` (AX-7.9, 2026-11-11): raised when the selection moves while the list handles a key (`PreProcessMessage`, where the form's commands run, and `WndProc` for the list box's own move and type-to-find), never inside `Fill` or `SetLines`; the item apps play the heading sound from it.
  - `Names` when some items are not names, `ResetTypeAhead` for a list filled anew.
  - `SetLines` (2026-10-25; from axMedia's queue and axFile's Actions list, inventory item 7): the lines made again, each changed line rewritten in place while the count is the same (a line the caller names left alone), the whole list otherwise, true when in place.
  - The rename in place (AX-8.7; from axFile on its second use, axTask and axPass, 2026-10-24):
    - `BeginRename` puts a "New name" box over the selected item, Enter hands its text to the window's commit (which calls `EndRename` when it takes it), Escape and leaving the box end it, `ended` tells the window;
    - `Renaming` lets a window's commands leave the box its own keys (Ctrl+Z, in a `When`);
    - the box sets its selection before it takes the focus (a `TextBox` given the focus selects all its text unless a selection was set first), and `EndRename` gives the focus back to the list before hiding the box, or WinForms picks the next control itself.
  - Where it is: in axFile's folder and Actions lists, axGIT's list, axMedia's queue, axProcess's list, the item apps' navigator and axCalc's history; `tests/AxKit.Tests/ListTests` fails on a plain `ListBox` in an app, its exceptions named there (the lists that never take a typed letter).
  - The automation channel's `keys` make no typed character and its `type` no Shift, so the backward search is in the unit tests and the NVDA plans.
- `AxKitCheckBox` (AX-8.8, 2026-10-31): the check box of every app, a `CheckBox` that says "checked" or "not checked" when the user toggles it, on the click alone (Space and the mouse), never for a change the window makes (NVDA said nothing on Space in the consent notice's box); `tests/AxKit.Tests/CheckBoxTests` fails on a plain `CheckBox`. In the notice's consent box, whose check the panel keeps for the same notice shown again after Ctrl+F.
- `ChoiceItems<T>` (AX-6.4, 2026-11-09): a menu of choices of which one is checked, the items made from the choices and re-checked by `Check`; from axFile's Sort by, axProcess's Sort processes by, axClaude's Speak replies, axTerminal's Speak output, axPass's Lock after and axCalc's Angles, each window keeping the click's work and its words.
- `PrivateClipboard` (security audit S-15; docs/axPass/SPEC.md PW-5.4, 2026-10-24): a secret on the clipboard with the marks password managers set (no clipboard history, no cloud clipboard, no clipboard viewers), cleared by the clipboard's sequence number so that a later copy of the user's is left alone; axPass's copies of a password and a user name.
- `WindowAccessibleObject`: every window's accessible object, reporting the client area with the title bar as the window's rectangle, so that NVDA+End finds the status bar (NVDA looks at the bottom-left pixel of the rectangle UI Automation gives, which for a WinForms window lies in the invisible resize border).
- `StatusLayout`: `Pair` makes a window's two status labels (no AccessibleName, no Spring, kept inside the strip as it resizes); `Fit` gives them fixed widths when their texts do not fit (an unexposed label otherwise).
- `BundleKeys` (AX-8.2): the keys that mean the same in every window; `All` feeds the collision test; `Text` spells any key the way a menu shows it ("Ctrl+Shift+S"), so that both windows' menu items read their shortcut text from the tables.
