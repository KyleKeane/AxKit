# AxKit.Forms: the window base, its notices, menus and palette

Part of the notes of `src/AxKit.Forms` (the index is `src/AxKit.Forms/CLAUDE.md`). One bullet per piece.

- `AxKitForm` (AX-6.5): the window base every app's window derives from, one class in partial files, one per section.
  - `AxKitForm.cs`:
    - the hooks a window fills in (listed under "what the window fills in"; `CalcForm` is the smallest example, `TextEditorForm` the editors', `AxClaude.MainForm` the richest);
    - the menus every window has (`CreateWindowMenu`, `CreateClaudeMenu`, `CreateTextMenu`, `CreateGeneralMenu`, `CreateDeveloperMenu`, `CreateHelpMenu`, `CreateExitItem`, `Item`, `Toggle`);
    - `OnShown` (the settings-not-read report, then the update check);
    - `WndProc` (Alt and F10 swallowed while a notice shows, and the release of an Alt held as the window was activated, within 1.5 s, since Alt+F4 on another window left this one's menu bar open, 2026-10-23; a hand-over answered at once and its `TakeHandOver` action posted);
    - `ProcessCmdKey` (text size keys everywhere, the find keys in a notice's text, then nothing else while a notice shows; a key from a `ToolStrip` stays the menu's, AX-6.6; F1, the palette and Ctrl+S (`SaveCommand`); then the window's `ProcessWindowKey` for what must come first, then its command list);
    - the command list (docs/axKit/app-kit.md AK-2; `Command`: a name, a key, what runs, `When` where the key acts, `Mark` for the AI tools):
      - `Add(menu, command)` makes the item and handles the key, `Add(command)` the same for an item the window places itself, the first of `CreateShowInMenu` or one in a context menu, `AddKey` a key with no item;
      - the first command whose key matches and whose `When` holds runs, in registration order;
      - `Commands` for the palette and MCP;
      - `Run` records a command in `Recent` (`AxKit.Core.RecentActions`, docs/axKit/reports.md RP-4.1: the last twenty commands, announcements and notices of the window, for a report; a window whose `RecordsAnnouncements` is false, axPass, axClip and the console windows, records no announcements) and runs it;
    - `After` (the one one-shot timer: an action on the window's thread after some milliseconds, once, never in a window that closed meanwhile; axClaude's settles and axTask's words after a dialog use it, docs/axKit/repairs.json R-17);
    - `Do` (a command's task; an escaped exception becomes a notice, since an exception out of an awaited task would otherwise be unobserved);
    - the window's place (`RestoreWindow`, saved on closing), `SaveSettings`;
    - `ShowSystemDialog` with `DialogShowing` (every Windows dialog goes through it, since a dialog's closing activates the window; the editors and axFile wait on activation while it is set; it puts the focus back on the control that had it when the dialog closes, OK or cancel alike, AX-7.2, 2026-11-09, so no caller selects a control after a dialog; a dialog from a notice's button leaves the notice's focus alone);
    - `ChooseFolder` (the Windows folder picker), `OpenUrl`, `OpenInExplorer` (a folder opened, a file selected; `select: true` selects a folder too; a gone path said as `FolderMissing` or `FileMissing` through `SaidMissing`, AX-9.10, 2026-11-09), `OpenSettingsFile`, `CopyDiagnostics`;
    - `PlaceMenuBar` and `BarMenus` (AX-9.1, B-19, 2026-11-11): every window's bar, Session, Actions, Navigation, Context, Options, then Window, axKit and the window's Help, named here whatever the window called them; an empty Actions, Navigation or Context gets one enabled item saying so (`SayWhenEmpty`); `MenuTests` holds the names and fails on a project with a Help menu that does not call it; `CreateWindowMenu` and `CreateAxKitMenu` are private, so no window places them itself; `ContextFromControl` gives an edit control a context menu that never shows and opens the bar's Context instead (the editors' text, the consoles' transcript and field), one behaviour for Shift+F10, the Applications key and a right click;
    - `OpenBarMenu` (Shift+F10, the Applications key and a right click: the bar's menu with a letter, Context's C in the windows that have one, posted as Alt and the letter once the keys that asked are up, so that NVDA reads its first item; from axFile on its second use, axProcess, 2026-10-24).
  - `AxKitForm.Notices.cs`:
    - `ShowNotice`, `CloseNotice`, `ShowError`, `Fail`, `Failed` (one line said, more shown), `AskText` (a notice with one field: the label, the initial text, the button, a check of the typed text that keeps the notice with its reason, a hidden field for a password; from `ItemForm` on its sixth copy, 2026-11-09), `Announce` (on the notice while one shows, on `AnnounceSource` otherwise; before the window's first activation kept and said half a second after it, since NVDA ignores a window that is not in front; a non-interrupting one within 300 ms of the one before joined to it into one notification, since NVDA drops a notification that reaches it while the one before still waits its turn (both heard by the NVDA pass of 2026-11-01), AX-7.3; not virtual);
    - and the one focus rule:
      - `_focusBeforeNotice` is the innermost focused control when the first notice of a chain opens (`FocusedControl`);
      - `_chaining` is set around a button's action so that a notice the action opens neither remembers the focus again nor calls `OnNoticeOpened` a second time;
      - and the last close gives the focus back to that control when it is still there and visible, to `FocusTarget` otherwise.
  - `AxKitForm.Find.cs`: one Find notice (`FindNotice`) and one last text (`FindText`) behind:
    - `ShowFind(TextBox)` with `FindNext`;
    - `ShowFind(Action<string>)` for a window with a search of its own (the transcripts);
    - `ShowFindInList` with `FindInList` (the next item whose name holds the text, wrapping once; from axFile on its second use, axMedia, 2026-10-22);
    - and `ShowFindInNotice` with `FindInNotice` (Ctrl+F, F3 and Shift+F3 while a notice shows, AX-7.2: the Find notice in the notice's place, then the notice shown again from `Overlay.Shown` with the match selected in `Overlay.Body`).
  - `AxKitForm.Fonts.cs`: `TextFont`, `ApplyTextFont`, `ChangeTextSize`, `UseSystemFont`, `ChooseFont`.
  - `AxKitForm.Updates.cs` (AX-3): `CheckForUpdates` (the state for About, Version set first, then one notice or announcement), the update notice, `InstallUpdate` behind one progress notice, the restart arguments kept for `OnFormClosing`, `KeepWorkingAfterUpdate`. In the Store's copy (`PackageIdentity.IsPackaged`, AX-13.3, 2026-11-08) the check never runs at start, `CreateGeneralMenu` has no Check for updates at start toggle, and a manual check ends in `ShowStoreUpdateNotice` (where the copy stands, Open axKit in the Microsoft Store through `OpenStorePage`, the release page) instead of the update notice; nothing is downloaded.
  - `AxKitForm.Palette.cs` (AX-10): the command palette, below.
  - `AxKitForm.Install.cs` (AX-2.9, 2026-10-24): `InstallProgram`, the Install it now of a missing program's notice:
    - a progress notice saying whether Windows will ask for an administrator's yes;
    - the installer run off the UI thread with a timeout and its output read under it;
    - one install at a time per window (`_installing`, cleared when the installer's process ends, never killed);
    - the PATH read again, the app's own check, then "Git is installed" and the app's next step, or a notice with Try again and the download page;
    - only its own progress notice is closed, and a failure while another notice shows is announced;
    - for a program with a `ProgramFile` (KeePassXC), the user's Run key read before and after (`ProgramInstall.SignInEntries`, never written): a sign-in entry the installer added makes the end a notice, "KeePassXC is installed", with `SignInNotice` (what happened, where to turn it off), and the app's next step runs when it closes (2026-11-14).
  - `AxKitForm.Consent.cs` (AX-11.4, AX-11.5, 2026-10-29): `HasConsent`, the one check before an access layer connects to a program or Install it now installs one (true goes on; false has shown the reminder, whose Connect or Install records the agreement, in `consent.json` and for the window's session when the file cannot be written, and runs the caller again); `ConsentNotice` (the reminder, the program's work, its terms with their address or that none is known, the check box, Connect and Not now); `ConsentBox`, the check box's sentence, shared with the AI tools' pairing notice (`AxKitForm.Mcp.cs`, whose Add axKit to Claude Code asks the Claude Code agreement first too).
  - `AxKitForm.Report.cs` (docs/axKit/reports.md, 2026-11-07): `ShowReport` (F4 from `ProcessCmdKey` and the Help menu's Send a report…: the notice "Report to axKit" with `ReportControls` as its custom control, the window's context gathered and redacted first: `AppLine` with Windows, NVDA's version from its process and the window's title, `FocusDescription`, the control's name and place and never its text, `Recent.Lines`, `Log.Tail`), `SaveReport` (the item written before anything is sent), `SendReports` (no token in this build: the cannot-send notice; the consent once, under the app name "axKit"; then `SendSaved`, the sender off the UI thread through `Do` and the outcome said, "Sent as issue N", or shown: `ShowCannotSend` with Copy report and Open GitHub's form for a build without the token and a revoked token, a plain notice for a blocked install), `KeepDraft` (Escape with words typed), `OpenReports` (Your reports: the list made, the unsent sent first when the user has agreed, and axTask started on it).
- `ReportControls` (reports.md RP-3, 2026-11-07): the report notice's fields in Tab order, each named as an instruction: the words (Enter presses the default button, Shift+Enter a line break), the kind as an `AxKitList` NVDA reads itself, the app line read-only, the actions, where the focus was, the log lines and the title filled from the first line typed; `Ready` says "Type a few words first" with the edge earcon; `ToReport`.
- The menus every window has are the base's too (since 2026-10-18): `CreateTextMenu` (the window's own items, a separator, then Font…, Larger text, Smaller text, Windows text size), `CreateGeneralMenu` (Check for updates at start, the window's own, then the AI tools' two, `AxKitForm.Mcp.cs`), `CreateDeveloperMenu` (Open settings file, the window's own, Copy diagnostics) and `CreateHelpMenu` (Keyboard shortcuts, User guide, a submenu of pages); `Toggle` makes a checked item for a setting that saves on each flip. A window builds its own menus (Session, Actions, Navigation, …, named on the bar by `PlaceMenuBar`) and keeps the shared order: in Options its own submenus first (axClaude's Sounds, Speech, When Claude is done, Questions), then Text, General and Developer; the Window, axKit and Help menus last (AX-9.1), each from the base.
- `OverlayPanel` and the records `Notice`, `OverlayChoice`, `OverlayInput`: a window's own dialogs drawn inside the window in place of its main controls (axClaude D23, bundle AX-7.2).
  - The window shows one with `Populate`, which adds the key line made from the buttons ("Enter: Save. Escape: Cancel.", the whole text when the notice has none), sets its `AcceptButton` and `CancelButton` to `DefaultButton` and `CancelButton`, calls `FocusStart`, hides its other controls and disables its menu, and swallows its own shortcuts while the notice shows; `Chosen` tells it which button was pressed.
  - The text and the Custom arguments field have the bundle's page and paragraph keys (`EditKeys`).
  - An `OverlayInput` may carry a `KeyHook`, asked about each key in the field first (axFile's path completion, 2026-10-22), with `InputCaret` and `SetInputText` for the window.
  - A `Notice` with `Progress` shows a progress bar under the text, moved with `SetProgress`; NVDA reports it by its own settings.
  - A `Notice` with `Consent` (AX-11.4, 2026-10-29) shows an `AxKitCheckBox` with that sentence as its name between the text and the buttons; the default button and a `NeedsConsent` choice say "Check the box first" until it is checked; the check is kept, by the sentence, for the same notice shown again after Ctrl+F in it, and forgotten when the notice is answered.
  - A `Notice` may carry a control of the window's own under the text (`Custom`, with `Accepts` asked before the default button acts and `HeadLine`, a first line the window changes through `SetHeadLine`; `PressDefault` for the control's Enter):
    - the New session controls of axClaude and axTerminal are `SessionControls` with `SessionPreset`, in their own file since 2026-10-23, each app giving it its own wording, its folder picker and its announcer (they sat in the panel because it moved whole from axClaude).
  - The text moves by Markdown structure through `AxKit.Core.MarkdownOutline` with the pairs in `Jumps`, the bundle's heading letters (`TextJump.HeadingLetters`) unless the window sets more, announcing on the notice (AX-7.2).
  - `Shown` is the notice on view and `Body` its text, so that the window base's find can put the Find notice in its place and bring it back with the match selected (`HasSearchableText`: a text without a field or a control of the window's own).
- `CommandPalette` (AX-10, 2026-10-22; the one source of every reader since 2026-11-13, docs/axKit/app-kit.md AK-2.5):
  - `Entries` reads the menu bar into `MenuEntry` records (the item, its name, its menus, its key, checked), which the palette (`Commands`) and the AI tools (`AxKitForm.ToolEntries`, for `axkit_window_commands` and `axkit_window_run`) both take; `Marked` gives an item its mark where it is made and `MarkOf` reads it (act when none was given, so the AI tools ask); `NeverForAiTools` withholds a menu and everything under it from the AI tools (AK-2.6, exception 3: the AI tools' submenu, AI help's switch and folders); `CommandMarkTests` keeps the number of unmarked items from growing.
  - `Commands` reads the window's menu bar into `AxKit.Core.PaletteEntry` lines (every enabled, available leaf item under a bar item, its name from `MenuText.Plain`, the menus as its path, the key from `ShortcutKeyDisplayString`, "checked"), each running the item's `PerformClick` and saying a `CheckOnClick` item's new state.
  - A submenu filled as it opens is `RefreshedOnOpening(menu, fill)` where its filling is attached, so that every reader fills it first (Open recent, the Window menu's lists); one too slow to fill for every reading is `NoEntry` (axFile's Drives, the Open with submenus), left out of the entries with everything under it, as is the one line that says a list is empty. **A new self-filling submenu is one of the two**, or the palette lists it empty or with last time's items.
  - `RefreshedOnOpening(menu, refresh)` attaches a refresh that changes items as the menu opens (axFile's Undo text, axTerminal's checked shell) and marks the menu so that `Commands` runs it before reading (2026-10-23).
  - The palette's flow is the window base's (`ShowCommandPalette` from `BundleKeys.CommandPalette` in `ProcessCmdKey` after the menu-mode check, and Help → Command palette, the first item `CreateHelpMenu` places):
    - a notice whose `OverlayInput` has `Changed` and `ListName`, so that `OverlayPanel` shows `_matches`, a list that never takes the focus, under the field (`SetMatches`, `MatchIndex`, `SelectMatch`, `MatchPage`);
    - the field's `KeyHook` moves through the matches;
    - the 300 ms `_paletteSpeak` timer says the first match;
    - Run is a `StaysOpen` choice that closes the notice itself and posts the entry's action, so that the focus is back where it was (the notice rule) before the command runs.
  - A window adds entries of its own through `PaletteEntries` (axFile's folder entries).
- `RecentMenu` (AX-9.5): `Fill` for every "Open recent …" submenu: the paths that still exist (asked of a path on a local drive only, `AxKit.Core.LocalPaths`, since a share could stall the menu; 2026-10-23) as "1. name (path)" with the number as the mnemonic, or one enabled item saying there are none (`NoneWhenEmpty`, which the Window menu's lists use too); `FillFolders` for a list of folders (Directory.Exists and `AxKit.Core.PathName.Of` filled in).
- `ThemePainter` with `ThemeMark` (docs/axKit/theme.md TH-2, TH-3; 2026-11-09): one walk over a control tree, each
  control's class from its type (`TranscriptView`, `TextBox`, `ListBox`, `Button`, `MenuStrip`, `StatusStrip`, a label
  or a surface) or from its `ThemeMark` (`Mark`: the console field and its band, axMedia's video surface as `fixed`),
  each class painted from the theme or, for `system` and for no theme, with its default, which is what the windows had
  before (the console tints live here). The caption through `DwmSetWindowAttribute`. `AxKitForm.Theme.cs` reads the
  file in the constructor (so that a window's own constructor can take a display setting from it) and on activation
  when it changed, paints the window in `OnLoad`, each notice as it opens and a control area's new controls, and holds
  axKit menu, Theme (Edit theme file, Reload theme, Theme on), the one place the theme speaks; and the display
  settings (TH-6): `WordWrapPreference`, `SetWordWrapPreference` (written into the file, read back) and the virtual
  `OnThemeChanged` after every re-read, which `TextEditorForm` overrides to follow the file's word wrap.
- The lists of apps (AX-9.2, AX-9.10, 2026-10-24): every one is made from `AxKit.Core/Dispatch.Apps`, never typed: `WindowMenu.AddApps` (the apps in order, a separator between groups) for New window and axFile's Open in axKit; `AxKitForm.CreateShowInMenu` for every Show current folder or file in submenu (its `missing` word said for a gone path, nothing started); `AxKitForm.PathInHand` for Recently closed, which the base fills as a window closes (empty for an app that holds no path, the default).
- `WindowMenu` (AX-9.1; `AxKitMenu` until 5.7.0, when the bundle's menus became Window, axKit and Help by intent): a `ToolStripMenuItem` every window puts after its own menus, made by the base's `CreateWindowMenu` (`new WindowMenu(this)`). The axKit menu is `CreateAxKitMenu` (Claude from `AxKitForm.CreateClaudeMenu` in AxKitForm.Ai.cs, AI tools, Theme) and Help is `CreateHelpMenu` (the palette, F1, the guide, the app's pages, the reports, the update items and About from `AxKit.Core.BundleAbout`); every bar is put together by `PlaceMenuBar` (AX-9.1, 2026-11-11).
  - Its items: New window with one item per app (`Dispatch.Apps`; a new process of this program file with the app's verb), Open windows, Recently closed (`AxKit.Core.RecentlyClosed`, started the same way with the path) and Close all windows. Open windows by type was here until 5.6.0.
  - The lists are refilled on `DropDownOpening` from `EnumWindows` (the visible, unowned, titled top-level windows of the processes with this one's name; Z order is recency), the current window checked.
  - In an empty list one enabled item that says what is missing ("No other open windows") and does nothing: WinForms skips disabled items when the keyboard moves through a menu, so a submenu of only a disabled "(none)" opened with nothing selected and NVDA read nothing (the user hit this; the apps' Recent lists follow the same rule).
  - A window item restores a minimized window and calls `SetForegroundWindow`, which Windows allows because the user's key in the foreground window asked for it.
  - Close all windows posts `WM_SYSCOMMAND` `SC_CLOSE` to every other axKit window and then to this one, so each closes as on Alt+F4 and asks its own question where it would.
  - The lists and labels are `AxKit.Core.AxKitWindows`, tested.
- `AppMessage` and `HandOver` (docs/axMedia/SPEC.md AM-1.3, AM-D4; docs/axPreview/SPEC.md AP-1.2; 2026-10-22): the hand-over between a starting process and the open window of the same app, for the apps that keep one window (axMedia, axPreview). `Send(appName, verb, paths)` finds the app's newest window through `WindowMenu.OpenWindows` and `AxKitWindows.Of`, sends one `WM_COPYDATA` with the text (`Format`: the verb, then one path per line; a signature in `dwData` so that other programs' messages are ignored) through `SendMessageTimeoutW` with five seconds and abort-if-hung, first granting the window's process the right to bring itself to the front (`AllowSetForegroundWindow`) for the verbs that take the focus (`TakesFocus`: everything but `add`; the window calls `WindowMenu.Activate` on itself once the paths are applied, so that NVDA reads the new content), and returns true when the window answered 1, so that the starting process ends without a window; `Receive(ref m)` in the window's `WndProc` gives the `HandOver` back (null for any other message), and the window sets `m.Result` to 1. The verbs are constants here (`Play`, `Add`, `Open`, `Show`). `SendTo(window, …)` hands over to a window the caller found itself: axStart's is hidden, so `OpenWindows` (visible windows only) never lists it, and axStart finds it by title and program (docs/axStart/SPEC.md AS-1.2). The text form is tested in `tests/AxKit.Tests` (`AppMessageTests`).
- `AppHost` (AX-1.7): every app's entry point: `Run(name, logName, usage, args, window)` sets up the log and the crash handling (the report as a notice in the open `AxKitForm`, or a message box without one), logs the start and the exit, answers `--help` and `--version`, and runs the window the function makes from the remaining arguments; `OnePath` reads an app's one file or folder and reports anything else; `FirstInstance` is the one process of a background app (the mutex of `AppPaths.OneAtATime`, kept for the life of the process; axStart, axClip and axHelp each held a copy until 2026-11-13); `BadCommandLine` logs and shows a message box, the only kind the bundle allows, since no window exists yet. Gotchas of the window live in the axDown notes and in the window's comments (the Ctrl+H/I/J/M guard, the word wrap handle recreation, the notice state flag).
