# AxKit.Forms: the window base

Part of the notes of `src/AxKit.Forms` (the index is `src/AxKit.Forms/CLAUDE.md`). One bullet per piece.

- `AxKitForm` (AX-6.5): the window base every app's window derives from, one class in partial files, one per section.
  - `AxKitForm.cs`:
    - the hooks a window fills in (listed under "what the window fills in"; `CalcForm` is the smallest example, `TextEditorForm` the editors', `AxClaude.MainForm` the richest);
    - the menus every window has (`CreateWindowMenu`, `CreateClaudeMenu`, `CreateTextMenu`, `CreateGeneralMenu`, `CreateDeveloperMenu`, `CreateHelpMenu`, `CreateExitItem`, `Item`, `Toggle`);
    - `SetTitle` (AX-7.1a, AX-9.6, the maintainer's word of 2026-11-26): every window's one title rule, an `Opened` (what is open: its name, and its full path) given to `AxKitWindows.Title`, "notes.md, axDown, C:\work\notes.md", null for the app's name alone; `AppName` is the name in it, never `AppTitle` with its keyword; the item window passes its level's `Opened` from `ReadLevel`, the editors the file with the unsaved star before the path; axTerminal adds its shell, axHelp's conversation and the hotkey windows keep a title of their own;
    - `OnShown` (the settings-not-read report, then the update check);
    - `WndProc` (Alt and F10 swallowed while a notice shows, and the release of an Alt held as the window was activated, within 1.5 s, since Alt+F4 on another window left this one's menu bar open, 2026-10-23; a hand-over answered at once and its `TakeHandOver` action posted);
    - `SayStatus` (AX-7.10, 2026-11-15: F9 since 2026-11-26, `BundleKeys.SayStatus`, and Window, Say the status: the status bar's texts as one interrupting announcement, since NVDA+End said "blank" over a full bar; `StatusTexts` is the one place that reads the labels off the window's status strip, for this, the automation channel's `state` and the AI tools'; `StatusWords` joins them, "No status" for none, tested in `StatusWordsTests`; no window does anything for it);
    - `ProcessCmdKey` (text size keys and F9 everywhere, a notice included, the find keys in a notice's text, then nothing else while a notice shows; a key from a `ToolStrip` stays the menu's, AX-6.6; F1, the palette and Ctrl+S (`SaveCommand`); then the window's `ProcessWindowKey` for what must come first, then its command list; Ctrl+Enter, `BundleKeys.MainAction`, AX-8.10 rule 3: while a notice shows it is `OverlayPanel.PressMain`, otherwise a window's command on that key where it has a main action, and the edge sound when no command took it, so that it never reaches a control);
    - the command list (docs/axKit/app-kit.md AK-2; `Command`: a name, a key, what runs, `When` where the key acts, `Mark` for the AI tools):
      - `Add(menu, command)` makes the item and handles the key, `Add(command)` the same for an item the window places itself, the first of `CreateShowInMenu` or one in a context menu, `AddKey` a key with no item (`KeyTaken`, AK-2.4);
      - the first command whose key matches and whose `When` holds runs, in registration order;
      - `Commands` for the palette and MCP;
      - `Run` records a command in `Recent` (`AxKit.Core.RecentActions`, docs/axKit/reports.md RP-4.1: the last twenty commands, announcements and notices of the window, for a report; a window whose `RecordsAnnouncements` is false, axPass, axClip and the console windows, records no announcements) and runs it; every other menu item is recorded as it is picked, whoever picks it, by `WritePick` (called from the menu's `ItemClicked`, which `CommandPalette.Marked` hooks, before the item's own click; `_commandItems` keeps a command's item from being written twice), and the keys of the whole window by `WriteKey`, each written by its name through `RecentActions.CommandText` (2026-11-25, command-language.md section 8 (a) 3);
    - `SayAtStart` with `StartNote` (a sentence about the start, said once the window shows without interrupting, a system line in the console windows: a remembered path on the network that was not opened, AX-9.5a, R-64);
    - `After` (the one one-shot timer: an action on the window's thread after some milliseconds, once, never in a window that closed meanwhile; axClaude's settles and axTask's words after a dialog use it, docs/axKit/repairs.json R-17);
    - `Do` (a command's task; an escaped exception becomes a notice, since an exception out of an awaited task would otherwise be unobserved);
    - the window's place (`RestoreWindow`, saved on closing), `SaveSettings` (a file that cannot be written is logged and said once in a run through `SettingsNotSaved`, a notice, or a system line in the console windows; the sentence is `SettingsFile.NotWrittenOnce`; AX-5.9, R-63);
    - `ShowSystemDialog` with `DialogShowing` (every Windows dialog goes through it, since a dialog's closing activates the window; the editors and axFile wait on activation while it is set; it puts the focus back on the control that had it when the dialog closes, OK or cancel alike, AX-7.2, 2026-11-09, so no caller selects a control after a dialog; a dialog from a notice's button leaves the notice's focus alone), and `InModalLoop`, which every modal loop of a window runs through (`ShowSystemDialog` itself, the shell's Open with and Properties, the shell's menu, the native popup of a form field's templates): from the loop's start, and for the rest of the key's handling, no key of the user's is being handled (`UserKeyMoment`, which the key dispatch's `ProcessCmdKey` sets with `Handle` and the loop clears with `ModalLoop`), so a notice the command shows after the dialog holds its keys (the sixth review of 2026-11-27, F3: Save as, then "Save as UTF-8?"; `ModalLoopTests` reads every source for a loop outside it);
    - `ChooseFolder` (the Windows folder picker), `OpenUrl`, `OpenInExplorer` (a folder opened, a file selected; `select: true` selects a folder too; a gone path said as `FolderMissing` or `FileMissing` through `SaidMissing`, AX-9.10, 2026-11-09), `OpenSettingsFile`, `CopyDiagnostics`;
    - `PlaceMenuBar` and `BarMenus` (AX-9.1, B-19, 2026-11-11): every window's bar, Session, Actions, Navigation, Context, Options, then Window, axKit and the window's Help, named here whatever the window called them; an empty Actions, Navigation or Context gets one enabled item saying so (`SayWhenEmpty`); `MenuTests` holds the names and fails on a project with a Help menu that does not call it; `CreateWindowMenu` and `CreateAxKitMenu` are private, so no window places them itself, and `AddBundleOptions` ends every Options with the settings of all of axKit after a separator (2026-11-26: the theme, the sounds folder, the app keys file, the update check at start, the log of events, from the axKit menu); `ContextFromControl` gives an edit control a context menu that never shows and opens the bar's Context instead (the editors' text, the consoles' transcript and field), one behaviour for Shift+F10, the Applications key and a right click;
    - `OpenBarMenu` (Shift+F10, the Applications key and a right click: the bar's menu with a letter, Context's C in the windows that have one, posted as Alt and the letter once the keys that asked are up, so that NVDA reads its first item; from axFile on its second use, axProcess, 2026-10-24).
  - `AxKitForm.Notices.cs`:
    - `ShowNotice`, `CloseNotice`, `ShowError`, `Fail`, `Failed` (one line said, more shown), `AskText` (a notice with one field: the label, the initial text, the button, a check of the typed text that keeps the notice with its reason, a hidden field for a password; from `ItemForm` on its sixth copy, 2026-11-09), `Announce` (on the notice while one shows, on `AnnounceSource` otherwise; before the window's first activation kept and said half a second after it, since NVDA ignores a window that is not in front; a non-interrupting one within 300 ms of the one before joined to it into one notification, since NVDA drops a notification that reaches it while the one before still waits its turn (both heard by the NVDA pass of 2026-11-01), AX-7.3; not virtual);
    - and the one focus rule:
      - `_focusBeforeNotice` is the innermost focused control when the first notice of a chain opens (`FocusedControl`);
      - `_chaining` is set around a button's action so that a notice the action opens neither remembers the focus again nor calls `OnNoticeOpened` a second time;
      - and the last close gives the focus back to that control when it is still there and visible, to `FocusTarget` otherwise.
  - `AxKitForm.Find.cs`: one Find notice (`FindNotice`) and one last text (`FindText`) behind:
    - `ShowFind(TextBox)` with `FindNext`;
    - `ShowFind(Action<string>)` for a window with a search of its own (the transcripts);
    - `ShowFindInList` with `FindInList` (the next item whose name holds the text, wrapping once; from axFile on its second use, axMedia, 2026-10-22);
    - and `ShowFindInNotice` with `FindInNotice` (Ctrl+F, F3 and Shift+F3 while a notice shows, AX-7.2: the Find notice in the notice's place, then the notice shown again from `Overlay.Shown` with the match selected in `Overlay.Body`).
  - `AxKitForm.KeyTest.cs` (AX-8.12, 2026-11-15): Help, Diagnostics, Test a key, in every window.
    - `StartKeyTest` adds `KeyTestFilter`, a message filter that takes every keyboard message for the window or a control in it ahead of `ProcessCmdKey`, the menus and the controls, so nothing is carried out; `EndKeyTest` removes it and says "Key test ended" (Escape, `OnDeactivate`, the window hidden, `ShowNotice`, closing).
    - Each press once (the repeat bit) goes to `KeyTestSession` and `KeyTest.Describe`, both pure in `AxKit.Core/KeyTest.cs` and tested in `KeyTestTests`: Escape ending it at once and never named, a modifier alone on its release, the line "F9: Say the status".
    - The window gives them the keys by name: the base's own bundle keys (`HandledByTheBase`), the command list with each `When` asked at the press, the keys the menus show (read once at the start, since reading fills the lists), the bar's letters, the focused control's kind.
    - `KeyTestOwn` is the hook for a key a control handles itself outside the command list (`ConsoleForm`: the transcript's quick keys, the field's Enter); without it such a key is "no command of this window", the honest default. A new control-level key of a window belongs in its command list or in that hook.
    - The automation channel's posted keys pass the same filter, after the channel's own, which set their modifiers; `McpChangeRefusal` refuses an AI tool's run meanwhile (`KeyTest.AiToolsRefusal`).
  - `AxKitForm.Fonts.cs`: `TextFont`, `ApplyTextFont`, `ChangeTextSize`, `UseSystemFont`, `ChooseFont`.
  - `AxKitForm.Updates.cs` (AX-3): the Help menu's two update items and the window's members (`CheckForUpdates`, `RestartPending`, `ClosingForUpdate`, `KeepWorkingAfterUpdate`), each one line onto `UpdateFlow`, the service the window holds (below, "The services"); `EnableUpdateItems`, `ShowUpdateItem` and the three forwarders of the app's hooks (`NoteUpdate`, `RestartText`, `ArgumentsForRestart`) are what the flow asks of the window. `UpdateFlow` holds the release the last check found, the busy flag and the restart arguments kept for `OnFormClosing`: `CheckForUpdates` (the state for About, Version set first, then one notice or announcement), the update notice, `InstallUpdate` behind one progress notice. In the Store's copy (`PackageIdentity.IsPackaged`, AX-13.3, 2026-11-08) the check never runs at start, `CreateGeneralMenu` has no Check for updates at start toggle, and a manual check ends in `ShowStoreUpdateNotice` (where the copy stands, Open axKit in the Microsoft Store through `OpenStorePage`, the release page) instead of the update notice; nothing is downloaded.
  - `AxKitForm.Palette.cs` (AX-10): the command palette, below.
  - `AxKitForm.Templates.cs` (docs/axTemplate/SPEC.md TP-5; from the editor shell on its second use, 2026-11-23): Actions, Insert template, `CreateInsertTemplateMenu(own, insert)`: a window's own templates, then axTemplate's checked for the app or for every axKit app, read off the UI thread at the start and on each activation. A window with a field to write in names it in `TemplateField` (the conversation windows: their `Input`), and `PlaceMenuBar` adds the menu at the end of its Actions; the editor shell makes its own menu with its undo step. In a form (TP-5.5, 2026-11-24), `ShowForm` calls `OfferTemplatesInForm`: in an app of `TemplateStore.AppsWithField`, each text field that is neither only read nor a password gets a `ContextMenuStrip` of the templates (`FillFieldTemplates`, filled at each opening), since a notice offers no command of the bar; `InsertInto` puts one in, as for `TemplateField`.
  - `AxKitForm.Install.cs` (AX-2.9, 2026-10-24): `InstallProgram`, the Install it now of a missing program's notice, one line onto `ProgramInstaller`, which does the work:
    - a progress notice saying whether Windows will ask for an administrator's yes;
    - the installer run off the UI thread with a timeout and its output read under it;
    - one install at a time per window (`_installing`, cleared when the installer's process ends, never killed);
    - the PATH read again, the app's own check, then "Git is installed" and the app's next step, or a notice with Try again and the download page;
    - only its own progress notice is closed, and a failure while another notice shows is announced;
    - for a program with a `ProgramFile` (KeePassXC), the user's Run key read before and after (`ProgramInstall.SignInEntries`, never written): a sign-in entry the installer added makes the end a notice, "KeePassXC is installed", with `SignInNotice` (what happened, where to turn it off), and the app's next step runs when it closes (2026-11-14).
  - `AxKitForm.Consent.cs` (AX-11.4, AX-11.5, 2026-10-29): the notice starts with `Consent.Problem`'s sentence when the file's agreements were changed outside axKit and are not used (AX-5.6); `HasConsent`, the one check before an access layer connects to a program or Install it now installs one (true goes on; false has shown the reminder, whose Connect or Install records the agreement, in `consent.json` and for the window's session when the file cannot be written, and runs the caller again); `ConsentNotice` (the reminder, the program's work, its terms with their address or that none is known, the check box, Connect and Not now); `ConsentBox`, the check box's sentence, shared with the AI tools' pairing notice (`AiToolsSetup`, whose Add axKit to Claude Code asks the Claude Code agreement first too).
  - `AxKitForm.Report.cs` (docs/axKit/reports.md, 2026-11-07): the window's two members, `ShowReport` and `OpenReports`, each one line onto `ReportFlow`, and `FocusDescription`, which stays the window's, since AI help's question carries it too. `ReportFlow` keeps nothing between two reports (the Reports list on the disk does): `ShowReport` (F4 from `ProcessCmdKey` and the Help menu's Send a report…: the form "Report to axKit", `ReportControls` shown with `ShowForm`, AX-8.10, the window's context gathered and redacted first: `AppLine` with Windows, NVDA's version from its process and the window's title, `FocusDescription`, the control's name and place and never its text, `Recent.Lines`, `Log.Tail`), `SaveReport` (the item written before anything is sent), `SendReports` (no token in this build: the cannot-send notice; the consent once, under the app name "axKit" and the target `ConsentTarget.GitHubReports`, "GitHub, encrypted reports", so that an agreement to the public issues of 5.1.0 to 5.8.0, target "GitHub", does not count and is taken out when the new one is recorded; then `SendSaved`, the sender off the UI thread through `Do` with `ReportSeal.PublicKey`, so that each report is sealed before it leaves, and the outcome said, "Sent, report N", the number to quote to the maintainer and never called an issue, which the user could not open, or shown: `ShowCannotSend` with Copy report alone, the plain report to the user's own clipboard, for a build without the token and a revoked token, GitHub's own form having gone on 2026-11-14 since it would post into a private repository, `ShowBlockedInstall` for an install the block list names: "Report not sent", the install id in the text, Copy install id, Open the block list page, `ReportSender.BlocklistIssuesUrl` through `OpenUrl`, and Close as Enter's and Escape's choice; a plain notice for a blocked version, which says to update, reports.md RP-6.4). Every text here that says where a report goes says: encrypted on your computer, a private repository on GitHub, only the maintainer can read it (reports.md RP-4.4), `Cancelled` (Escape or Cancel: "Cancelled", nothing kept, RP-D13; a draft was kept until 2026-11-14), `OpenReports` (Your reports: the list made, the unsent sent first when the user has agreed, and axTask started on it).
- The services the window holds (docs/axKit/repairs.json R-15, 2026-11-14): `UpdateFlow`, `ProgramInstaller`, `ReportFlow`, `AiHelpFlow` and `AiToolsSetup` (the last two in `notes/ai-and-automation.md`), each a plain sealed class in its own file, made in `AxKitForm`'s constructor with the window as its one collaborator (as `McpChannel` has it), holding the state that was the base's.
  - A service calls the window's own members as `_form.ShowNotice`, `_form.Announce`, `_form.Do`, `_form.HasConsent`, which are `protected internal` for that; an app sees them as before.
  - A hook an app overrides stays `protected` on the base with its name and signature; a service reaches it through a one-line internal forwarder beside the service's field (`NoteUpdate`, `RestartText`, `ArgumentsForRestart`, `ShowFailure`).
  - The members an app calls (`InstallProgram`, `CheckForUpdates`, `AskClaude`, `ShowReport`) stay on the base, one line each onto the service; menu items and their marks are made on the base as before, so the source tests read the same files.
  - A new service of this kind is added the same way; one whose code reads and sets the window's notice, focus or menus in many places stays a partial file.
- The menus every window has are the base's too (since 2026-10-18): `CreateTextMenu` (the window's own items, a separator, then Font…, Larger text, Smaller text, Windows text size), `CreateGeneralMenu` (Check for updates at start, the window's own, then the AI tools' two, `AxKitForm.Mcp.cs`), `CreateDeveloperMenu` (Open settings file, the window's own) and `CreateHelpMenu` (Keyboard shortcuts, User guide, a submenu of pages, the reports, then `CreateDiagnosticsMenu`: Test a key and Copy diagnostics, AX-9.1, 2026-11-15); `Toggle` makes a checked item for a setting that saves on each flip. A window builds its own menus (Session, Actions, Navigation, …, named on the bar by `PlaceMenuBar`) and keeps the shared order: in Options its own submenus first (axClaude's Sounds, Speech, When Claude is done, Questions), then Text, General and Developer; the Window, axKit and Help menus last (AX-9.1), each from the base.

- `AppHost` (AX-1.7): every app's entry point: `Run(name, logName, usage, args, window)` sets up the log and the crash handling (the report as a notice in the open `AxKitForm`, or a message box without one), logs the start and the exit, answers `--help` and `--version`, and runs the window the function makes from the remaining arguments; `OnePath` reads an app's one file or folder and reports anything else; `FirstInstance` is the one process of a background app (the mutex of `AppPaths.OneAtATime`, kept for the life of the process; axStart, axClip and axHelp each held a copy until 2026-11-13); `BadCommandLine` logs and shows a message box, the only kind the bundle allows, since no window exists yet. Gotchas of the window live in the axDown notes and in the window's comments (the Ctrl+H/I/J/M guard, the word wrap handle recreation, the notice state flag).
- `AppHost.OneCopy` (AX-1.9, R-65, 2026-11-16): the one start of axStart, axClip and axHelp: the mutex (`FirstInstance`), the wait for the first copy's window, the hand-over given as a function that says whether the copy answered (`AppMessage.SendTo`, or `AppMessage.Answers` when there is nothing to hand over), and, when it did not, the one message box whose default is No; Yes ends the processes of this program file started with the app's verb (`ThisProgram.CommandLineOf`, `BackgroundStart.IsCopyOf`) and goes on as the copy. The decision and the words are `AxKit.Core/BackgroundStart`.
- `PutAway` (2026-11-15, docs/axClaude/SPEC.md FR-9.6): a virtual of `AxKitForm`, false but for a window hidden by its own close and running on (axClaude's `--hide-on-close`, axHelp's conversation). While it holds, `Announce` and `AnnounceBefore` drop their text (nothing is kept for later), `McpChannel` answers every request with "This window is hidden" (so the AI tools neither list nor read it), and the automation channel's `activate` leaves it hidden; its `state` carries `visible`. A hotkey window is never put away in this sense: it speaks while hidden; to the AI tools it is hidden all the same, since `McpChannel` answers every request of a window that is not shown with `HiddenWindow` (2026-11-27, MC-6.2), so that no pairing notice or question opens where nobody sees it. `AppMessage.End` closes such a window for good; `AppMessage.Show` brings it up.
- `ReportFlow`, 2026-11-16 (reports.md RP-6.9): it saves through `ReportFiles.Save` with `AppPaths.ReportsWrittenFile`, sends when `UnsentOfTheForm` has any, and ends what it says after a send with `ReportWritten.NotSentSentence` when the outcome counts files the form did not write.
- The places (`AxKitForm.Places.cs`, `Place`; docs/axKit/workflow-graph.md WG-1, 2026-11-26): `Places`, a virtual each kind of window overrides with its table's places and the control that is each (an app appends its own, as `HelpForm` does with `AxHelpPlaces`); `PlaceId` (`axCalc.field`), `PlaceNow` (the place the focus is in, or the one it was last in while a notice or a choice holds it; read from the thread's focus, `FocusNow`, since a window shown without activation has no active control), `OverId` (what stands over the places: `menu`, `dialog` while `DialogShowing`, the notice by its kind with `PaletteTitle` for the palette, `choice` while the focus is inside a `ControlArea`, else `none`), `GoToPlace` and `Unplaced` and `PlacesListing` for the automation channel alone. `AutomationState` carries `place` and `over` between `visible` and `status`, where no script's expectation of neighbouring fields meets them (`"title","notice"` and `"]}` are both expected). Nothing a user hears or presses reads any of it.
