# Workflow: Add a shell of your own
# axTerminal: the user's own shells (AT-1.6a), section 3 of docs/axTerminal/nvda-test-plan.md, the steps on Add a
# shell and Remove a shell. Switch shell needs menu mode, which only the foreground window enters: "menu" runs the
# same items by their palette names ("1. Test cmd (cmd.exe /k)" to switch, "1. Remove Test cmd" to remove).
# The last check has the window refuse shells written into its settings file: that refusal is logged as an error.
allow error were changed outside axKit and are not used
mkdir work\myproject
file home\AxKit\axTerminal.json {"shell": "powershell"}
# The reminders agreed to already (AX-11.5): a user's shell is agreed to by its name and its command line (AT-1.6b).
file home\AxKit\consent.json {"items":[{"app":"axTerminal","target":"Windows PowerShell","version":"0","when":"2026-10-31T00:00:00"},{"app":"axTerminal","target":"Test cmd, command line cmd.exe /k","version":"0","when":"2026-10-31T00:00:00"},{"app":"axTerminal","target":"PowerShell 7","version":"0","when":"2026-10-31T00:00:00"}]}
start terminal {temp}\work\myproject
expect said Ready

# Goal: Add a shell of your own
# Add a shell: one form (bundle AX-8.10), the name then the command line, the focus in the name and the explanation
# said once; a blank or taken name, or a blank command line, is said with the focus in that field, the form kept.
# With none yet, Remove a shell holds one line that says so; it does nothing, so it is no command of the list
# (docs/axKit/app-kit.md AK-2.5: the line that says a list is empty is never an entry).
refuse commands No shells of your own yet
menu Add a shell
expect state "notice":"Add a shell"
expect focus "name":"Type the shell's name"
# The form's sound, its title and the one word (bundle AX-7.11); its explanation is read on F7, not at opening.
expect said ♪ FormOpen
expect said Add a shell, form
refuse said A shell of your own: the name Switch shell and the New session notice show for it
keys f7
expect said ! A shell of your own: the name Switch shell and the New session notice show for it
keys enter
expect said ♪ Edge
expect said Type a name
expect state "notice":"Add a shell"
expect focus "name":"Type the shell's name"
type Command Prompt
keys enter
expect said A shell named Command Prompt is already there
expect focus "name":"Type the shell's name"
keys ctrl+a
type Test cmd
# Enter in a one-line field presses Add: the command line is still empty, so the focus goes there.
keys enter
expect said Type the command line
expect state "notice":"Add a shell"
expect focus "name":"Type the command line that starts it"
type cmd.exe /k
# Tab reaches the buttons after the two fields; Shift+Tab comes back; Ctrl+Enter adds from the field.
keys tab
expect focus Add
keys tab
expect focus Cancel
keys shift+tab shift+tab
expect focus "name":"Type the command line that starts it"
keys ctrl+enter
expect said Added Test cmd
expect state "notice":null
refuse said New session

# Check: A new shell is listed in Switch shell and in Remove a shell
# Listed in Switch shell after the built-in shells, and in Remove a shell.
expect commands 1. Test cmd (cmd.exe /k), Session, Switch shell
expect commands 1. Remove Test cmd, Session, Remove a shell

# Goal: Switch to a shell of your own
# Started from Switch shell: the title and the system line name it; cmd's own output in the terminal.
menu 1. Test cmd
expect said Test cmd
expect state , axTerminal, 
expect state \myproject, Test cmd","notice"
expect commands 1. Test cmd (cmd.exe /k), Session, Switch shell, checked
# Check: The terminal names the shell, and its own output reaches the terminal
do Terminal
expect text "System: Switched to Test cmd in
do Command field
type echo hello-user-shell
keys enter
do Terminal
expect text hello-user-shell
do Command field

# Check: The New session notice lists the shell of your own, selected
# The New session notice lists it after the built-in shells, selected while it is the shell in use.
do New session
expect state "notice":"New session"
keys tab
expect focus folder..."}
keys tab
expect focus "role":"RadioButton"
expect focus "value":"Test cmd"}
keys escape
expect state "notice":null
close

# Check: The shell in use starts again in the next window
# Remembered for the next window: the same shell starts again.
start terminal {temp}\work\myproject
expect state , axTerminal, 
expect state \myproject, Test cmd","notice"
do Terminal
expect text "System: Shell started: Test cmd, command line cmd.exe /k, in
do Command field

# Goal: Remove a shell of your own
# Removed while in use: off both lists, the machine's default shell started in its place in the same folder.
menu 1. Remove Test cmd
expect said Removed Test cmd
expect state , axTerminal, 
refuse state Test cmd","notice"
# With none yet, Remove a shell holds one line that says so; it does nothing, so it is no command of the list
# (docs/axKit/app-kit.md AK-2.5: the line that says a list is empty is never an entry).
refuse commands No shells of your own yet
refuse commands Test cmd
close

# Check: Shells another program wrote into the settings file are not used
# AT-8.1a: the window sealed the file as it saved it; a file written over it without the seal starts the default shell,
# keeps none of its shells, and says so once as a system line.
# The closed window writes its settings as it goes: the file is written over only after that.
wait 2000
file home\AxKit\axTerminal.json {"shell": "custom", "customShell": "cmd.exe /k", "userShells": [{"name": "Planted", "commandLine": "cmd.exe /k"}]}
start terminal {temp}\work\myproject
expect said Ready
refuse state Planted","notice"
refuse state Custom shell","notice"
refuse commands Planted
do Terminal
# The text is matched as the channel writes it, where an apostrophe is escaped: the part after it.
expect text settings were changed outside axKit and are not used. Add them again from Session, Add a shell.
