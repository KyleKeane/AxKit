# Workflow: Have a typed answer wait until Claude's question was said, with Claude Code's screen
# Needs: tools/AxAutomate, which puts its own program in AXKIT_STANDIN for the stand-in of Claude Code; no Claude Code, no network and no model.
# axClaude, docs/axClaude/SPEC.md D33 ("Nothing typed answers a question not yet put to the user", 2026-11-27, found by
# the second review of that day; bundle rule 11). With Claude Code's screen a question is acted on once the screen
# has settled, 400 ms after it came, and while the keys of a typed answer still go out the settle waits for them.
# In that time the message field still stands: a "1" typed there and sent went to Claude Code as the answer to a
# question of which nothing had been said, and a bare Enter went to whatever the screen showed. The window now says
# "Not sent: Claude asks something, and its question opens in a moment" and keeps the text; once the question was
# said ("Claude asks", since this script runs with Answer from a list off), the same Enter sends it.
# The stand-in (tools/AxAutomate/StandIn.cs) draws each question at a file of the script's and acts on no key. Until
# the third review of that day a long answer made that moment six seconds wide, since its keys go out one at a time
# and the settle waited for them, and this script typed its "1" into it. That review found the other half of the
# same moment: the rest of the long answer, and its Enter, went on into the question that had replaced the one it
# was typed for. Each queued key now asks, right before it is written, whether Claude Code still waits on what the
# answer was for (D33, "What is queued is asked about again when it is written"); when not, the keys still waiting
# are dropped, the window says "Not sent", and the user's act ends there, so the new question is said at once.
# What is left of the first rule's moment is the settle's 400 ms, too short for a script to press into: the pure
# rule is held by AnsweredWaitTests (Unheard, StillWaits) and the window's use of it by WindowLastResortTests. The
# last part is the interrupt during such an answer: its keys are dropped, so the user's act ends there, and the
# next question is said at once; until that day the settle went on waiting for keys that were never sent.
