# Workflow: Have a typed answer wait until Claude's question was said, with Claude Code's screen
# Needs: tools/AxAutomate, which puts its own program in AXKIT_STANDIN for the stand-in of Claude Code; no Claude Code, no network and no model.
# axClaude, docs/axClaude/SPEC.md D33 ("Nothing typed answers a question not yet put to the user", 2026-11-27, found by
# the second review of that day; bundle rule 11). With Claude Code's screen a question is acted on once the screen
# has settled, 400 ms after it came, and while the keys of a typed answer still go out the settle waits for them.
# In that time the message field still stands: a "1" typed there and sent went to Claude Code as the answer to a
# question of which nothing had been said, and a bare Enter went to whatever the screen showed. The window now says
# "Not sent: Claude asks something, and its question opens in a moment" and keeps the text; once the question was
# said ("Claude asks", since this script runs with Answer from a list off), the same Enter sends it.
# The stand-in (tools/AxAutomate/StandIn.cs) draws each question at a file of the script's and reads no key. The
# long answer is what makes the moment wide enough to play: its keys go out for six seconds, one at a time, and the
# settle waits for them. The second half is the interrupt during such an answer: its keys are dropped, so the user's
# act ends there, and the next question is said at once; until that day the settle went on waiting for keys that
# were never sent.
