# Workflow: Get an offered command and a message back when Claude Code's prompt row holds a draft
# Needs: tools/AxAutomate, which puts its own program in AXKIT_STANDIN for the stand-in of Claude Code; no Claude Code, no network and no model.
# axClaude, docs/axClaude/SPEC.md D33 ("One message in flight", the sixth review of 2026-11-27, F1 and F2; the eighth of
# 2026-11-28, M-A and M4). A command an AI tool offered goes as a ! line when the user says yes, typed only onto a bare
# prompt row, as a message is. Here Claude Code keeps an earlier message on its row (its Enter dropped): that one stays
# Claude Code's and is said; the line and a message sent behind it wait for a bare row and come back, the message into
# the field, the line written out in the conversation under rule 11's caution, whole, so that nothing is lost and the
# line is never read as axKit's own.
# The stand-in (tools/AxAutomate/StandIn.cs) draws what is typed, drops every Enter ("dropEnters") and writes every key
# it reads to a file ("keys"); the runner is the AI tool.
file home\AxKit\axClaude.json {"replySpeech":"none","interruptForQuestions":true,"workingMusic":false,"backgroundAlert":false}
file home\AxKit\consent.json {"items":[{"app":"axClaude","target":"Claude Code","version":"0","when":"2026-10-31T00:00:00"}]}
mkdir ol
file claude.cmd @"%AXKIT_STANDIN%" standin "%~dp0scenario.json" %*
file scenario.json {"version":"2.1.332 (stand-in)","dropEnters":99,"keys":"keys.txt","steps":[{"frame":["claude: started","auto mode on (shift+tab to cycle)","$"],"clear":true},{"idle":true}]}
file expected.txt first message<Enter>\n<Enter>\n
start claude {temp}\ol --claude {temp}\claude.cmd -- --model haiku --effort low
expect said Ready
expect focus "name":"Message to Claude"

# The access on and the runner paired, as in mcp\01-read-and-pair.
menu Let AI tools read and open axKit
expect state "notice":"Turn on AI tools?"
wait 1100
keys enter
expect said AI tools on
try said Not in a test run
mcp start
mcp call axkit_windows
expect state "notice":"axAutomate asks to use axKit"
wait 1500
keys tab
expect focus I understand
keys space
expect said ! checked
keys tab
expect focus &Allow
keys enter
expect said axAutomate may read axKit
expect mcp "app": "axClaude"

# Check: An offered command and a message behind it are never typed onto a row that holds a draft
# The first message's Enter is dropped twice and its draft said. The offered line waits for a bare row, the message
# behind it too, and both come back.
do Message field
type first message
# The field holds its Enter for a moment after the focus came to it (bundle AX-6.4).
wait 1100
keys enter
expect said Sent
expect said Claude's prompt row still shows a draft after your Enter
mcp call axkit_offer_command {"window":"{window}","command":"echo offered"}
expect mcp "offered": true
expect focus 1. Explain this command
wait 1500
keys down
expect focus 2. Yes, run it
keys enter
expect focus "name":"Message to Claude"
# The field the list gave the focus back to holds its Enter for a moment (bundle AX-6.4); the line waits meanwhile.
type a message
wait 1100
keys enter
expect said Not sent: Claude's prompt row holds other text; your message is back in the message field; the one after it was not typed either
expect focus "name":"Message to Claude"
expect text a message
run fc /b ol\keys.txt expected.txt

# Check: The offered command that did not go is written out in the conversation under the AI caution
do Conversation
expect text Not sent: Claude's prompt row holds other text, so the line was not typed. The Send key menu can empty the row. Your message is back in the message field. The message sent after it was not typed either. Not put into the field: a line with a command axAutomate, an AI model, offered: axAutomate wrote the command, it can be wrong, and axKit has checked none of it. A command can be offered because axAutomate's own permission or safety checks refused it, so read every detail before you run it; running it is your own choice: ! echo offered.
expect text # Input 1
