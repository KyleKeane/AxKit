# Workflow: Hear that Claude Code keeps a message on its prompt row, and send it from there
# Needs: tools/AxAutomate, which puts its own program in AXKIT_STANDIN for the stand-in of Claude Code; no Claude Code, no network and no model.
# axClaude, docs/axClaude/SPEC.md D33 ("One message in flight", the sixth review of 2026-11-27, F1, and the eighth of
# 2026-11-28, M-A). Claude Code drops an Enter in its first seconds and leaves the message on its prompt row. Until the
# sixth review a second message sent within a second and a half was typed onto the same row, after the first. Until
# the eighth the first came back into the field when the row still held it three seconds after its Enter, a guess that
# sent a message Claude Code had taken a second time. Now a message whose Enter went is Claude Code's: the Enter goes
# once more after a second and a half, and when the row still shows a draft three seconds after the Enter that is
# said once, and the user decides: Enter in the empty field sends the draft. The next message is typed only onto a
# bare row: it waits, and comes back.
# The stand-in (tools/AxAutomate/StandIn.cs) draws what is typed, drops the first two Enters ("dropEnters") and writes
# every key it reads to a file ("keys"), which the script compares with what it expects.
file home\AxKit\axClaude.json {"replySpeech":"none","interruptForQuestions":true,"workingMusic":false,"backgroundAlert":false}
file home\AxKit\consent.json {"items":[{"app":"axClaude","target":"Claude Code","version":"0","when":"2026-10-31T00:00:00"}]}
mkdir nt
file claude.cmd @"%AXKIT_STANDIN%" standin "%~dp0scenario.json" %*
file scenario.json {"version":"2.1.332 (stand-in)","dropEnters":2,"keys":"keys.txt","steps":[{"frame":["claude: started","auto mode on (shift+tab to cycle)","$"],"clear":true},{"idle":true}]}
file expected1.txt first message<Enter>\n<Enter>\n
file expected2.txt first message<Enter>\n<Enter>\n<Enter>\n
start claude {temp}\nt --claude {temp}\claude.cmd -- --model haiku --effort low
expect said Ready
wait 1000

# Check: A message Claude Code keeps on its row is said, never given back, and the next is never typed onto it
# The first message's Enter goes and is dropped, and once more. Three seconds after the first Enter the draft on the
# row is said; the second message waits for a bare row three seconds more and comes back into the field.
type first message
keys enter
expect said Sent
type second message
keys enter
expect said Claude's prompt row still shows a draft after your Enter: Enter in the empty field sends it, the Send key menu can clear it
expect said Not sent: Claude's prompt row holds other text; the message is back in the message field
expect focus "name":"Message to Claude"
expect text second message
run fc /b nt\keys.txt expected1.txt

# Goal: Send the draft Claude Code kept
# Enter in the empty field sends the draft on Claude Code's row.
keys ctrl+a
keys delete
keys enter
wait 1000
run fc /b nt\keys.txt expected2.txt

# Check: The message Claude Code kept stays in the conversation, which says it was not taken yet
do Conversation
expect text # Input 1
expect text Claude Code had not taken this yet when axClaude last looked.
refuse text # Input 2
