# Security

## Reporting a problem

Please report a security problem privately, through GitHub: [report a vulnerability](https://github.com/KyleKeane/AxKit/security/advisories/new). Do not open a public issue for it. Say which app and version, what an attacker could do, and how to reproduce it; leave out personal data.

You will get an answer as soon as the maintainer can give one. A fix goes out as a new release, which installed copies offer through Check for updates, and the advisory is published with it.

## Supported versions

Only the latest release is supported. Installed copies check for it themselves (axKit menu, Check for updates), so updating is one notice away; a copy from the Microsoft Store is updated by the Store itself.

## What axKit does that matters here

- The update check asks GitHub for the latest release of this repository and, when the user agrees, downloads and installs it for the user only, without administrator rights. It is the only network call a window makes on its own, and it can be turned off (Options, General); the updater takes a download only from this repository's release address, checked against GitHub's digest and the release key's signature. The one other network request of axKit's own code is a report the user sends (F4; `docs/axKit/reports.md`): posted to GitHub as a public issue of the reports repository `KyleKeane/AxKit-reports`, as a reporter account of the maintainer's whose token ships in the release build and can reach that repository's issues alone; the token is revoked and replaced at a release when it is abused, every report names its install by a random id, and a blocklist in that repository stops a blocked install or version from sending. The access layers (axClaude, axGIT, axTerminal, axPass) start Claude Code, git, the user's shell and KeePassXC's tool as child processes and talk to them through a pseudo console or pipes; those programs use the network as they would without axKit, on the user's command. Everything axKit contacts, and when, is [PRIVACY.md](PRIVACY.md); [docs/axKit/outside-calls.md](docs/axKit/outside-calls.md) lists every such call in the code, by what it reaches, with its file, line and purpose, written from the sources on every push and every release.
- Releases are built by GitHub Actions from this repository with GitHub's build attestation, and approved by the maintainer before they are published ([GOVERNANCE.md](GOVERNANCE.md)). The GitHub release's `AxKit.exe` carries no Windows (Authenticode) signature, and every release's notes say so; Windows' Smart App Control may refuse it, and an update it refuses stops without changing anything. The signed copy is the Microsoft Store's: an MSIX package the Store signs with Microsoft's certificate after its certification, installs and updates; that copy has no updater of its own, runs every program it starts (Claude Code, the shells, git, KeePassXC's tool, the installers) outside the package as Windows does by default, and keeps its own files in the package's private AppData ([docs/axKit/SPEC.md](docs/axKit/SPEC.md) AX-13). A signing service for the GitHub release was set up and retired, unused, in 2026-11 ([docs/axKit/code-signing.md](docs/axKit/code-signing.md)).
- axClaude runs the user's own Claude Code; axTerminal runs the user's own shells; axFile runs the programs the user chooses. None of them run anything the user did not ask for.
- Settings and logs stay in the user's profile (`%APPDATA%\AxKit`, `%LOCALAPPDATA%\AxKit`). Copy diagnostics puts the versions, paths and the log's end on the clipboard, with the account's name, paths, e-mail addresses and ids replaced, for the user to read before sharing.
- Releases are signed with a key that lives only on the maintainer's machine; the apps and `install.cmd` install nothing whose signature does not check (`docs/axKit/SPEC.md` AX-3.4).
- The audit of 2026-10-24 and the review of 3.7.x on 2026-10-25, `docs/axKit/security-audit-2026-10-24.md`, list every finding, what was done about it and what was accepted; the AI tools are specified with their protections in `docs/axKit/mcp.md`, and off until the user turns them on. Running a window's command for a paired AI tool (`axkit_window_run`, MC-7) has a second switch of its own, off by default and sealed with the first, is never offered in axPass or axClip, never while the window asks the user something or while the user types in it, and asks the user before any command that acts outside the window (a program started, a file opened in its program, the clipboard read among them; a test fails on a command without its mark). Turning the access off and Forget AI tools turn it off too.
