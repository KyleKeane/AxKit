# axKit

axKit is the set of tools I use every day as a blind scientist, shared in case they help someone else: personal tools, not a product or a service, with no support and no warranty. It is one Windows program that holds several apps for people who use a screen reader. It is made for NVDA and works with any screen reader that reads ordinary Windows text fields. Each app has its own window, its own Start menu entry, its place in File Explorer's Open with axKit submenu and its own console command, and all of them share this one installation and update together. More apps come as I find another thing worth doing by ear.

The apps come in two kinds. Standalone apps need only Windows and work with the network off:

- **axDown** is a plain editor for Markdown and text files: one file in one window, written back exactly as it was found, with find, go to line, and questions asked inside the window.
- **axJSON** is the same editor for JSON files, with keys that jump from key to key, object to object and array to array, a key that lands on the first mistake, and a Format command that lays the file out and repairs the small things.
- **axFile** is a file manager for one folder: a plain list of its entries, folders first, where Enter opens a folder in the list and a file in the program you have made its default in Windows, as in File Explorer. New folder, new text file, rename, delete to the Recycle Bin, cut, copy and paste, move to a new folder, zip and unzip, copy the path, with Space to select several; every operation is a line of the Actions list under the folder list, to read again, undo (Ctrl+Z) or jump back to (Enter). It opens from the other windows on the folder or file you are in, and hands sound and video to axMedia and reading to axPreview.
- **axMedia** is a player for sound and video files with one queue: Enter on a file in axFile or File Explorer (once axMedia is its default program) plays it with its folder's other files after it; Space pauses, Ctrl+Left and Ctrl+Right seek, Ctrl+Shift+Left and Ctrl+Shift+Right change file, Ctrl+Shift+Comma and Ctrl+Shift+Period change the speed with the pitch kept, Ctrl+Q says what is playing. One window takes everything you open; a video's picture shows at the top of it.
- **axPreview** is a read-only viewer for one text file: the text in a plain field with every reading key axDown has, including the Markdown navigation keys, `l` for the line, Go to line and find; Ctrl+E opens the file in its editor. Shift+Enter in axFile reads a file here; one window takes everything you open.
- **axStart** is a program launcher: Ctrl+Shift+Space from anywhere brings up one search field; type part of a program's name, Down and Up move through the matches while the caret stays in the field, and Enter starts it. It runs in the background from sign-in, with no window until the key.
- **axProcess** shows what runs on the computer as one list with three views: Ctrl+1 the running programs with their memory and processor use ("chrome, 350 MB, 3% CPU, process 9120"), Ctrl+2 the Windows services, Ctrl+3 the programs that start when you sign in. Enter shows an item's details with what can be done to it, Delete ends a process after a question, Ctrl+Q says how busy the computer is; the list changes only when you press F5.
- **axTask** keeps tasks and lists as a folder of small files: Right goes into a list and Left back up, as in axFile; Tab goes to the selected item's fields ("Due, date, 30 October 2026, Friday"), Enter changes one; Space marks a task done; Ctrl+1 is All tasks, every task not done, the soonest due first.
- **axCalc** is a calculator as one field and a history: type an expression such as `1920*1080*4` and press Enter to hear the answer; every answer stays as a line of the history above the field, to read back, copy (Ctrl+Shift+C) or put back in the field (Enter). Ctrl+I says an answer in hexadecimal, binary and octal.
- **axClip** is a clipboard history: it keeps the text of what you copy, in memory unless you turn on Keep history between runs, and leaves out what a password manager marks private. Windows+Alt+V from anywhere brings up one search field over it, newest first; type to narrow it, Down and Up move through it, Enter pastes the item into the program you were in, Shift+Enter only copies it, Ctrl+Q reads it in full, Ctrl+P pauses recording. It runs in the background from sign-in, as axStart does.

Access layers, which work through a program you install (Claude Code, Git, your shell, KeePassXC) that does the real work under its maker's terms; `NOTICE.md` next to the program says what axKit does, what the other program does, and what is yours:

- **axClaude, access layer for Claude Code** runs the Claude Code CLI for you and shows everything Claude says in a plain text window, one line at a time, with a few keys to move around and spoken notices when Claude needs you.
- **axGIT, access layer for Git** is a git manager for one repository: a list of the changed files, the log or the branches, the details of what you pick as text, and the daily commands, stage, commit, switch, fetch, pull and push, each one announcement. It opens from the other windows on the repository of the folder or file you are in.
- **axTerminal, access layer for your shell** is a terminal: a shell (PowerShell, Command Prompt or Git Bash) in axClaude's kind of window, where every command and what it printed stand under their own Input and Output lines, the keys of axClaude find them again, and you hear when a command is done and whether it failed. It opens from the other windows on the folder you are in.
- **axPass, access layer for KeePassXC** opens a KeePass password database (`.kdbx`) in the same two panes: Right into a group, Tab to an entry's fields, the password read as hidden; Ctrl+B copies the user name, Ctrl+C the password (the clipboard clears after 30 seconds), Ctrl+L locks. It needs KeePassXC installed, whose command-line tool reads and writes the file.

Each app's guide is inside it: Help, User guide.

## Install

axKit runs on Windows 10 version 1809 or later and on Windows 11, 64-bit; the pseudo console that axClaude and axTerminal run their programs in came with 1809. Download `install.cmd` from the latest release on the releases page (https://github.com/KyleKeane/AxKit/releases) and double-click it. It fetches the latest axKit and installs it; press a key when it is done. If you have the zip instead, extract it and double-click the `install.cmd` inside. From the first release whose notes say so, the program, `AxKit.exe`, is signed for Windows through Microsoft's Azure Artifact Signing, with a certificate Microsoft issues in the maintainer's verified name, so that Windows' Smart App Control accepts it; Windows names Dr. Kyle Keane as the publisher. `install.cmd` and `install.ps1` are scripts and carry no signature of their own. If Windows SmartScreen still warns, it is building its reputation for a new version: choose More info, then Run anyway.

This puts axKit in your Programs folder (`%LOCALAPPDATA%\Programs\AxKit`) and adds, for each app, a Start menu entry (`axKit axClaude`, `axKit axDown`, `axKit axJSON`, `axKit axGIT`, `axKit axTerminal`, `axKit axFile`, `axKit axMedia`, `axKit axPreview`, `axKit axStart`, `axKit axProcess`, `axKit axTask`, `axKit axPass`, `axKit axCalc`, `axKit axClip`: press the Windows key and type `axc`, `axd`, `axj`, `axg`, `axt`, `axf`, `axm`, `axp`, `axs`, `axpro`, `axta`, `axpa`, `axca` or `axcli`), a place in the `Open with axKit` submenu of File Explorer's right-click menu (axClaude, axGIT, axTerminal, axFile and axTask on folders, axDown, axFile and axPreview on every file, axJSON on `.json` files, axPass on `.kdbx` files, axMedia on sound and video files) and a console command (`axclaude`, `axdown`, `axjson`, `axgit`, `axterminal`, `axfile`, `axmedia`, `axpreview`, `axstart`, `axprocess`, `axtask`, `axpass`, `axcalc`, `axclip`; `axkit` alone opens the app that fits the path you give it; they live in `%USERPROFILE%\.local\bin`, which the install puts on your PATH when it is not there yet, so a console opened after the install finds them; Claude Code's own install uses the same folder). It also starts axStart in the background, and axStart then starts with Windows (a setting in axStart). Settings, Apps lists axKit with an Uninstall. No administrator rights are needed, and no PowerShell setting has to change.

The install also registers the apps that open files as programs Windows knows: axDown for `.md`, `.markdown` and `.txt`, axJSON for `.json`, axMedia for the sound and video kinds, axPreview for `.txt`, `.md`, `.markdown`, `.log` and `.json`. They appear under Windows' own `Open with`, and you can make one the program that opens a kind when you press Enter on a file, in axFile or in File Explorer: Settings, Apps, Default apps, the app, then the kind; or right-click a file, Open with, Choose another app, the app, Always. Windows does not let a program set that for itself, so axKit never does.

axKit was called Axit up to 4.0.0. If you have Axit installed, close its windows and run `install.cmd` from the release page: it removes Axit completely (its folder, Start menu entries, File Explorer entries, console commands, sign-in entries and Apps entry) and installs axKit, and the first app you start moves your settings, recently closed list, consents, AI tools' pairings and logs from the Axit folders to the AxKit folders. Axit's own Update cannot make this step, since it looks for a release's files under the old repository address. If you had axClaude installed before the bundle existed, the installer removes it first too, and axClaude takes over its settings the first time it starts.

## Start

- Start menu: `axKit axClaude`, `axKit axDown`, `axKit axJSON`, `axKit axGIT`, `axKit axTerminal`, `axKit axFile`, `axKit axMedia`, `axKit axPreview`, `axKit axStart`, `axKit axProcess`, `axKit axTask`, `axKit axPass`, `axKit axCalc`, `axKit axClip`.
- Anywhere: Ctrl+Shift+Space, axStart's search field.
- Console: `axclaude`, or `axclaude C:\my\project`; `axdown notes.md`; `axterminal C:\my\project`; `axfile C:\Music`; `axmedia C:\Music\Dune` or `axmedia 03.mp3`; `axpreview README.md`; `axprocess`; `axtask C:\my\tasks`; `axpass C:\Vault\mine.kdbx`; `axcalc`; `axclip` (or Windows+Alt+V). `axkit C:\my\project` and `axkit notes.md` do the same as the first two, since a folder means axClaude and a file axDown, a `.json` file axJSON, a sound or video file axMedia.
- File Explorer: right-click a folder, open `Open with axKit` and choose axClaude, axGIT, axTerminal or axFile; right-click a file, open `Open with axKit` and choose axDown, axFile or axPreview, axJSON on a `.json` file, axMedia on a sound or video file. On Windows 11 the submenu is in the full menu (Shift+F10, or Show more options).
- From any axKit window: Ctrl+Shift+P, the command palette, finds any command of the window by typing part of its name, read with its menu and its key; Enter runs it.
- From any axKit window: F4 reports a bug, an idea or feedback to axKit's maintainer. Type your words and press Enter; Tab reviews what goes with them (the kind, the app and version, the window's last actions, where the focus was, the log's last lines, a title), all of which you can edit. The report is saved on your computer first (axKit menu, Your reports, an axTask list) and sent to GitHub as a public issue posted by axKit itself, with nothing that names you; an unsent one goes with the next.
- From any axKit window: the axKit menu (Alt+A) has the command palette, the report and your reports, starts a new window of any app, reopens a file or folder you closed lately, lists the open axKit windows, the one you were in last first and by type, closes them all, holds the AI tools, checks for updates, and has About with the version, the licence, the attribution, this guide and the project's page on GitHub.
- AI tools such as Claude Code: off until you turn them on in any window, axKit menu, AI tools, Let AI tools read and open axKit; its confirmation also adds axKit to Claude Code for you. A tool then asks you once, in an axKit window, before it reads anything; it can read what the windows show and open apps, never change or delete anything, and never reads axPass or axClip. Forget AI tools takes every permission back, and Read the log lists every call.
- In any notice's text (the keyboard shortcuts of F1, a user guide, this guide, About): h and Shift+H move by heading and 1 to 6 by level; Ctrl+F finds a text, F3 and Shift+F3 the next and the previous match.

## Update

Each app offers new versions itself (axKit menu, Check for updates and Update to). You can also run `install.cmd` again. Either way the old version is removed completely first and the new one is installed fresh. Your settings stay. An installed Axit, up to 4.0.0, is the one exception: its Update cannot reach axKit, and `install.cmd` is the way (see Install).

Every release is built by GitHub from the project's source and signed: the zip with the project's own key, which the apps and `install.cmd` check before they install anything, and, from the first release whose notes say so, `AxKit.exe` for Windows through Microsoft's Azure Artifact Signing, as above. To see the Windows signature yourself: in File Explorer, Properties of `AxKit.exe`, the Digital Signatures tab; or in PowerShell, `Get-AuthenticodeSignature "$env:LOCALAPPDATA\Programs\AxKit\AxKit.exe"`, whose status reads Valid. Versions up to 5.0.0 carried no Windows signature, and a computer with Smart App Control on could refuse them; if yours did, install the latest release from the releases page with `install.cmd` once its notes say it is signed.

## Privacy

axKit collects nothing and has no telemetry. Its own code makes network requests in two places, the updater and the report sender, over HTTPS to GitHub only. The updater: the update check when a window starts, one request for the latest release that carries the version you have and nothing else about you (Options, General, Check for updates at start turns it off), and, when you choose Update, the download of the release's zip and its signature from the release page, installed only if both check. The report sender: only when you send a report (F4), what the report notice showed you goes to GitHub as a public issue of axKit's reports repository, posted by axKit's own account with a random id of your install and nothing that names you, after a look at that repository's blocklist; an unsent report waits in Your reports and goes with the next. The access layers reach the network only through the program each runs as a child process on your computer: axClaude's Claude Code talks to Anthropic with your account; axGIT's git reaches your repository's remotes on fetch, pull and push alone, on your command and after your consent for that server; axTerminal's shell does what the commands you type do; axPass's KeePassXC tool has no network feature. Install it now runs winget or Anthropic's installer only when you choose; links open in your browser. `PRIVACY.md` next to the program says all of it, and every window shows it: axKit menu, About, Privacy. The repository's `docs/axkit/outside-calls.md` lists every network request, program start and pipe in the code, by what it reaches, with its file, line and purpose, written from the sources at every release.

## Remove

Settings, Apps, Installed apps, axKit, Uninstall (or Add or remove programs in the Control Panel). Close the apps first: while one runs, nothing is removed and the window says so. A console window says what was removed; press a key to close it. Your settings stay in `%APPDATA%\AxKit` and the logs in `%LOCALAPPDATA%\AxKit`. From a console, `"%LOCALAPPDATA%\Programs\AxKit\install.cmd" -Uninstall` does the same.
