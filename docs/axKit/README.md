# axKit

axKit is the set of tools I use every day as a blind scientist, shared in case they help someone else: personal tools, not a product or a service, with no support and no warranty. It is one Windows program that holds several apps for people who use a screen reader. It is made for NVDA and works with any screen reader that reads ordinary Windows text fields. Each app has its own window, its own Start menu entry, its place in File Explorer's Open with axKit submenu and its own console command, and all of them share this one installation and update together. More apps come as I find another thing worth doing by ear.

The apps come in two kinds. Standalone apps need only Windows and work with the network off:

- **axDown** is a plain editor for Markdown and text files: one file in one window, written back exactly as it was found, with find, go to line, and questions asked inside the window.
- **axJSON** is the same editor for JSON files, with keys that jump from key to key, object to object and array to array, a key that lands on the first mistake, and a Format command that lays the file out and repairs the small things.
- **axFile** is a file manager for one folder: a plain list of its entries, folders first, where Enter opens a folder in the list and a file in the program you have made its default in Windows, as in File Explorer. New folder, new text file, rename, delete to the Recycle Bin, cut, copy and paste, move to a new folder, zip and unzip, copy the path, with Space to select several; under the folder list a second pane holds your favourite folders, one Enter away; every operation can be undone with Ctrl+Z, newest first, and read again or jumped back to from Actions, Recent operations. It opens from the other windows on the folder or file you are in, and hands sound and video to axMedia and reading to axPreview.
- **axMedia** is a player for sound and video files with one queue: Enter on a file in axFile or File Explorer (once axMedia is its default program) plays it with its folder's other files after it; Space pauses, Ctrl+Left and Ctrl+Right seek, Ctrl+Shift+Left and Ctrl+Shift+Right change file, Alt+Up and Alt+Down change the speed with the pitch kept, F7 says what is playing. One window takes everything you open; a video's picture shows at the top of it.
- **axPreview** is a read-only viewer for one text file: the text in a plain field with every reading key axDown has, including the Markdown navigation keys, `l` for the line, Go to line and find; Ctrl+E opens the file in its editor. Shift+Enter in axFile reads a file here; one window takes everything you open.
- **axStart** is a program launcher: Ctrl+Shift+Space from anywhere brings up one search field; type part of a program's name, Down and Up move through the matches while the caret stays in the field, and Enter starts it. It runs in the background from sign-in, with no window until the key.
- **axProcess** shows what runs on the computer as one list with three views: Alt+1 the running programs with their memory and processor use ("chrome, 350 MB, 3% CPU, process 9120"), Alt+2 the Windows services, Alt+3 the programs that start when you sign in. Enter shows an item's details with what can be done to it, Delete ends a process after a question, a startup program is turned off and on again as in Task Manager, or removed after a question, F7 says how busy the computer is; the list changes only when you press F5.
- **axTask** keeps tasks and lists as a folder of small files: Right goes into a list and Left back up, as in axFile; Tab goes to the selected item's fields ("Due, date, 30 October 2026, Friday"), Enter changes one; Ctrl+Enter marks a task done (Space selects items, for a command on several); Ctrl+0 is All tasks, every task not done, the soonest due first.
- **axCalc** is a calculator as one field and a history: type an expression such as `1920*1080*4` and press Enter to hear the answer; every answer stays as a line of the history above the field, to read back, copy (Ctrl+Shift+C) or put back in the field (Enter). Ctrl+I says an answer in hexadecimal, binary and octal.
- **axClip** is a clipboard history: it keeps the text of what you copy, in memory unless you turn on Keep history between runs, and leaves out what a password manager marks private. Ctrl+Shift+Comma from anywhere brings up one search field over it, newest first; type to narrow it, Down and Up move through it, Enter pastes the item into the program you were in, Shift+Enter only copies it, F7 reads it in full, Ctrl+P pauses recording. It runs in the background from sign-in, as axStart does.
- **axTemplate** is your templates: pieces of text written once and put in again and again, with marks for where the caret is left and where the selection and the clipboard go. Ctrl+Shift+Semicolon (or the hotkey you choose) brings up its launcher over any program: type words of a template's name or text, Enter, and it is pasted where your caret was. Its browser is a list of your templates with a template's fields beside it, as in axTask. Ctrl+Enter there puts the template in around what you had selected, and what you had copied is on the clipboard again afterwards. It is being built: the launcher and the browser are there; the templates inside the other axKit apps come next.
- **axAutomate** is the workflows that drive axKit's windows, starting with the automated checks of every app: open the folder of checks, move through each one step by step, and run one with F5, on a desktop of its own.

Access layers, which work through a program you install (Claude Code, Git, your shell, KeePassXC) that does the real work under its maker's terms; `NOTICE.md` next to the program says what axKit does, what the other program does, and what is yours:

- **axClaude, access layer for Claude Code** runs the Claude Code CLI for you and shows everything Claude says in a plain text window, one line at a time, with a few keys to move around and spoken notices when Claude needs you.
- **axGIT, access layer for Git** is a git manager for one repository: a list of the changed files, the log or the branches, the details of what you pick as text, and the daily commands, stage, commit, switch, fetch, pull and push, each one announcement. It opens from the other windows on the repository of the folder or file you are in.
- **axTerminal, access layer for your shell** is a terminal: a shell (PowerShell, Command Prompt or Git Bash) in axClaude's kind of window, where every command and what it printed stand under their own Input and Output lines, the keys of axClaude find them again, and you hear when a command is done and whether it failed. It opens from the other windows on the folder you are in.
- **axHelp, access layer for Claude Code** is your conversation with Claude from anywhere: Ctrl+Shift+Slash, the question mark key (or the hotkey you choose), brings up an axClaude window titled axHelp, one conversation that goes on until you clear it, read and answered as in axClaude, on a fast model of its own (Options, Conversation model in axHelp's window); Claude Code there can do work on your computer and asks before each change. Ctrl+Shift+Period, the greater-than key, puts a picture of the window in front into the conversation, with its path on the clipboard, so that you type a question about the screen and press Enter. Alt+F4 on the conversation hides it, Claude Code running on, and the key brings the same window back at once with the caret in the message field. axDescribe is part of axHelp since 5.7.0. Shift+F1 in any axKit window asks Claude about that window. For a question about axKit, Claude answers from axKit's own guides and workflow pages, files in Claude's working folder that open in axDown: what each app can do, the steps of each task with their keys as they are in your version, and every window's commands.
- **axMCP, access layer for MCP servers** lists the MCP servers Claude Code knows on this computer (its own configuration and a folder's `.mcp.json`) and the ones you add: Right on a server starts it, the first time after your agreement, and shows its Tools, Resources and Prompts; Tab on a tool reads its arguments as fields, Enter fills one, Ctrl+Enter calls it and the result opens as text; Enter on a resource reads it. Remote servers (http) are listed and not started in this version.
- **axPass, access layer for KeePassXC** opens a KeePass password database (`.kdbx`) in the same two panes: Right into a group, Tab to an entry's fields, the password read as hidden; Ctrl+B copies the user name, Ctrl+C the password (the clipboard clears after 30 seconds), Ctrl+L locks. It needs KeePassXC installed, whose command-line tool reads and writes the file.

Each app's guide is inside it: Help, User guide.

## Install

axKit runs on Windows 10 version 1809 or later and on Windows 11, 64-bit; the pseudo console that axClaude and axTerminal run their programs in came with 1809.

The simplest way, from the Microsoft Store, where axKit is listed (the 5.2.1 package, the one submitted so far): in any terminal, `winget install 9PK01L2K5000 -s msstore`, or open the Store's page, https://apps.microsoft.com/detail/9PK01L2K5000, and press Install (Windows 10 version 2004 or later for this copy). The Store signs the package with Microsoft's certificate, which Windows' Smart App Control accepts, installs it for your account, and keeps it current by itself (see Update). The Store's copy has eight of the Start menu entries described below, the Store's limit (axClaude, axDown, axFile, axTerminal, axGIT, axTask, axStart and axClip, with axHelp in axGIT's place from the next Store package; the other apps open from their console command, from a file of their kind, from the axKit menu's Apps and Access layers, or their keys, in any window and from axFile), every console command and Windows' Open with entries, but not File Explorer's "Open with axKit" submenu, which a package cannot declare; axStart's and axClip's Start with Windows is Windows' own Startup page there (Settings, Apps, Startup, where the two are listed), which their Options, General item opens. To remove it: Settings, Apps, Installed apps, axKit, Uninstall, as for any Store app; its settings and logs go with it.

Without the Store, or for a computer with Windows 10 before version 2004: download `install.cmd` from the latest release on the releases page (https://github.com/KyleKeane/AxKit/releases) and double-click it. It fetches the latest axKit and installs it; press a key when it is done. If you have the zip instead, extract it and double-click the `install.cmd` inside. The program in the zip, `AxKit.exe`, carries no Windows signature: Windows' Smart App Control may refuse it, and a computer with Smart App Control on is better served by the Store's copy, which Microsoft signs. If Windows SmartScreen warns, it is building its reputation for a new version: choose More info, then Run anyway.

Pick one of the two ways. A Store copy and a zip copy on the same computer are two installs with separate settings (the Store keeps its copy's in the package's own folder), and each updates from its own source: the Store copy from the Store, the zip copy from the project's releases on GitHub; neither knows about the other, and Check for updates in one says nothing about the other.

This puts axKit in your Programs folder (`%LOCALAPPDATA%\Programs\AxKit`) and adds, for each app, a Start menu entry (`axKit axClaude`, `axKit axDown`, `axKit axJSON`, `axKit axGIT`, `axKit axTerminal`, `axKit axFile`, `axKit axMedia`, `axKit axPreview`, `axKit axStart`, `axKit axProcess`, `axKit axTask`, `axKit axPass`, `axKit axCalc`, `axKit axClip`, `axKit axMCP`, `axKit axHelp`, `axKit axAutomate`, `axKit axTemplate`: press the Windows key and type `axc`, `axd`, `axj`, `axg`, `axt`, `axf`, `axm`, `axp`, `axs`, `axpro`, `axta`, `axpa`, `axca`, `axcli`, `axmc`, `axh`, `axa` or `axtem`), a place in the `Open with axKit` submenu of File Explorer's right-click menu (axClaude, axGIT, axTerminal, axFile, axTask, axMCP and axAutomate on folders, axDown, axFile and axPreview on every file, axJSON on `.json` files, axPass on `.kdbx` files, axMedia on sound and video files) and a console command (`axClaude`, `axDown`, `axJSON`, `axGIT`, `axTerminal`, `axFile`, `axMedia`, `axPreview`, `axStart`, `axProcess`, `axTask`, `axPass`, `axCalc`, `axClip`, `axMCP`, `axHelp`, `axAutomate`, `axTemplate`; `axkit` alone opens the app that fits the path you give it; they live in `%USERPROFILE%\.local\bin`, which the install puts on your PATH when it is not there yet, so a console opened after the install finds them; Claude Code's own install uses the same folder). It also starts axStart in the background, and axStart then starts with Windows (a setting in axStart). Settings, Apps lists axKit with an Uninstall. No administrator rights are needed, and no PowerShell setting has to change.

The install also registers the apps that open files as programs Windows knows: axDown for `.md`, `.markdown` and `.txt`, axJSON for `.json`, axMedia for the sound and video kinds, axPreview for `.txt`, `.md`, `.markdown`, `.log` and `.json`. They appear under Windows' own `Open with`, and you can make one the program that opens a kind when you press Enter on a file, in axFile or in File Explorer: Settings, Apps, Default apps, the app, then the kind; or right-click a file, Open with, Choose another app, the app, Always. Windows does not let a program set that for itself, so axKit never does.

axKit was called Axit up to 4.0.0. If you have Axit installed, close its windows and run `install.cmd` from the release page: it removes Axit completely (its folder, Start menu entries, File Explorer entries, console commands, sign-in entries and Apps entry) and installs axKit, and the first app you start moves your settings, recently closed list, consents, AI tools' pairings and logs from the Axit folders to the AxKit folders. Axit's own Update cannot make this step, since it looks for a release's files under the old repository address. If you had axClaude installed before the bundle existed, the installer removes it first too, and axClaude takes over its settings the first time it starts.

## Start

- Start menu: `axKit axClaude`, `axKit axDown`, `axKit axJSON`, `axKit axGIT`, `axKit axTerminal`, `axKit axFile`, `axKit axMedia`, `axKit axPreview`, `axKit axStart`, `axKit axProcess`, `axKit axTask`, `axKit axPass`, `axKit axCalc`, `axKit axClip`, `axKit axMCP`, `axKit axHelp`, `axKit axAutomate`, `axKit axTemplate`.
- Anywhere: Ctrl+Shift+Space, axStart's search field; Ctrl+Shift+Slash, the question mark key, axHelp's conversation with Claude; Ctrl+Shift+Period, the greater-than key, a picture of the window in front into that conversation.
- Console: `axClaude`, or `axclaude C:\my\project`; `axdown notes.md`; `axterminal C:\my\project`; `axfile C:\Music`; `axmedia C:\Music\Dune` or `axmedia 03.mp3`; `axpreview README.md`; `axProcess`; `axtask C:\my\tasks`; `axpass C:\Vault\mine.kdbx`; `axCalc`; `axClip` (or Ctrl+Shift+Comma). `axkit C:\my\project` and `axkit notes.md` do the same as the first two, since a folder means axClaude and a file axDown, a `.json` file axJSON, a sound or video file axMedia.
- File Explorer: right-click a folder, open `Open with axKit` and choose axClaude, axGIT, axTerminal, axFile, axTask, axMCP or axAutomate; right-click a file, open `Open with axKit` and choose axDown, axFile or axPreview, axJSON on a `.json` file, axMedia on a sound or video file, axPass on a `.kdbx` file. On Windows 11 the submenu is in the full menu (Shift+F10, or Show more options).
- From any axKit window: F1, the command palette, palette and help in one: with nothing typed it lists the rules of the keys, the window's keys and every command; typing part of a command's name finds it, read with its menu and its key; Enter runs it. Ctrl+Comma opens the same, a second key on trial; Help, Keyboard shortcuts shows the keys as a text.
- From any axKit window: Ctrl+Period opens the Context menu, what acts on what you are on, as Shift+F10 and the Applications key do; let go of both keys and the menu opens. Ctrl+Slash asks Claude about the window you are in, as Shift+F1 does; with Shift added, Ctrl+Shift+Slash, it brings up axHelp from any program.
- In axClaude, axTerminal, axGIT and axProcess: Alt+1, Alt+2 and Alt+3 go to the window's first, second and third place or view (the message field, the conversation and the latest reply; Changes, Log and Branches).
- From any axKit window: F9 says the status, what the status bar at the bottom of the window holds, as one announcement, from a text, a list or a notice; nothing moves. NVDA+End reads the status bar too, when NVDA finds it; F9 is axKit's own and does not depend on that. F7 reads in full what you are on, and F8 reads it with details where the window has them. It is also Window, Say the status.
- From any axKit window: F4 reports a bug, an idea or feedback to axKit's maintainer. The form opens with the notice's explanation said once and the focus in Your report, ready to type; Enter there makes a new line. Tab goes on through standard controls: the kind (a list: Feedback, Bug, Feature request), a check box for more detail, and What is sent with your report, a text you can read but not change (the app and version, the commands you last ran, the kind of control the focus was in, the log's recent errors with paths masked), then the Send and Cancel buttons. Ctrl+Enter sends from anywhere in the form, and so does the Send button; Escape cancels and keeps nothing. The report's title is the first line you typed. By itself a report names none of your files, folders or items; a check box in the form, not checked, adds detail that may: the window's title, the focused item, what the window said, the log as it is. The report is saved on your computer first (Help, Your reports, an axTask list). Then it is encrypted on your computer and sent to a private repository on GitHub that only axKit's maintainer can open; only the maintainer's key can read it, and nothing in it names you unless you write it. The maintainer may quote or summarise a report in axKit's public repository when fixing it, without anything that identifies you. An unsent one goes with the next.
- From any axKit window, the bundle's menus at the end of the menu bar, after the app's own: the app's Options, then Window (Alt+W) starts a new window of any app, lists the open axKit windows, the one you were in last first, reopens a file or folder you closed lately, closes them all and says the status; axKit (Alt+K) holds what is the whole bundle's: Claude (the switch Use Claude in axKit, a question about this window, the folders Claude may read, Claude's working folder), the AI tools, the theme and the app keys file; Help (Alt+H) has the command palette, the keyboard shortcuts, the user guide, the report and your reports, checks for updates, and has About with the version, the licence, the attribution, this guide and the project's page on GitHub.
- In any field where you can type several lines (the editors, a long text in axTask, axClaude's message, axTerminal's command, a report): a line break you type is said, "new line", since NVDA says nothing for Enter; Enter that sends, opens or presses a button says nothing of it. Options, Text, Say new line in any window turns it off or on for every window; it is kept in the theme file as `display.sayNewLine`.
- Wherever a key lands on a heading, a heading row of a list in axTask, axPass, axMCP or axAutomate, or a Markdown heading in axDown, axPreview or a notice's text: a short rising sound plays before NVDA reads it, so you know it is a heading before the words come. Options, Text, Sound on headings in any window turns it off or on for every window; it is kept in the theme file as `display.headingSound`.
- Whenever the focus enters a list, a text, a field or a form (something opened, Tab or F6 took you to another part of the window, a notice closed, a window started), a short sound of bell notes says what kind of thing you are now in, before NVDA reads it, so that you know how the keys will work there. Every one starts with the same three quick beeps running up, then goes down: one long tone is a field to type in; a lower long tone is a text to read; four quick beeps are a list; beeps and tones together are a form, where Tab moves between several fields. Moving inside one of them is silent. When the same key already played another sound, such as the edge or a refusal, you hear that one alone. A form then says its title and the word "form", for example "Move 2 items, form", and nothing more: F7 reads its explanation when you want it, and reads the text of any question or notice again. Options, Text, Entry sounds in any window turns the sounds off or on for every window; it is kept in the theme file as `display.openingSounds`.
- AI tools such as Claude Code: off until you turn them on in any window, axKit menu, AI tools, Let AI tools read and open axKit; its confirmation also adds axKit to Claude Code for you. axHelp's conversation gets the tools by itself while they are on, with instructions for Claude on when to use which; while they are off it gets none. A tool then asks you once, in an axKit window, before it reads anything; it can read what the windows show and open apps, and never reads axPass or axClip. Only if you also turn on AI tools, Let AI tools run commands, can it run a window's menu commands by name: the window says each one as it runs ("Claude ran Word wrap"), a command that deletes, moves, sends, opens a file in its program, starts or ends something asks you first, and it never answers a question the window asks you. The question is a short list you answer with the arrows. It comes with an alarm of five short falling swoops and starts with the words "Command offer", then who asks, the command and what it would act on (the selected file, program or item). The list starts on "Explain this command", which only opens a text about the request and comes back, so an Enter pressed by accident runs nothing; "Yes, run it" is the second answer and "No, do not run it" the third, which Escape chooses too. In axClaude, axTerminal and the editors the list is at the bottom and the conversation or the text is still there to read; in the other windows it covers the window until you answer. The command does not run if the selection has changed by the time you say yes. A command it runs may move the caret or the focus as its key would, so it never runs in the window in front while you are typing there; in a window behind, you hear a chime and the window flashes on the taskbar instead of the words, once for a quick run of several. Forget AI tools takes every permission back, Let AI tools run commands with it (turning the AI tools off does too), and Read the log lists every call. With an axTask window open, a tool can also read your lists and their items, and, while Let AI tools run commands is on, add an item to one of them by words ("remind me next week to call the dentist"): the window says "Claude added Call the dentist to Personal", and Ctrl+Z there takes it back; it never changes or deletes an item.
- In any notice's text (Help, Keyboard shortcuts, a user guide, this guide, About): h and Shift+H move by heading and 1 to 6 by level; Ctrl+F finds a text, F3 and Shift+F3 the next and the previous match.
- Colours, for a sighted helper or low vision: in any window, Options, Theme, Edit theme file opens `%APPDATA%\AxKit\theme.json` in axJSON, one line per class of object (the window, the texts, the transcripts, the lists, the console field and its band, the notices, the status bar, the menus, the buttons, the title bar), each `system` for Windows' own colour or a hex colour such as `#FFF4C2`. Save it and switch back: the window takes it, and every other window when it is next activated; Reload theme reads it at once, Theme on switches it off and on. Nothing changes for a screen reader. The same file holds `display.wordWrap`, the editors' word wrap, one value for axDown, axJSON and axPreview, which Ctrl+Shift+W in any of them writes.
- The app keys: from any axKit window, Ctrl with a function key opens an app and Ctrl+Shift with one an access layer, each group of apps on a block of four keys (F1 lists them; axKit, Apps and Access layers show each app's key). To give an app a key of your own: Options, Edit app keys file opens `%APPDATA%\AxKit\app-keys.json` in axJSON, written the first time with every app and its key, such as `"axFile": "Ctrl+F2"`. Change a key, or write `"none"` to take an app's key away; an app you delete from the file keeps its usual key. A standalone app keeps Ctrl with a function key and an access layer Ctrl+Shift with one, so that a key still says which kind of app it opens. Save it: every window you open after that has the new keys, the menus and F1 too; a window already open keeps the keys it started with, and axStart, axClip and axHelp take them at their next start. An entry axKit cannot use, a name that is no app, a key it cannot read or of the wrong kind, or a key another app or the bundle already has, is skipped and that app keeps its usual key; `axKit.log` in `%LOCALAPPDATA%\AxKit\logs` says why. Two apps can swap their keys in the file. Delete the file to have every usual key back.

- A log of events, for finding where an app behaves oddly: in any window, Options, Keep a log of events (off at first; "Keep a log of events, checked" when you turn it on). While it is on, each thing that reaches you (a refusal, a line arriving, a turn done, words said) is one line of `%LOCALAPPDATA%\AxKit\logs\events.log` with its time and its kind, never a word of it. Every window follows the switch from its next activation; turning it off stops the writing and leaves the file until you delete it.

## If a key does nothing

In any axKit window: Help, Diagnostics, Test a key (Alt+H, D, T), or F1 and `test a key`. It says "Key test. Press any key to hear its name and what it does here. Press Escape to end."

- Now press the key. axKit says its name and what it does in this window, where you are: "F9: Say the status", "F8: What runs in the background", "A: types the letter", "Down: moves in the list", or "Shift+F9: no command of this window". Nothing is carried out while the test runs: no command runs, nothing is typed, the menu does not open, and Alt+F4 does not close the window. A key such as Alt or Ctrl, pressed and released alone, is named too.
- A key that is not said did not reach axKit. The keyboard changed it (a function key that needs or must not have the Fn key), or Windows, NVDA or another program took it first. NVDA's own input help, NVDA+1, says each key NVDA sees: a key that NVDA names and axKit does not was taken between the two; a key that NVDA does not name either never left the keyboard as that key. NVDA+1 again turns input help off.
- A key that is said with a command you did not expect is the window's own answer: the same key can do something else in another place of the window, so test it where you would press it, the text field or the list.
- Escape ends the test at once, "Key test ended"; Escape is the one key the test does not name. It also ends when you go to another window. The keys act again, and nothing in the window has changed.

Help, Diagnostics also holds Copy diagnostics, which puts the version, the paths and the last log lines on the clipboard for a bug report, with your account's name and paths replaced.

## Update

A copy from the Microsoft Store is updated by the Store itself, usually within a day of a release, with nothing to press; Check for updates (Help menu) says where your copy stands against the latest release and opens axKit's Store page, where Update appears as soon as the Store has it. That copy makes no check at start and downloads nothing itself.

A copy installed from the zip offers new versions itself (Help, Check for updates and Update to). You can also run `install.cmd` again. Either way the old version is removed completely first and the new one is installed fresh. Your settings stay. An installed Axit, up to 4.0.0, is the one exception: its Update cannot reach axKit, and `install.cmd` is the way (see Install).

Every release is built by GitHub from the project's source, and its zip is signed with the project's own key, which the apps and `install.cmd` check before they install anything. `AxKit.exe` itself carries no Windows signature, and every release's notes say so; the Microsoft Store's copy is the one Microsoft signs, so a computer with Smart App Control on, which refuses an unsigned program, installs axKit from the Store.

## Privacy

axKit collects nothing and has no telemetry. Its own code makes network requests in two places, the updater and the report sender, over HTTPS to GitHub only. The updater: the update check when a window starts, one request for the latest release that carries the version you have and nothing else about you (Options, Check for updates at start turns it off, for every app), and, when you choose Update, the download of the release's zip and its signature from the release page, installed only if both check. The Store's copy makes no check at start and downloads nothing: Check for updates by hand asks GitHub the same one question, and the Microsoft Store installs the updates under Microsoft's privacy statement, as for any Store app. The report sender: only when you send a report (F4), what the report notice showed you is encrypted on your computer, for a key only axKit's maintainer has, and goes to GitHub as an issue of axKit's private reports repository, posted with the maintainer's reporter token, never with an account of yours, carrying in the clear a random id of your install, axKit's version and the report's kind, and nothing that names you. Before that it reads the block list, a file of a public repository on GitHub that holds only random install ids and versions whose reports are not accepted: a read that sends nothing of yours but the request. Those are the two addresses of GitHub the report sender contacts. If your install or version is on the list, nothing is sent and a notice says so, with your install id and the page where to ask if it is a mistake. GitHub stores the encrypted text and sees when and from which network address it came, under GitHub's terms; an unsent report waits in Your reports and goes with the next. The access layers reach the network only through the program each runs as a child process on your computer: axClaude's Claude Code talks to Anthropic with your account, when you start axClaude or axHelp's conversation, and without your key only if you turn on axHelp's Options, Keep the conversation ready in the background, off at first: axHelp, started in the background at sign-in, then starts Claude Code hidden for its conversation once you have agreed to Claude Code in axClaude, and Claude Code may contact Anthropic as it starts; axGIT's git reaches your repository's remotes on fetch, pull and push alone, on your command and after your consent for that server; axTerminal's shell does what the commands you type do; axPass's KeePassXC tool has no network feature. Install it now runs winget or Anthropic's installer only when you choose; links open in your browser. `PRIVACY.md` next to the program says all of it, and every window shows it: Help, About, Privacy. The repository's `docs/axKit/outside-calls.md` lists every network request, program start and pipe in the code, by what it reaches, with its file, line and purpose, written from the sources at every release.

While you have Options, Developer, Events from Claude Code's hooks turned on (it is off at first), axClaude asks Claude Code to start `AxKit.exe hook` for eight kinds of events of it (a session started or ended, a turn stopped or failed, an agent started or stopped, a permission asked, a notification): that process tells the axClaude window, over a pipe on your computer that only your Windows account may open, that the event happened, and ends. The hooks are registered for that one start of Claude Code with a file of axKit's own (`claude-hooks.json` in `%LOCALAPPDATA%\AxKit`), never in your settings or a project's, and decide nothing Claude Code does; Options, Developer, Events from Claude Code's hooks turns them off. Nothing is sent anywhere, and axKit listens on no port.

A second way to run Claude Code is being built and is off unless you turn it on (Options, Developer, Feed the next window from Claude Code's stream): Claude Code as one process without a console, over pipes on your computer. It talks to Anthropic exactly as it does the other way; axKit adds no network contact. Run this way, Claude Code starts `AxKit.exe ask` and asks it before a tool call that needs your word and for Claude's own questions: that process passes each question to the axClaude window, over a pipe on your computer that only your Windows account may open, and passes your answer back; where the window cannot be asked, its answer is no. It is named for that one start with a file of axKit's own (`claude-ask.json` in `%LOCALAPPDATA%\AxKit`), never in your settings or a project's. Before the first start in a folder, axClaude asks whether you trust the folder, since Claude Code does not ask then.

axClaude also reads the session file Claude Code keeps for the conversation, in memory only, to check and order what it shows; nothing of it is sent, logged or reported, and Options, Developer, Ground the conversation in Claude Code's session file turns it off.

## Settings that decide what is run

Some settings decide which program an app starts or what Claude may read: axTerminal's shells, axGIT's trusted repositories, axMCP's servers, axFile's custom programs, the place of Claude Code, AI help's switch, folders and working folder, and the record of what you agreed to (Help, About, Licence). axKit seals these in their files, so that they count only as axKit wrote them: change them in the menus. If one is changed in its file by hand or by another program, it is not used, your other settings stay, and the app says once what was not used and where to add it again, for example "Your shells in axTerminal's settings were changed outside axKit and are not used. Add them again from Session, Add a shell."; for the agreements, each app asks again. The file as it was found is kept beside it, with .changed at the end of its name. AI help's `claudePath` and `workingFolder` in `ai-help.json` have no menu item yet, so they can be set by hand only in a file axKit has not written yet. The seal's key is kept by Windows for your account, on this computer only. A program running as you could ask Windows for it, so the seal protects against a file changed by another program or by hand, a profile copied or synced from another computer, and an AI tool writing files, and not against a program that sets out to forge it.

## Settings with several windows open

Two windows of one app share one settings file. When a window saves its settings, it keeps what another window of the app saved since: only the settings you changed in this window are written over the file's. So a favourite, a shell, a trusted repository or a server you add in one window stays when an older window saves something else. Two limits: a window shows the other window's change only after it is started again, and a list you changed in both windows (say, a shell added in each) keeps the list of the window that saved last. A setting that a newer version of axKit wrote and this version does not know is left in the file as it was.

If a settings file cannot be written (it is read-only, the disk is full), the window says so once: "Settings could not be saved:", the reason, and "What you change lasts until this window closes." Every failure is in the log.

If a settings file cannot be opened when an app starts (another program holds it: a sync client, a backup, a virus scanner), the app uses the defaults for that run and does not save, so that the file is not replaced; it says so and asks you to close the window and start it again. If one value in the file is mistyped, only that setting is at its default: the app says "The settings file was read, except for the settings named here.", names them, keeps the rest, and keeps a copy of the file as it was, with .bad at the end of its name. A file that is not readable at all is copied the same way, and the app starts with the defaults.

## A remembered folder on the network

An app started without a path opens what it had last: axFile its folder, axGIT its repository, axTerminal and axClaude their folder, axPass its database, axTask its list, axAutomate its folder of workflows. When that place is on a network share or a mapped network drive, the app does not look for it while it starts, because a network that is away would keep the window from appearing for a long time without a word. It opens as if nothing were remembered and says where the place is and how to open it: "<path> is on the network and was not opened at start; Open recent opens it." In axPass the sentence ends "Open database opens it", in axAutomate "Open a folder of workflows opens it", in axTask "Right on its list opens it". A path you give when you start the app is always opened.

## Remove

Settings, Apps, Installed apps, axKit, Uninstall (or Add or remove programs in the Control Panel). For the zip's copy: close the apps first: while one runs, nothing is removed and the window says so. A console window says what was removed; press a key to close it. Your settings stay in `%APPDATA%\AxKit` and the logs in `%LOCALAPPDATA%\AxKit`. From a console, `"%LOCALAPPDATA%\Programs\AxKit\install.cmd" -Uninstall` does the same. For the Store's copy, Windows removes the package and, with it, the settings and logs that copy made, which Windows kept in the package's own AppData folder; a settings file that existed before that copy's first start stays where it was.
