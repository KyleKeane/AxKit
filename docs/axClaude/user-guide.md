# axClaude user guide

**axClaude, access layer for Claude Code.** axClaude only shows what Claude Code does and passes your messages and answers to it. Claude Code, Anthropic's program, and Anthropic's service do the work, under your Anthropic account and Anthropic's terms. Before axClaude first starts Claude Code it shows a short reminder with a check box: you confirm that axClaude is only an access layer and that following Claude Code's terms is up to you. Help, About, Licence has these reminders and what you agreed to.

axClaude is a Windows program for using Claude Code with a screen reader. It runs Claude Code for you and shows everything Claude says in a plain text window, one line at a time. You type to Claude in a text field at the bottom. It is made for NVDA and works with any screen reader that reads ordinary Windows text fields.

You are talking to the real Claude Code. Slash commands, questions, permission prompts and modes all work as they do in a terminal. axClaude only adds a window you can read line by line, a few keys to move around, and spoken notices when Claude needs you.

## What you need

- Windows 10 (version 1809 or later) or Windows 11.
- Claude Code, installed and logged in. If it is missing, axClaude tells you and gives you the install command. To install it yourself, open Windows PowerShell and run `irm https://claude.ai/install.ps1 | iex`, then run `claude` once and follow the login steps. Claude Code needs a Claude subscription (Pro, Max, Team or Enterprise) or a Console account.

## Install axClaude

axClaude is one app of **axKit**, one program that holds several apps for screen reader users. Download `install.cmd` from the latest release on the releases page (https://github.com/KyleKeane/AxKit/releases) and double-click it. It fetches the latest axKit and installs it; press a key when it is done. If you have the zip instead, extract it and double-click the `install.cmd` inside. If Windows SmartScreen warns about an unknown publisher, choose More info, then Run anyway.

This puts axKit in your Programs folder and adds a Start menu entry, "axKit axClaude" (press the Windows key and type `axc`), axClaude in the "Open with axKit" submenu of the right-click menu of folders, the `axClaude` command for consoles, and an entry in Settings, Apps named axKit. No administrator rights are needed, and no PowerShell setting has to change. If you had axClaude installed before axKit existed, the installer removes it first, and axClaude takes over your settings the first time it starts.

To update: axClaude offers new versions itself (the Help, Check for updates). You can also run `install.cmd` again. Either way the old version is removed completely first and the new one is installed fresh. Your settings stay.

To remove: Settings, Apps, Installed apps, axKit, Uninstall (or Add or remove programs in the Control Panel). Close axClaude first: while it runs, nothing is removed and the window says so. A console window says what was removed; press a key to close it. Your settings stay. From a console, `"%LOCALAPPDATA%\Programs\AxKit\install.cmd" -Uninstall` does the same.

## Start

Claude works in one project folder at a time. Pick how you start:

- Start menu: axKit axClaude opens the folder you used last time. The first time, it asks you to choose a folder.
- Console: `axClaude` uses the current folder. `axclaude C:\my\project` uses that folder, and so does `axkit C:\my\project`, since a folder means axClaude. axClaude continues your last conversation in the folder, or starts a new one when there is none; `axclaude --` alone always starts a new one, and anything else after `--` goes to Claude Code, for example `axclaude -- --resume`.
- File Explorer: right-click a folder, open "Open with axKit" and choose axClaude.

Session, New session (Ctrl+N) starts a new session from inside axClaude. The notice shows the folder, with a Choose folder button under it, then a list of ways to start Claude: a new conversation, continue the last conversation, choose a conversation to resume, plan mode, edits accepted without asking, and Custom, where you type Claude Code's own command line options, one or more on each line. Enter stops the current session, clears the conversation and starts the new one in the empty window; with "Continue the last conversation" the earlier exchanges come back under their "from previous session" headings, and messages count from 1 again. Escape keeps the current session. Force Claude to restart (Ctrl+Shift+R) keeps the options you chose and the conversation.

The first time Claude Code sees a folder it asks whether you trust it. Questions like this, and the lists that commands such as `/model` open, take the place of the message field at the bottom of the window: a quick high trill, and the answers as a list, named with the question. From the message field you are taken there at once; from the conversation a moment later, where NVDA reads the question and the current answer after what it was reading, so that nothing cuts your own reading short. Ctrl+Tab takes you back to the conversation for what Claude said before asking. Options, Questions, "Go to them at once, interrupting speech", off in a new install, takes you to a question at once from anywhere and stops whatever NVDA was reading. One thing a question still cuts off: a reply that axClaude itself is speaking for you (Options, Speech, Speak replies), which would otherwise run into the question; the reply stays in the conversation. After you answer, Claude Code leaves a note in the question's place, "User answered Claude's questions:" with the question and your answer; it is there to read and is never spoken by itself, since you heard "Sent" with your answer. Ctrl+Tab or F6 moves between the conversation and the answers, as it does with the message field, and the question is read each time you arrive. Up and Down Arrow or the answer's number (or y and n) choose; pressing a number again moves on to the next answer starting with it (1, 10, 11), and Shift with the number goes back. 0 goes through the answers 1 to 9, Shift+0 back. Page Up and Page Down move ten answers, Home and End, or Ctrl+Home and Ctrl+End, go to the first and the last. The same keys work in every list axClaude shows, Enter answers, Escape cancels the question. Ctrl+Q reads the question again at any time, from anywhere, all its lines and the answer you are on, without moving you; it reads a screen such as the feedback review the same way. The conversation stays as it is, with Claude's full question in it. When you choose "Other", or another answer that asks for your own words, a field takes the list's place, named with the question and the answer you chose: type your answer and press Enter, or Escape to go back to the list. When Claude asks several questions at once, they come one after the other, each named with its place ("Question 1 of 2"); after each answer axClaude says what comes next. Claude then shows a review of your answers, and axClaude submits it for you, unless a question was left without an answer. The same review follows a question alone that takes several answers, and axClaude submits it the same way. Options, Questions, "Review answers before they go to Claude", shows the review instead, where y submits your answers. A question that allows several answers has check boxes: Space ticks the answer you are on, and Enter sends all the ticked ones. For a second after a question appears, Enter and the other answering keys do nothing, so keys you were typing for a message cannot answer by accident. When Claude has your answer, the message field comes back, with what you had typed in it.

Screens that Claude shows until you press a key, such as `/status`, `/tasks` and `/help`, come the same way: a list of the screen's lines, then one item for every key the screen offers, for example "View (Enter)", "Close (Escape)" or "Select (Down)". Enter on a key's item sends that key to Claude. Enter on any of the screen's lines, or Escape, closes the screen, and you hear "Closed"; if the screen is still open afterwards, the list comes back with what it shows now. A screen that only informs, such as the side answer of `/btw <question>` or `/goal`, is read-only text inside the window instead, read with the arrow keys: its title, then its lines. Enter or Escape closes it, in Claude too; Tab reaches its buttons, Close and one for each other key the screen offers, such as "Copy (c)" and "Fork (f)", or "Browse (Shift+Left)" after a second `/btw`, which change the text in place. `/config` lists Claude's settings: Enter on one changes it (a true or false setting asks which), and Escape saves and closes.

Claude Code sometimes drafts feedback for Anthropic by itself, about a bug or an idea it noticed, and prints a card at the end of the turn: "Product feedback drafted", a preview of the draft, and keys to review, send or dismiss it that cannot be pressed from the message field. axClaude brings the draft up like a question instead, as soon as Claude is done: the trill, then the draft's review as a screen with the draft's text, "Send (Enter)", "Discard (d)" and "Later (Escape)". Enter anywhere in the review sends it and d anywhere discards it, as in the terminal, where only Claude's highlight counts; the items at the end of the list name the keys. The receipt follows with "Continue (Enter)". After any of the three the message field comes back. "Move (Up)" moves Claude's highlight to the transcript switch and then to the draft's fields: a switch is changed with "Change (Left)" or "Change (Right)", while a text row such as Details gives you a field named with the row: what you type is added to the end of the row's text when you press Enter, which also moves on to the next row, and Escape cancels the edit. Ctrl+Q reads the review with the row's text as it stands. Nothing can be deleted this way: to reword a draft, discard it and ask Claude to draft it again with your changes. Later keeps the draft: `/feedback` lists the drafts waiting on this machine, this session's first, and Enter on one gives the same review. Drafts already waiting when axClaude starts are left for `/feedback` too; nothing opens by itself at startup. The card itself is not in the conversation. `/config` has a setting that turns Claude's drafting off.

Now and then Claude Code also asks "How is Claude doing this session? (optional)". axClaude shows it like any question: the list Bad, Fine, Good and Dismiss, where Enter answers and Escape dismisses it. Claude takes the answer as a single key with no Enter after it, and axClaude sends it that way. A question whether Anthropic may look at the session's transcript can follow, with Yes, No and Don't ask again, where Escape says No.

Anything Claude asks that axClaude cannot list stays with the message field and is announced with "Claude asks". Then Enter only sends an answer: a message you typed stays in the field, and axClaude says so; press Enter again to send it all the same. Options, Questions, "Answer from a list", turns the lists and this protection off: questions are then only announced, and you answer them in the message field.

## The window

From top to bottom: the menu bar (press Alt), the conversation, the message field, the status bar. Focus starts in the message field.

- The **message field** is called "Message to Claude". Enter sends, and so does Ctrl+Enter, the main action in every axKit window. Shift+Enter starts a new line. Enter on an empty field sends a plain Enter, which is how you confirm a dialog. Page Up and Page Down move one screen of the field at a time and reach the first and last line of your message; Home and End move within the line, Ctrl+Home and Ctrl+End to the start and end of the message. Ctrl+Up and Ctrl+Down move to the previous and next paragraph of your message, the first line after a blank line, and with Shift they select to there, as in Word.
- The **conversation** is a read-only text called "Conversation". Every line Claude prints is a line here. Arrow keys, Home, End, Page Up, Page Down and your screen reader's reading commands all work. Ctrl+Up and Ctrl+Down move to the previous and next paragraph, the first line after a blank line, and Ctrl+Shift+Up and Ctrl+Shift+Down select to there, as in Word. Alt+1 goes to the message field and Alt+2 to the conversation; when you are there already, the key says so, which helps when you have lost track of where you are. Tab, Shift+Tab, Ctrl+Tab or F6 switches between the two. Escape in the conversation goes back to the message field.
- While Claude is still writing a line and you are on it, Down Arrow reads only what has arrived since you last heard it, so you can follow a long reply as it comes without hearing anything twice. Once you move on, the line reads as one line again.
- To copy from the conversation: Shift with the arrow keys selects text, Ctrl+C copies it and says "Copied". While text is selected, new output waits until you press a plain arrow key. Escape clears the selection; a second Escape goes to the message field.
- The **status bar** says what Claude is doing (starting, ready, working, waiting for your answer, stopped), how many messages are waiting and how many things run in the background ("1 shell in the background", "3 in the background: 1 shell, 2 agents"), the permission mode, the session name and the project folder. F8 says it from anywhere in the window, as in every axKit window; NVDA+End reads it too.
- **Work in the background** is something Claude started and left running: a shell command, an agent working on a part of the task, or a workflow, a larger piece of work in several steps. axClaude does not read Claude Code's rows about it into the conversation, and never speaks them: not the row of each agent, not a workflow's row that shows how far it is, and not "Waiting for 1 dynamic workflow to finish" after a turn. You hear it instead: three quick bell notes going up, with a little sparkle, when background work starts, the same three going down when it ends, and while anything runs, slow soft chords, one after another: each swells, rings with a long fading tail and a small bell note, about four and a half seconds in all, and after a pause of 2 seconds the next comes, another of the background music's four chords chosen at random. Each thing running adds a note on top, up to five things: the more runs, the fuller the chord, so that you hear in passing that work goes on and how much. Something that starts is heard in the next chord; when nothing runs any more, no new chord starts and the last one rings out. Ctrl+B (Actions, What runs in the background) says the number, each agent's type and what it does, and each workflow with how far it is, such as "Workflow axkit-design-map-and-verify: 88 percent, 8 of 9 done, 20m18s". Options, Background work turns each sound off, sets the pause between the chords (2, 5, 10 or 20 seconds; 2 at first), and has Say background work as it starts and ends, off at first, which also speaks a short line for each change, after whatever is being read. Show Claude Code's live progress rows in the conversation, off at first, puts those rows back at the end of the conversation, as Claude Code draws them, for when you want to read them there: they change as the work goes on and are still never spoken.

axClaude never opens a second window. Its questions, errors and help texts are **notices** that take the place of the conversation and the message field, so nothing can hide behind the window. Your screen reader reads the title and the first line; Down Arrow reads the rest. Tab moves to the buttons, Enter chooses the main button, Escape closes the notice. Only the Windows folder, file and font pickers are separate windows.

Alt+F4 closes axClaude and ends the Claude Code session. If Claude is still working, a notice asks first: Enter closes anyway, Escape keeps axClaude open. What is done so far is saved, and the next start carries on from it.

One window is different: axHelp's conversation, the axClaude window titled axHelp. There Alt+F4 hides the window and Claude Code keeps running, so that axHelp's key brings it back at once; hidden, it says nothing and plays no sound. Its Session menu has Hide this window in Exit's place, and End Claude and close this window, which ends it as Alt+F4 ends any other axClaude window. A program that wants such a window starts axClaude with `--hide-on-close`, and with `--hidden` to start it hidden. With `--ai-tools`, as axHelp starts it, Claude in that window gets axKit's AI tools by itself while you have them turned on (axKit menu, AI tools); turned off, nothing is added.

## Send a message

When Claude has started, axClaude says "Ready" with a high ping. Type in the message field and press Enter. axClaude says "Sent" with a short low note, and "Responding" with a rising chime when the reply starts. A soft tick, like a typewriter key, marks every new line that arrives from Claude, and a tiny soft pop, over in a moment, marks each tool Claude starts, so you can hear Claude working without reading along. "Done" comes with three falling notes once the whole turn has ended and its last reply is in the conversation. When replies are spoken, the word comes first and the last reply's words after it, "Done" and then the reply, so that you know at once that Claude has finished; what NVDA was already reading is not cut off. Options, When Claude is done, Announce "Done" turns the word off, and the reply is then read alone. A reply you interrupt, and one that Send queued messages now cuts short, ends without "Done". A question from Claude comes with two equal notes and "Claude asks". If the window is in the background, its taskbar button flashes, and a louder alert sounds there in place of the done or question chime, so that you hear it from another window. Quiet, slow background music, soft sustained chords that drift into one another with a faint high ping now and then, like the lift of a building of the future, plays while Claude works and stops when the turn ends, so you hear that Claude is still at it without reading along. Ctrl+M turns the music on or off from anywhere in the window and says so, and tells you when nothing is running yet. The alert and the music are on in a new install. Options, Sounds and Options, When Claude is done turn each of these on or off.

You can send while Claude is still working. Claude Code keeps the message and takes it up when it can. axClaude says "Queued" and the status bar counts the waiting messages. The message appears in the conversation when Claude takes it up, usually after its current step. Ctrl+Shift+S (Actions, Send queued messages now) makes Claude take it up at once.

To read back a long message before you send it, press Ctrl+Space in the field: axClaude says "Navigation mode", and the single letters move through the message as they do in the conversation: h and Shift+H by heading, 1 to 6 by level, k by link, l by list, i by list item. The arrows still move and select, and Ctrl+C copies, but nothing changes the message: Enter does not send and plays the low edge sound, as Backspace and Delete do. A letter that moves you gives a high tick first, one that finds nothing of its kind a low buzz, and a letter with no command a wooden bonk. Ctrl+Space again says "Edit mode", and you type as before. The status bar says "field in navigation mode" while it lasts, and the field starts in edit mode every time. In the conversation, which you cannot type in, Ctrl+Space says "Read only: there is no edit mode here".

Up and Down in the field only move through what you are typing. Messages you sent earlier are in the conversation: `i` and Shift+I jump between their `# Input` lines, and Enter on a line copies it into the message field.

Keys that go straight to Claude Code:

- Shift+Escape interrupts Claude, or closes one of its dialogs. Plain Escape in the message field does nothing, on purpose: it is easy to press by accident, and it would stop Claude in the middle of its work.
- Ctrl+Shift+M switches to the next permission mode (manual, accept edits, plan, auto and so on) from anywhere in the window. The new mode is spoken. It is the key Claude Code calls Shift+Tab; in axClaude, Shift+Tab moves the focus like Tab.
- Actions, Send key, Up and Down send Up and Down to Claude, for its own menus, and Shift+Up and Shift+Down send those two keys. They have no key: Ctrl+Up and Ctrl+Down move by paragraph, as everywhere in axKit, and Shift with an arrow selects text in the message field. To change Claude's effort level, type /effort.
- Ctrl+Shift+C sends Ctrl+C from anywhere in the window. Ctrl+O, Claude's detailed view, is switched off in axClaude: in screen reader mode it redraws the whole conversation, which doubled it and spoke old replies again. Pressing it says so. To see what the tools print, start the session with the `--verbose` argument (Ctrl+N, Custom, for example `--continue --verbose`): every tool's output then appears in full under its "tool:" line. Claude, Send key has Ctrl+D and Tab too.

### When Claude asks you to run a command yourself

Some commands Claude cannot or should not run: a sign-in that asks questions, or something its permissions refuse. Claude can then offer you the command. When its turn has ended, a list takes the message field's place. You answer it as you answer one of Claude's questions, and you can always tell it from one: it has a sound of its own, an alarm of five short falling swoops, where a question has the quick high trill, and everything about it starts with the words "Command offer". The list is called "Command offer: it runs on your computer, outside axKit. Claude offers a command for you to run" followed by the command itself, and Ctrl+Q reads that again with Claude's reason. The conversation is still there: Tab or Alt+2 goes to it, so you can read what led to the command, and Tab or Alt+1 comes back to the list.

The list starts on its first answer, which runs nothing, so an Enter pressed by accident is harmless:

- Explain this command opens a text: the command, why Claude offers it, what each part does in Claude's words when it said so, and what each answer does. Read it with the arrows; `h` jumps by heading. Enter or Escape closes it and you are back on the list.
- Yes, run it sends the command to Claude Code as a line that starts with an exclamation mark, exactly as if you had typed it, and says "Sent". What the command prints appears in the conversation, and Claude can read it.
- No, do not run it sends nothing and says "Not run". Escape does the same.
- No, copy it to the clipboard instead puts the command on your clipboard and sends nothing. It is the only answer that touches your clipboard.
- No, and report a concern about it asks for your words in a field (they are optional), then opens Claude Code's own feedback with the command, Claude's reason and your words. Claude Code shows you the report and asks before anything goes to Anthropic. Escape in the field goes back to the list.

Claude writes the command and its explanation, and Claude can be wrong; axKit checks neither. A command may be offered precisely because Claude Code's own permission or safety checks refused to run it, so treat it with care: read the explanation and the conversation before you say yes, and do not run a command you do not understand. The question says so each time it is read ("Written by Claude, an AI: read the explanation before you run it"), and the explanation starts with a section called "Read this first". Running it is your own act, as if you had typed it.
A command run this way skips Claude Code's own permission check, because it is your command, so axClaude asks every time and there is no "always allow". For this to work, the AI tools must be on and axKit added to Claude Code: axKit menu, Claude, AI tools, Let AI tools read and open axKit. You can always type such a line yourself too: an exclamation mark, a space and the command.
## Slash commands

Anything that starts with a slash is a Claude Code command. Type `/help` and press Enter for the list. Some useful ones:

- `/clear` starts a new conversation with an empty context. The window empties too, says "Conversation cleared", and starts with one "System:" line saying that `/resume` brings the previous conversation back. `/compact` shortens the current one to free up space.
- `/model` picks the model. `/permissions` changes what Claude may do without asking. `/config` has the other settings.
- `/resume` goes back to an earlier conversation. `/cost` and `/status` show usage and the session state.
- `/exit` ends the Claude Code session. The window stays open; Ctrl+Shift+R starts Claude again.

The Help menu opens the Claude Code documentation in your browser: the commands, the keys and the command line. Claude Code's autocomplete list is not shown; axClaude sends exactly what you typed.

## Read the conversation

Every message you send is printed like this: the line `# Input 1`, your message, a blank line, the line `# Output 1 Reply from Claude`, a blank line, then Claude's reply. Options, Text, Markers in the text hides the `#` of every heading line in the window; the keys and the export keep them. Both `#` lines are level 1 headings. When axClaude starts on a folder with a conversation, the earlier exchanges come back under `# Input 1 from previous session` and `# Output 1 from previous session Reply from Claude`, with the message as a `you:` line; new messages count from 1 as usual. Restart (Ctrl+Shift+R) keeps the conversation as it is. New session (Ctrl+N), Open folder and Open recent folder clear it first, so another folder starts with an empty window and its own earlier conversation, when it has one. Options, Text, "Time stamps on Input and Output lines" adds the time.

In the conversation, these keys move to a line and speak it. Add Shift to go backwards.

- `i`: the next `# Input` line (a message you sent). `o` or `r`: the next `# Output` line (a reply from Claude). Alt+3 from anywhere goes to the newest reply (Navigation → Latest response); for the last line of any other kind, Ctrl+End and then Shift with its letter.
- `h`: the next heading. `1` to `6`: the next heading of that level. Input and Output lines are level 1; headings inside Claude's replies are level 2 and deeper.
- `c`: the next line that starts a Claude reply. `t`: the next tool line (a file Claude edited or a command it ran). `p`: the next paragraph, the first line after a blank line or the first line of a message from Claude, so it also finds the short messages Claude prints between its tool calls; tool and thinking lines are never paragraphs, `t` finds the tool lines. `e`: the next error or warning. `d`: the next "done" line at the end of a reply. `s`: the next system line from axClaude. `q`: the next question Claude asked: axClaude writes a line `Question: …` in front of each one, which stays when Claude replaces the question with your answer. `b`: the next side question you asked with `/btw`: axClaude writes a line `btw: …` with your question in front of each side answer, and `q` passes over it.
- `l`: says where you are, like "Line 12 of 340". Nothing else ever speaks line numbers.
- Page Up and Page Down move one screen at a time, and reach the first and last line. Ctrl+Up and Ctrl+Down move to the previous and next paragraph, the first line after a blank line; with Shift they select to there.
- Ctrl+F opens Find. Type the text and press Enter; F3 and Shift+F3 find the next and previous match. "Not found" means there is none.
- Enter copies the line into the message field, under a line that says it was copied from the conversation and a line with its number, followed by a line that says your comment starts, and puts you in the field under it, ready to write. Alt+2 takes you back to the same conversation line, so you can collect several lines into one message. While one of Claude's questions is at the bottom of the window in the field's place, Enter only says so: answer the question first.
- Backspace goes back to the line you were on before the last jump, and again for the jump before that, so a stray `p` or `h` is undone in one press.
- Ctrl+Alt with one of these letters, from anywhere, reads everything of that kind from the line you are on to the end of the conversation in one go, without moving you: Alt+3 to the newest reply, then Ctrl+Alt+P for its prose, each paragraph whole, Ctrl+Alt+H for its headings, Ctrl+Alt+C for Claude's lines, Ctrl+Alt+T for its tool lines, Ctrl+Alt+E for the errors, Ctrl+Alt+O for the "# Output" lines that follow. Press Control when you have heard enough. While Windows Magnifier runs, it keeps Ctrl+Alt+H and Ctrl+Alt+K for its own reading, and Ctrl+Alt+L and Ctrl+Alt+M for its views, so those four never reach axClaude: close Magnifier with Win+Esc.
- `m` drops a bookmark on the line you are on: a line that says `Bookmark 1` appears just above it, and axClaude says "Bookmark 1 added". `m` on the same line takes it away again. `k` and Shift+K go to the next and previous bookmark and read the bookmarked line with it. Bookmarks are lines in the conversation, so Ctrl+S saves them with it, and they go when the conversation goes. The Navigation menu has the same commands, and Ctrl+Shift+K bookmarks the line from anywhere in the window.

Long paragraphs are shown as one line. Claude Code's screen decorations (the mode line, spinners, tips) are not shown; they feed the status bar instead. Text that arrives while you read never moves your place. Claude's replies are spoken as they arrive: Options, Speech has three choices for them. "Speak replies: all lines" is the default in a new install; "Speak replies: none" keeps axClaude silent about replies, and you read them when you choose. "Speak replies: first lines" speaks the first line of each of Claude's messages, where Claude says what it is doing or what it found, so you follow the major moments of a long turn without its detail. "Speak replies: all lines" speaks every line of Claude's replies. An error from Claude, such as "error: API Error: 401 Invalid API key · Please run /login" when your login has lapsed, is spoken in both modes, since it can be the whole reply. Each message is spoken in one go once it is complete; tool output, thinking and the conversation replayed at startup are never spoken. Options, Speech, "Speak each tool call" adds the line that names each tool Claude runs, such as "tool: Read (notes.txt)", as soon as it appears, whichever of the three you chose; what the tool printed is still not spoken. Press Control to silence NVDA when you have heard enough: the text stays in the conversation, and the ticks go on either way.

Session, Export conversation (Ctrl+S) writes the conversation to a text file. axClaude has no Save: the conversation itself is Claude Code's record, which `--continue` brings back. Ctrl+A and Ctrl+C in the conversation copy it.

The heading keys, h, Shift+H and 1 to 6, also work in the user guide and the other help texts of the Help menu, where they move by the text's own headings; Ctrl+F finds a text there, F3 and Shift+F3 the next and the previous match.

## Settings

### Choosing what you hear

- Options, Announcements: a switch for each word axClaude says by itself: "Ready", "Claude goes on by itself", "Sent" and "Queued", "Responding", "Question closed", and Claude's own notices such as "accept edits on". All are on at first. "Claude goes on by itself" is said when a turn starts that you did not send: Claude Code starts one by itself when work in the background finishes, and axClaude says so, so that you know why the music plays and a reply comes. "Done" has its switch under Options, When Claude is done. A switch silences the word only; the chimes stay, under Options, Sounds.
- Options, Speech, "Words that keep a reply line silent": type words with a semicolon between them, such as `Tip; Cost:`. A reply line that holds one of them, in any case, stays in the conversation and is not spoken. Leave the field empty to hear every line again.
- Options, Questions, "Dismiss Claude's feedback surveys unheard": Claude's "How is Claude doing this session?" is dismissed for you, with nothing said; the survey's lines stay in the conversation. Off at first. To keep Claude Code from asking at all, use Options, Claude Code settings, "Block Claude Code's feedback requests" (below).
- Options, Questions, "Open Claude's feedback drafts by themselves": on at first; off, a feedback draft Claude made waits until you type /feedback.

### Claude Code's own settings

Options, Claude Code settings changes settings of Claude Code itself, not of axClaude. Each item writes one setting into Claude Code's settings file, `.claude\settings.json` in your user folder, the file Claude Code reads in every project; everything else in that file stays as it was, and a copy of the file as it was before the change is kept beside it as `settings.json.axkit-backup`. Claude Code takes the change at once. Nothing is changed until you choose an item: at first every item is Claude Code's own default, and turning an item off again removes the setting, which gives Claude Code's default back. The checks show what the file holds each time you open the menu.

- "Block Claude Code's feedback requests": Claude Code no longer asks "How is Claude doing this session?", nor the question about your transcript that may follow a rating. Off at first. This is Claude Code's own switch; Options, Questions, "Dismiss Claude's feedback surveys unheard" is axClaude's, which lets the survey come and answers it for you.
- "Claude-drafted feedback": Claude can draft feedback to Anthropic for you to review. A card for each is Claude Code's default; quiet only counts the drafts at the bottom of Claude Code's screen, without a card; off stops Claude from drafting any.
- "Hide tips while Claude works", "Hide the turn duration after each reply" (the "Cooked for 1m 6s" line) and "Hide the session recap after time away": lines Claude Code adds that you may not want to hear.
- "No reply from Claude after my ! commands": a command you run with `!` puts its output into the conversation, and Claude does not answer it until you write.

If the file is not valid JSON, for example after an edit by hand, axClaude does not touch it and says on which line the problem is. Actions, "Choose the model" and "Choose the effort" send `/model` and `/effort` and show Claude Code's own list in place of the message field, its current choice marked; they wait until Claude is done with a reply.

### Where axClaude keeps its settings

Everything else you change in the Options menu is saved in `%APPDATA%\AxKit\axClaude.json` (the first start of axKit copies your settings from axClaude 1.x there). Options, Developer, "Open settings file" opens it in axJSON. `claudePath` names the Claude Code program when it is not on PATH. It is sealed: it decides which program axClaude starts as Claude Code, so it counts only as axClaude wrote it, with "Locate claude.exe" in the notice "Claude Code was not found". If you change it in the file by hand, or another program does, axClaude does not use it, looks for Claude Code in the usual places, keeps your other settings, and says once, as a system line, that claudePath was changed outside axKit and is not used; to start another program while Claude Code is found, start axClaude with `--claude <path>`. The seal's key is kept by Windows for your account; a program running as you could ask Windows for it, so the seal protects against a file changed by another program or by hand, a profile copied or synced from another computer, and an AI tool writing files, and not against a program that sets out to forge it. Some settings have no menu item: `joinWrappedLines` set to false keeps long paragraphs on separate lines, `ptyColumns` and `ptyRows` size the hidden console Claude writes to (240 by 50), and `maxTranscriptLines` caps the conversation (20000 lines).

### Where axClaude's events come from

axClaude learns what Claude Code is doing from what Claude Code draws on its screen and from the marks it puts in its output where a turn starts and ends. Where this version of axClaude and your Claude Code allow it, two more sources join them: events that Claude Code reports for this one conversation, and the session file Claude Code keeps for it. Nothing of this leaves your computer, and nothing in it changes what Claude Code does. You do not need any of it in daily use; it is there for when something sounds wrong. Options, Developer has a switch for each of the two sources, the session file's on at first and the events' off at first (turn it on when you want them), and a command that says what is in use:

- **Events from Claude Code's hooks.** Off, axClaude asks Claude Code for no events, from the next start of Claude. You hear "Events from Claude Code's hooks off, from the next start of Claude".
- **Ground the conversation in Claude Code's session file.** Off, axClaude does not read the session file, at once. You hear "Grounding in Claude Code's session file off".
- **Say the event sources.** For example "Events. Marks: 14. Hooks: not passed. Session file: not found. Core: in charge of state and Done." Marks counts the turn marks seen since Claude was started, three for each turn. "Hooks: not passed" and "Session file: not found" mean that these two are not in use in this conversation, and "Hooks: off" and "Session file: off" that you switched them off. "Core: in charge of state and Done" means that whether Claude works, as the status bar and "Queued" have it, and when "Done" is said come from the marks Claude Code writes at the start and the end of a turn, and no longer from the spinner on the screen and a fixed pause after Claude Code's bell; what is spoken is still decided from the screen. "Core: in shadow" means that all of it is decided from the screen, as it always was, and "Core: off after an error" that it went back to the screen until Claude is started again.
- The words for the hooks: "Hooks: on, 9 received" means that Claude Code has reported nine events in this conversation since Claude was started. "Hooks: not passed" is followed by one word that says why: "version" for a Claude Code older than the events axClaude asks for, "arguments" when your own options for Claude Code already name a settings file, "store" in the copy from the Microsoft Store. "Hooks: passed, none received" means that the events were asked for and none has come.

With both switches off axClaude works from the screen and the marks alone. Help, Diagnostics, Copy diagnostics holds the same numbers in more detail, and never a word of the conversation.

### Claude Code without its screen: the stream (being built)

axClaude can run Claude Code a second way. The first way, which is the default and stays, is Claude Code in a hidden console in screen reader mode, read off its screen. The second is Claude Code as one process that writes what happens line by line, with no screen at all. It is being built, it is off, and you do not need it. It is here so that it can be tried.

- **Turn it on:** Options, Developer, "Feed the next window from Claude Code's stream". You hear "Claude Code's stream on, from the next axClaude window. This window keeps the screen". A window keeps the way it was started with; the next axClaude window you open uses the stream. The same item turns it off again.
- **The folder's question.** Claude Code's own window asks before it works in a folder it has not seen. Without its screen it does not ask, so axClaude asks for it before it starts Claude Code: "Start Claude Code in this folder?" Enter and Escape are no. To say yes, press Tab to "Start Claude Code" and then Enter. The yes holds for that folder while the window is open.
- **The conversation** reads as always: your message, the reply, the tool calls, the same keys. "Ready", "Sent", "Queued" and "Done" are said as always. A reply is shown as Claude wrote it, so you may hear Markdown marks such as stars; making that plain is still to come.
- **When Claude asks to use a tool** (a command, a file to write), the question comes up in the message field's place, as Claude's questions do: "Claude asks to use Bash: " and the command, then "Asked by Claude, an AI: read the explanation before you allow it". The list starts on "No". The other answers are "Yes, once", "Yes, and do not ask again for" that tool "in this session", and "Explain what Claude asks to do", which opens everything Claude asks for as a text, answers nothing and comes back to the list. Escape is no. Allowing a tool call is your own act: read the explanation first.
- **Claude's own questions** come one after another, each with its answers and "Other" for your own words. Escape is no to all of them; in the field for your own words, Escape goes back to the answers.
- **Shift+Escape** interrupts the turn, and you hear "Interrupted". While a question waits, it answers no to the question, and you hear "Cancelled".
- **Ctrl+Shift+M** goes to Claude Code's next permission mode, and you hear the mode.
- **What is not there.** Claude Code's own screens (`/config`, `/status`, `/permissions`, the pickers of `/model` and `/effort`, `/login`) need its screen. Send queued messages now, the Send key items and Ctrl+O say "Not with the stream source". The conversation from before is not shown when Claude Code takes a conversation up again, though Claude remembers it. The copy from the Microsoft Store cannot start Claude Code this way yet.
- **The way back.** If Claude Code does not start this way, or ends at once, a notice says why and offers "Open with the screen": axClaude starts again on the same folder the usual way, and this window closes. Options, Developer, "Say the event sources" says "Source: the stream" in such a window.

## Updates

New versions are published on GitHub. When axClaude starts, it asks GitHub once whether there is a newer one; Options, General, "Check for updates at start" turns that off. If there is one, the update notice opens by itself: Enter updates, Escape keeps the version you have, and a "System:" line in the conversation records it.

Help, "Check for updates (axKit 1.0.0)" names the version you have, asks GitHub at any time and tells you either way. It is always there, so after skipping a version you can look again. While a newer version is known, Help, "Update to axKit 1.0.1" is below it and shows what is new, with four buttons. I accept all terms, install and restart (Enter) downloads and installs the new version while axClaude stays open, then closes axClaude and starts the new version on the same folder; if you had a conversation open, it is picked up again. I accept all terms, install and close installs it and closes without starting it again. One progress bar covers the download and the installation, and NVDA reports it the way it reports any progress bar (beeps or percentages, by your NVDA settings). Escape during the download cancels it and keeps the version you have; once the installation has begun it runs to the end, a few seconds. Open release page opens it in the browser. Later keeps the version you have, and the Help menu offers the update until you take it. Help, About, Version names the version you have, the latest release on GitHub and where the settings and logs are.

## If something goes wrong

- "Claude Code was not found": install it with the command in the notice, then press Ctrl+Shift+R. If it is installed somewhere unusual, use "Locate claude.exe" instead: Claude starts at once and the place is remembered.
- An error from axClaude is a notice inside the window and a "System:" line in the conversation. Escape closes the notice.
- Claude stopped, or the conversation looks wrong: Ctrl+Shift+R restarts Claude in the same folder. While Claude is running it asks first, because a restart quits Claude Code at once and ends anything it runs in the background: Enter restarts, Escape keeps Claude running. Starting axClaude again brings the conversation back. While Claude is stopped, Enter sends nothing and keeps your text.
- For a bug report: Help, Diagnostics, Copy diagnostics puts the version, the paths and the last log lines on the clipboard. Options, Developer, "Record raw stream for a bug report" records everything Claude Code prints, which includes your account's e-mail address if you open `/status`, so read a recording before you share it. The log is in `%LOCALAPPDATA%\AxKit\logs`.
- Your files stay out of your project's git: recordings and exported conversations are offered in your Documents folder, and their names start with `axclaude-`. When the project folder is a git repository, axClaude also lists those names in the repository's own local exclude file (`.git\info\exclude`, which is never committed), so git ignores them even when you save one in the project. Options, General, "Keep recordings and saved conversations out of git", on by default, turns this off, for when you want to commit such a file.
- An update did not start axClaude again: `%LOCALAPPDATA%\AxKit\logs\update.log` says what the installer did. Start axClaude from the Start menu; if it is still the old version, download the zip from the release page and run `install.ps1` yourself.
