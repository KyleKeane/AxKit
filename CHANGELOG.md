# Changelog

## 5.8.0

- axDown, axJSON: a letter typed over selected text is one step to undo. Before, the first Ctrl+Z took only the letter back and left the text empty, and a second brought the selected text back.
- axTerminal: a command longer than the console is wide is no longer read back after "Sent". The part of its echo that wrapped onto the next rows was spoken and stood under Output; it is hidden now, as the rest of the echo is.
- axMCP: an error a server answers with is always a notice named after what failed, "echo failed" or "Could not start weather", with the server's message. A message of one line was only said, as "Failed:" and the message, without the tool's or the server's name.
- axMCP: Right or Enter on a remote server (http or sse) says why it is not started and stays on the list of servers. Before, it opened a level of the server's with one row, and the reason was cut off by the level's name.
- axAutomate: a folder you start axAutomate on (`axAutomate C:\my\workflows`) is opened again by the next start without one. Before, only a folder chosen with Ctrl+O was remembered.
- axPass, axTask: Ctrl+Q on an entry or an item reads an empty long text as "empty", "Notes: empty", as every other empty field. Before, it said "Notes:" and nothing after it.
- axKit: the check runner (`tools/AxAutomate`) puts the clipboard's text back after its last script; axClip's check scripts used to leave their test text on your clipboard.
- axKit: the unused route for submitting to the Microsoft Store through its API is removed (the workflow, two scripts); the Store copy is submitted through Partner Center as before.
- axKit: every window's menu bar is the same eight menus, in this order, each with its letter: Session (S), Actions (A), Navigation (N), Context (C), Options (O), Window (W), axKit (K) and Help (H). Session holds what concerns the file, folder or session as a whole; Actions what the app does ("Operations" before); Navigation the moves and the finds; Context what acts on what the focus is on, and only that; Options the app's settings first. Shift+F10, the Applications key and a right click open Context. A menu with nothing in it yet holds one item that says so. The keys did not change. axKit's menu is Alt+K now, no longer Alt+A.
- axTask, axPass, axMCP, axAutomate, axProcess: the menus that followed the focus (List, Item and Field; Group, Entry and Field; Server, Item and Field; Process, Service and Startup) are now the one Context menu, which says "Nothing selected" or "A heading: nothing to act on" when there is nothing. New item, New list, Undo, Lock, Add server and Summary are in Actions; All tasks, Find in every list, the sections and axProcess's views in Navigation; Hide done tasks and Sort processes by in Options.
- axFile, axGIT, axMedia: the same eight menus. axFile's entry menu is Context (Alt+C, and Shift+F10 as before), its Selection menu a submenu of it; Undo, New folder, New text file, Paste, Select all and Deselect all are in Actions; Favorites, Drives, Go to folder, Up one level and The Actions list in Navigation; Sort by and Filter in Options. axGIT's Operations and Branches menus are Actions (Stage all, Commit, branches and the server) and Context (what acts on the change, commit or branch you are on), the views in Navigation. axMedia's Play, Remove and Information are in Context, Next file, Previous file and Go to time in Navigation.
- axDown, axJSON, axPreview, axClaude, axTerminal, axStart, axClip, axCalc, axHelp: the same eight menus. The editors' Operations is Actions and their Navigate is Navigation; Cut, Copy, Paste and Select all are Context, which opens in place of the text's own menu. axClaude's and axTerminal's Context holds Quote this line in the message (axTerminal: Copy this line into the command field), Bookmark this line and Copy the selection. Every F1 text names Shift+F10.
- axKit: the command palette (Ctrl+Shift+P) finds your recent files and windows: every Open recent list, axFile's Favorites, and the Window menu's Open windows and Recently closed. Type a few letters of a file's name and press Enter.
- axKit: a line break you type is said, "new line", in every field that takes one: the editors, a long text in the item apps, axClaude's message and axTerminal's command with Shift+Enter, the report's words. Options, Text, Say new line, in any window, turns it off or on for all of them (on by default; `display.sayNewLine` in the theme file). From the reports repository's issue 1.
- axKit: a short rising sound plays when your key lands on a heading, before NVDA reads it: a section row in axTask, axPass, axMCP and axAutomate, and a Markdown heading in axDown, axPreview and every notice's text. Never for a list filled or a change the window makes. Options, Text, Sound on headings turns it off for every window (on by default; `display.headingSound`).
- axKit: Find in a list (Ctrl+F in axCalc's history, axFile, axMedia's queue and the other list windows) moves the focus to the match, so NVDA reads it. Before, a Find started from another control selected the match without a word.
- axKit: a file you save is written whole or not at all: the new text goes to a temporary file that then takes the old one's place, so a crash or a full disk in the middle of a save leaves the file as it was. This covers the editors' documents, axTask's items, the settings and the theme.
- axKit: an update is installed only when the program in the download is the version its release names and newer than the one running; otherwise it is deleted and the notice says why. An older release offered under a newer number can no longer take you back.
- axKit: the Microsoft Store's copy gives axHelp one of its eight Start menu entries, in axGIT's place, so that axHelp starts at sign-in there as in the GitHub install; axGIT opens from its command, a repository's folder and every window's New window. This comes with the next Store package.

With axKit menu, AI tools, Let AI tools run commands turned on (off unless you turn it on), a tool such as Claude Code runs a menu command of an axKit window by its name with `axkit_window_run`; the window says it as it runs ("Claude ran Word wrap"), and a window behind chimes and flashes. The AI tools' own switches, and AI help's switch and folders, are never offered to them. One list now feeds the menus, the palette and the AI tools, so they cannot drift apart.
- axKit: AI tools: every menu item of every window now states what it does (it reads, it moves within the window, it changes the window's own things, or it acts outside the window). An AI tool you allowed to run commands therefore no longer asks before a harmless one, such as Read in full, Refresh, a move to the next section or a change of speed, and still asks before anything that deletes, sends, copies to your clipboard, starts a program, reaches the network or types into Claude Code or a shell. The window says "Claude added Call the dentist to Personal", and Ctrl+Z takes it back. Refused with the reason: a title or field name with a control character, a title over 200 characters, and an add into a GitHub list.
- axClaude: AI tools: when Claude needs you to run a command yourself (a sign-in that asks questions, or one its permissions refuse), it can offer it instead of asking you to type or paste it. After its turn ends, a list takes the message field's place, as for one of Claude's questions, named with the command; the conversation stays there to read. - axKit: when an AI tool asks to run a window command that acts outside the window, the question is now the same as for a command Claude offers: the alarm, a name that starts with "Command offer", and a list you answer with the arrows, starting on "Explain this command", then "Yes, run it" and "No, do not run it". In axClaude, axTerminal and the editors it is at the bottom, with the conversation or the text still there to read; in the other windows it covers the window. It was a notice with Run and Deny buttons reached by Tab. Both questions now say how far the command reaches right after "Command offer": "it acts outside this window" for a window's own command, "it runs on your computer, outside axKit" for a shell command, and each explanation has a section "How far it reaches".
